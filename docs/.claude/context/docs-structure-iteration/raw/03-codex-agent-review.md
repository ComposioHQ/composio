- Correct: `docs/content/docs/meta.json:7-20` separates **Use Composio** (Connect/CLI/plugin) from the SDK-oriented docs, and `docs/content/docs/quickstart.mdx:23-43` makes the sessions-first pattern explicit while marking `composio.tools.get()` / `composio.tools.execute()` as deprecated. That gives an AI the right default entrypoint.
- Correct: `docs/content/docs/authentication.mdx:11-20` and `docs/content/docs/triggers.mdx:22-39` cleanly separate auth and triggers: auth defaults to in-chat/session flows, while triggers are tied to connected accounts and project subscriptions rather than sessions.
- Fixed: none (review only; no edits requested).
- Blocker: Session lifecycle is internally contradictory. `docs/content/docs/how-composio-works.mdx:41-42` says sessions are immutable and “You don't need to cache or manage session IDs,” but `docs/content/docs/users-and-sessions.mdx:108-165` and `docs/content/docs/quickstart.mdx:27-28` say sessions persist, should be reused with `composio.use()`, and can be updated with `session.update()`. An AI reading both will form the wrong state model. Minimal fix: rewrite the `How Composio works` session paragraph to match the reusable/persistent model and say to create a new session only when you want separate isolation or a different config.
- Note: Legacy/direct execution is still too foregrounded. The sidebar puts `sessions-vs-direct-execution` directly under Help and shows the legacy cluster inline (`docs/content/docs/meta.json:51-64`), while `docs/content/docs/tools-and-toolkits.mdx:70-72,98-102` actively routes readers to direct execution. That conflicts with the quickstart’s “NEVER use `composio.tools.get()` / `composio.tools.execute()`” guidance (`docs/content/docs/quickstart.mdx:39-43`). Minimal fix: move `sessions-vs-direct-execution` under a collapsed Legacy/Migration bucket and relabel the direct-execution callout/card as advanced or legacy.

The API spec says `enable_wait_for_connections` defaults to false (`docs/public/openapi-v3.json:16045-16049`). Minimal fix: either document `COMPOSIO_WAIT_FOR_CONNECTIONS` everywhere as optional/disabled-by-default, or remove it from the Connect overview.
- Note: The main concept path does not bridge “tool router” to the new sessions mental model. The only explicit statement is buried in migration docs: the experimental tool router “has now graduated to… sessions” (`docs/content/docs/migration-guide/tool-router-beta.mdx:7-9`). Minimal fix: add one sentence in `how-composio-works` or `users-and-sessions` stating that sessions are the stable tool-router abstraction.
