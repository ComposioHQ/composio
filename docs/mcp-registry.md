# Publishing & updating the Composio MCP server listing

Composio's hosted MCP server is published to the community MCP registry as
[`io.github.ComposioHQ/composio`](https://registry.modelcontextprotocol.io/v0/servers?search=io.github.ComposioHQ/composio).
That registry entry is what powers the GitHub MCP Registry card at
<https://github.com/mcp/ComposioHQ/composio>.

[`server.json`](../server.json) at the repo root is the **source of truth** for that
listing. The registry card — including the one-line description and the
**Install in VS Code** button GitHub renders on it — is generated from the fields in
`server.json`. There is no prose to hand-write and no README that drives the card:
edit `server.json`, re-publish, and the listing updates.

## What each field drives

| Field | Where it shows up |
| --- | --- |
| `description` | The one-line summary on the registry card and the `github.com/mcp` page |
| `remotes[].url` | The endpoint MCP clients connect to, and the URL the **Install in VS Code** button is generated from |
| `remotes[].type` | Transport — `streamable-http` for the hosted server |
| `version` | Must be **bumped on every publish**; the registry rejects re-publishing an existing version |

Currently published: **v1.0.5** &rarr; `https://connect.composio.dev/mcp`.

## Update the listing

1. Edit [`server.json`](../server.json) — e.g. reword `description`, or point
   `remotes[].url` at a new endpoint. **Bump `version`.**
2. Install the official publisher CLI (`mcp-publisher`). See install options in the
   [MCP registry repo](https://github.com/modelcontextprotocol/registry).
3. Authenticate against the `io.github.ComposioHQ/*` namespace. This uses GitHub
   auth and requires membership in the **ComposioHQ** org:
   ```bash
   mcp-publisher login github
   ```
4. Publish from the repo root (reads `server.json`):
   ```bash
   mcp-publisher publish
   ```
5. Verify it went live:
   ```bash
   curl "https://registry.modelcontextprotocol.io/v0/servers?search=io.github.ComposioHQ/composio"
   ```

## Automate on release (optional)

The `io.github.ComposioHQ/*` namespace can be claimed via GitHub OIDC, so publishing
can run from CI with no long-lived token:

```yaml
# .github/workflows/publish-mcp.yml
name: Publish MCP server
on:
  release:
    types: [published]
permissions:
  id-token: write   # required for GitHub OIDC
  contents: read
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Install mcp-publisher
        run: |
          curl -fsSL "https://github.com/modelcontextprotocol/registry/releases/latest/download/mcp-publisher_linux_amd64.tar.gz" | tar -xz
      - name: Login via GitHub OIDC
        run: ./mcp-publisher login github-oidc
      - name: Publish
        run: ./mcp-publisher publish
```

## Notes

- The **Install in VS Code** button is generated by the registry from
  `remotes[].url` + `remotes[].type`; you do not author it. If it looks wrong, fix the
  remote in `server.json` and re-publish — not a README.
- The `$schema` pin (`2025-12-11`) tracks the registry's published schema version; only
  bump it when the registry schema itself revs.
