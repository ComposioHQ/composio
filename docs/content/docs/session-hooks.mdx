Tool execution hooks let you inspect and control the tool calls your agent makes and the results it gets back. Use them to block unwanted actions, prevent prompt injection, validate how a tool is called, and redact or transform a tool's arguments and response to protect sensitive data.

Hooks run regardless of how your agent calls a tool, whether that's through multi-execute, the workbench, or bash.

Composio supports three kinds of hooks:

- **Condition check:** This can be used to block tool calls that match a condition you describe in natural language, such as "Sharing internal pricing with anyone outside acme.com". See [Firewall](/docs/firewall#custom-prompt-checks). Available on paid plans.
- **Prompt injection check:** This is a pre-built hook that can be used to scan tool results for prompt injection before they reach your agent. See [Firewall](/docs/firewall#prompt-injection-detection). Available on paid plans.
- **Webhook:** This allows you to configure a webhook endpoint that gets called before or after a tool call. It gives you a powerful way to run arbitrary code on tool calls, such as screening them for PII with your own detection service. See [Webhooks](#webhooks). Available on the Enterprise plan.

## Adding a hook to a session

You can add hooks to a session when you create it, by passing them in `hooks`. Every hook has the same structure, regardless of its kind:

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
<Tab value="Python">
```python
session = composio.create(
    user_id="user_123",
    hooks=[
        {
            "id": "no_pricing_to_customers",
            "type": "before_execute",
            "applies_to": {"toolkits": ["gmail"]},
            "handler": {
                "type": "condition_check",
                "condition": "Sharing internal pricing with anyone outside acme.com",
                "action": "block",
            },
        },
    ],
)
```
</Tab>

| Field | Description |
|---|---|
| `id` | An identifier for the hook, unique within the session. |
| `type` | When the hook runs: `before_execute` or `after_execute`. |
| `applies_to` | The toolkits the hook applies to, or `"all"`. |
| `handler` | The kind of hook and its configuration. Set `handler.type` to `condition_check`, `prompt_injection_check`, or `webhook`. |

You can add several hooks to a session, and replace them later with `session.update()`. See [Updating checks](/docs/firewall#updating-checks).

The example above is a condition check. [Firewall](/docs/firewall) covers condition checks and prompt injection checks in detail. The rest of this page covers webhooks.

## Webhooks

Tool execution webhooks let you run your own code on a tool call. Composio sends the call to your webhook endpoint, before the tool runs or after it returns, and waits for your response. In that response, you can allow the call, block it, or modify it.

Use a webhook when a decision depends on your own code or data. For example:

- **Screen for sensitive data:** Scan tool calls for PII with your own detection service, and block the ones that contain it.
- **Enforce access policies:** Check each call against your own permission or approval system.
- **Redact tool results:** Strip secrets from a tool's response before your agent reads it.

<Callout type="info">
Webhooks are available on the Enterprise plan.
</Callout>

<Callout type="info">
If your agent runs its tools through the Composio SDK in your own application, you may not need webhooks. [Before](/docs/tools-direct/modify-tool-behavior/before-execution-modifiers) and [after](/docs/tools-direct/modify-tool-behavior/after-execution-modifiers) execution modifiers let you run your own code around each tool call, without setting up an endpoint. Use webhooks when your agent also calls tools from the workbench or over MCP, because modifiers don't run for those calls.
</Callout>

### Setting up a webhook URL

You can configure the webhook URL from the dashboard, under [Sessions → Webhooks](https://dashboard.composio.dev/~/project/sessions/webhook?utm_source=docs&utm_medium=content&utm_campaign=session-hooks). Composio then calls this endpoint for all sessions in the project. Only organization admins can set or change the URL.

<Figure src="/images/session-webhook-settings.png" alt="The Webhooks tab under Sessions in the Composio dashboard, with the webhook endpoint URL and its masked signing secret" caption="The webhook URL and its signing secret, under Sessions → Webhooks" />

When you save the URL, the dashboard displays a signing secret. Copy it and store it in your project's environment. It's only shown once.

Use the secret to verify that a request came from Composio. Composio signs every request with it, so you can check the signature before acting on a request. If the secret is ever exposed, rotate it from the same page. The previous secret is invalidated immediately.

### Adding a webhook to a session

Once the URL is configured, you can add webhooks to your sessions. To add one, set the handler `type` to `webhook`. This example sends every Gmail tool call to your endpoint before it runs:

```python
                "type": "webhook",
```

### Receiving webhooks

For every call a webhook applies to, Composio sends a `POST` request to your endpoint and waits for your response. This is the request for the webhook above when your agent sends an email:

```json
{
  "id": "msg_3f2a9c1e-5b7d-4e8a-9c21-7d4e5f6a8b90",
  "type": "composio.session_hook.before_execute",
  "timestamp": "2026-11-20T12:00:00.000Z",
  "metadata": {
    "project_id": "pr_123",
    "session_id": "trs_123",
    "user_id": "user_123",
    "hook_id": "check_gmail_calls",
    "tool_call_id": "0b9c3a52-7d41-4e8f-a6c5-1f2e3d4c5b6a"
  },
  "data": {
    "type": "tool_execute",
    "tool_call": {
      "toolkit_slug": "gmail",
      "tool_slug": "GMAIL_SEND_EMAIL",
      "toolkit_version": "20261101_00",
      "connected_account_id": "ca_123",
      "arguments": {
        "recipient_email": "jane@customer.com",
        "subject": "Pricing"
      }
    }
  }
}
```

Use `metadata.tool_call_id` to match the `before_execute` and `after_execute` requests for the same call. Both carry the same ID.

For the full schema of the request and of your response, see the reference for [`before_execute`](/reference/api-reference/session-webhooks/composio_session_hook_before_execute) and [`after_execute`](/reference/api-reference/session-webhooks/composio_session_hook_after_execute).

Here's an example that receives this request and blocks the call if it contains a US Social Security number. The Python example uses FastAPI, and the TypeScript example is a Next.js route.

{/* code-example: no-api reason="parse() runs inside your webhook endpoint; it verifies and types the incoming request in the SDK" */}
<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
import json
import os
import re

from composio import (
    Composio,
    SessionWebhookBeforeExecuteEvent,
    SessionWebhookBeforeExecuteResponse,
)
from fastapi import FastAPI, Request

composio = Composio()
app = FastAPI()

SSN = re.compile(r"\b\d{3}-\d{2}-\d{4}\b")


def before_execute(
    hook: SessionWebhookBeforeExecuteEvent,
) -> SessionWebhookBeforeExecuteResponse:
    data = hook["data"]
    if data["type"] == "tool_execute" and SSN.search(json.dumps(data["tool_call"]["arguments"])):
        return {"action": "block", "message": "The call contains a Social Security number"}
    return {"action": "continue"}


@app.post("/composio/session-webhook")
async def session_webhook(request: Request):
    # parse() verifies the request signature against your secret and returns
    # the typed event. It raises an error if verification fails.
    # Pass the raw body: the signature is computed over its exact bytes.
    hook = composio.sessions.webhooks.parse(
        body=await request.body(),
        headers=request.headers,
        verify_secret=os.environ["COMPOSIO_SESSION_WEBHOOK_SECRET"],
    )

    # Respond with HTTP 200 and a JSON body that tells Composio how to proceed.
    if hook["type"] == "composio.session_hook.before_execute":
        return before_execute(hook)
    return {"action": "continue"}
```

```typescript
// @noErrors
// app/composio/session-webhook/route.ts
import {
  Composio,
  type SessionWebhookBeforeExecuteEvent,
  type SessionWebhookBeforeExecuteResponse,
} from '@composio/core';

const composio = new Composio();

const SSN = /\b\d{3}-\d{2}-\d{4}\b/;

function beforeExecute(hook: SessionWebhookBeforeExecuteEvent): SessionWebhookBeforeExecuteResponse {
  const { data } = hook;
  if (data.type === 'tool_execute' && SSN.test(JSON.stringify(data.tool_call.arguments))) {
    return { action: 'block', message: 'The call contains a Social Security number' };
  }
  return { action: 'continue' };
}

export async function POST(request: Request) {
  // parse() verifies the request signature against your secret and returns
  // the typed event. It throws an error if verification fails.
  // Pass the raw body: the signature is computed over its exact bytes.
  const hook = await composio.sessions.webhooks.parse({
    body: await request.text(),
    headers: request.headers,
    verifySecret: process.env.COMPOSIO_SESSION_WEBHOOK_SECRET!,
  });

  // Respond with HTTP 200 and a JSON body that tells Composio how to proceed.
  if (hook.type === 'composio.session_hook.before_execute') {
    return Response.json(beforeExecute(hook));
  }
  return Response.json({ action: 'continue' });
}
```

The following sections cover each way you can respond.

#### Blocking a call

To block a call, respond with `action: "block"` and a `message`, as the example above does:

```json
{ "action": "block", "message": "The call contains a Social Security number" }
```

The message is returned to your agent, so use it to explain why the call was blocked. Your agent receives a blocked result with your `message` in `error`, the same as when [any other hook blocks a call](/docs/firewall#custom-prompt-checks).

You can block a call from `after_execute` in the same way. By then the tool has already run, but its result is withheld from your agent.

#### Modifying a tool's arguments

To run a call with different arguments, respond with `action: "continue"` and an `override`. Composio runs the call with exactly the arguments you return, so start from the originals and change only what you need. This `before_execute` adds your compliance team as a BCC on every email your agent sends:

{/* code-example: no-api reason="builds the answer your webhook endpoint returns; it runs in your own server, not through the API" */}
<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
from composio import (
    SessionWebhookBeforeExecuteEvent,
    SessionWebhookBeforeExecuteResponse,
)


def before_execute(
    hook: SessionWebhookBeforeExecuteEvent,
) -> SessionWebhookBeforeExecuteResponse:
    data = hook["data"]
    if data["type"] == "tool_execute" and data["tool_call"]["tool_slug"] == "GMAIL_SEND_EMAIL":
        arguments = {**data["tool_call"]["arguments"], "bcc": ["compliance@acme.com"]}
        return {"action": "continue", "override": {"tool_call": {"arguments": arguments}}}
    return {"action": "continue"}
```

#### Modifying a tool's response

In `after_execute`, return an `override` to replace the tool's response before it reaches your agent. This example redacts anything that looks like an API key from a tool result. To use it, add an `after_execute` webhook to your session and call this function from your endpoint for `composio.session_hook.after_execute` requests:

{/* code-example: no-api reason="builds the answer your webhook endpoint returns; it runs in your own server, not through the API" */}
<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
import json
import re

from composio import (
    SessionWebhookAfterExecuteEvent,
    SessionWebhookAfterExecuteResponse,
)


def after_execute(
    hook: SessionWebhookAfterExecuteEvent,
) -> SessionWebhookAfterExecuteResponse:
    data = hook["data"]
    if data["type"] != "tool_execute":
        return {"action": "continue"}

    result = json.dumps(data["tool_response"]["data"])
    redacted = re.sub(r"sk-[A-Za-z0-9]{20,}", "[redacted]", result)
    return {
        "action": "continue",
        "override": {"tool_response": {"data": json.loads(redacted)}},
    }
```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
import type {
  SessionWebhookAfterExecuteEvent,
  SessionWebhookAfterExecuteResponse,
} from '@composio/core';

function afterExecute(hook: SessionWebhookAfterExecuteEvent): SessionWebhookAfterExecuteResponse {
  const { data } = hook;
  if (data.type !== 'tool_execute') {
    return { action: 'continue' };
  }

  const result = JSON.stringify(data.tool_response.data);
  const redacted = result.replace(/sk-[A-Za-z0-9]{20,}/g, '[redacted]');
  return { action: 'continue', override: { tool_response: { data: JSON.parse(redacted) } } };
}
```

#### Proxy calls

Webhooks also apply to [proxy calls](/docs/extending-sessions/proxy-execute) to a toolkit's API. For a proxy call, `data.type` is `proxy_execute`, and the request is in `http_request` instead of `tool_call`. Use `override.http_request` to modify the request, and `override.http_response` to modify its response.

### Other details

#### Timeouts

Composio waits up to 3 seconds for your response. Set `timeout_ms` on the handler to change this, to any value from `100` to `5000` milliseconds. The tool call is held until you respond, so respond as quickly as you can.

```json
{ "type": "webhook", "fallback_action": "block", "timeout_ms": 1000 }
```

#### Fallbacks

`fallback_action` is required. Set it to choose what happens to a call when Composio doesn't get a valid response from your endpoint:

- Set it to `block` to fail closed. The call is blocked. Use this for checks that must never be skipped.
- Set it to `continue` to fail open. The call proceeds unchecked. Use this when your agent should keep working while your endpoint is down.

The fallback applies when:

- the request times out, or your endpoint can't be reached
- you respond with a status other than `200`
- your response doesn't match the [expected format](/reference/api-reference/session-webhooks)

Composio sends each request once, with no retries. When the fallback applies, the webhook is reported as `unavailable` in the call's hook results, with the reason in `detail`:

```json
{ "id": "check_gmail_calls", "status": "unavailable", "detail": "The webhook endpoint timed out" }
```

#### Order of execution

When a webhook and other hooks apply to the same call, the webhook runs first. If you block the call, the remaining hooks are skipped. Otherwise, condition checks and the prompt injection check evaluate the call as you returned it, including any changes you made.

#### Limits

You can add one `before_execute` webhook and one `after_execute` webhook to a session. Creating a session with a webhook returns a `400` if the project has no webhook URL configured.
