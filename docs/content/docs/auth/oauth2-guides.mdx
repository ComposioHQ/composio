Use these guides to register your own OAuth app with a provider and connect it to Composio.

## When you need custom OAuth credentials

Use your own OAuth app when you need your app's name on the provider's consent screen, scopes that Composio's managed app isn't approved for, or an OAuth toolkit without managed auth. You supply the app's client ID and client secret through a custom auth config. Composio still stores and refreshes the connected account's tokens.

### Choose managed or custom OAuth

1. Check [Managed OAuth apps](/toolkits/managed-auth). If your OAuth toolkit has no managed app, follow its [setup guide](#provider-setup-guides) to create your own.
2. If a managed app is available, check whether its consent branding and approved scopes meet your needs. If either doesn't, use a custom OAuth app.
3. Otherwise, use Composio-managed OAuth. You don't need to register an app or supply OAuth client credentials. Follow the [authentication guide](/docs/authentication).

You can make this choice separately for each toolkit. See [Managed vs custom auth](/docs/authentication/custom-app-vs-managed-app) for the full comparison.

## Set up your OAuth app

1. Open the [Composio dashboard](https://dashboard.composio.dev/~/project/auth-configs?utm_source=docs&utm_medium=content&utm_campaign=oauth2-guides), create an auth config, and select your toolkit and OAuth2 scheme.
2. Follow the provider guide below to register your OAuth app. Register the exact redirect URI shown by Composio in the provider's developer portal.
3. Enter your client ID, client secret, and any other required fields in the custom auth config. Save it and copy its ID.
4. [Pass the auth config ID to your session](/docs/authentication/custom-app-vs-managed-app#pass-the-auth-config-id-in-your-session), keyed by toolkit. Creating the config alone doesn't select it for a session.

The provider's OAuth redirect URI is separate from the callback URL that returns users to your app after authentication. See [Custom callback URL](/docs/authentication#custom-callback-url).

## Common OAuth2 troubleshooting

| Problem | What to check |
| --- | --- |
| `redirect_uri_mismatch` | The redirect URI registered with the provider must exactly match the one in your Composio auth config. Copy it from the current auth-config flow. Don't substitute your application's post-authentication callback URL. |
| `invalid_client` | Confirm that the client ID and secret belong to the same provider app and match the values in your auth config. Check the provider guide for app installation or approval requirements. |
| `invalid_scope` or blocked consent | Check the scope names and whether the provider has approved them for the selected OAuth app. For Google, see [OAuth setup and consent](/kb/guide/platform-google-oauth). |
| Microsoft shows "Needs Admin Approval" | Ask a tenant administrator to approve the app and requested permissions, then start a fresh connection. See [Microsoft tenant consent](/kb/guide/platform-microsoft-oauth). |
| Users still see Composio's OAuth app | Confirm that the session uses your custom auth config ID for that toolkit. For consent-screen branding, see [White-label authentication](/docs/authentication/white-labeling-authentication). |
| A connection still lacks permissions after changing scopes | Have the user reconnect to grant the new scopes. Existing connections keep their previously granted scopes. See [Controlling scopes](/docs/authentication/controlling-scopes#update-scopes-on-an-existing-config). |
