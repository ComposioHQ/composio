Composio is built with security at its core. We use least-privilege defaults, isolate every organization and project, encrypt credentials, and give you controls over what we store.

## Compliance and the Trust Center

Composio is SOC 2 Type II compliant. For our latest reports and certifications (the SOC 2 Type II report, our sub-processor list, and more), visit the [Composio Trust Center](https://trust.composio.dev).

## Common questions from security reviews

| Question | Short answer |
| --- | --- |
| Where does our data go during a tool call? | To the destination provider, Composio's execution infrastructure, temporary file storage, your trigger destinations, and a code sandbox if you use Workbench. See [Where your data goes](/docs/security/data-retention#where-your-data-goes). |
| What do you store, and for how long? | Execution and trigger logs, including payloads by default, for up to one year. Files are deleted after 24 hours. See [Data retention and handling](/docs/security/data-retention). |
| Can you stop storing our payloads? | Yes. [Zero Data Retention](/docs/security/zero-data-retention) keeps metadata only for covered calls. |
| Do you train models on our data? | Not on request arguments, response data, or trigger payloads. See [Model training](/docs/security/data-retention#model-training). |
| Can we run Composio in our own VPC or on-prem? | Private VPC and self-hosted deployments are Enterprise arrangements. See [Deployment options](/docs/security/token-custody#deployment-options). |
| Who holds our users' provider credentials? | In Composio Cloud, Composio does, encrypted at rest. If Composio must not be able to decrypt them, ask about a customer-managed key deployment, which keeps the keys in your KMS. See [Token custody architecture](/docs/security/token-custody). |
| Who are your sub-processors? | The current list is in the [Trust Center](https://trust.composio.dev/subprocessors). |
| Which IP addresses should we allowlist? | See [Outbound IP addresses](/docs/security/outbound-ips). |

## Isolation and access control

- Organizations and projects isolate your resources. Data from one project is not visible to another.
- API keys are scoped, support per-key IP allowlisting, and can opt in to capabilities such as Proxy Execute at creation.
- Scoped project API keys separate **Session management** (creating, viewing, configuring, and deleting sessions) from **Session tool execution** (search, tool execution, proxy execution, and session-linked MCP access). See [API key permissions](/reference/authenticating-to-composio/project-api-key-permissions) to configure access.
- Multi-factor authentication (MFA) is available for Dashboard sign-in and can be enforced by an organization admin.
- Organization admins can see who changed members, projects, API keys, and other settings in [audit logs](/docs/security/audit-logs).

## Credential protection

See [Token custody architecture](/docs/security/token-custody) for credential boundaries, server-side execution, default API redaction, and deployment options.

- Connected-account credentials, auth configs, and API keys are encrypted at rest using AES-256-GCM, and all traffic is encrypted in transit using TLS.
- Connected-account tokens are redacted by default in API responses, for both Composio-managed and custom auth configs. To act on a provider directly, use [Proxy Execute](/docs/extending-sessions/proxy-execute).
- Webhook deliveries are signed; verify the `webhook-signature` header when handling trigger events. For custom OAuth webhook setup, see [Custom OAuth webhooks](/docs/setting-up-triggers/custom-oauth-webhooks).

## Your responsibilities

Composio executes the tools and connections you configure. You control which toolkits are enabled, which accounts are connected, and what your agents are allowed to do. Review the access you grant, and treat connected-account scopes as you would any production credential.

## Reporting a vulnerability

To report a security issue, contact `security@composio.dev`. Please do not disclose vulnerabilities publicly until we have addressed them.
