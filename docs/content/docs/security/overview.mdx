## Compliance and the Trust Center

Review the [compliance reports and evidence](/docs/security/compliance#compliance-and-the-trust-center), including SOC 2 Type II, ISO 27001, and the subprocessor register.

### Data Processing Addendum

See [DPA eligibility and acceptance](/docs/security/compliance#data-processing-addendum) for the applicable plans, dashboard steps, and processing terms.

### HIPAA and the BAA

Read the [BAA acceptance and workflow guidance](/docs/security/compliance#hipaa-and-the-baa) before sending PHI. Acceptance alone does not establish that every feature or destination is suitable for PHI.

## Isolation and access control

Composio provides project isolation, scoped API-key permissions, IP allowlisting, and dashboard MFA. See [Access control](/docs/security/access-control#isolation-and-access-control) for the controls you configure.

Organization admins can see who changed members, projects, API keys, and other settings in [audit logs](/docs/security/audit-logs).

### Authorization boundaries

Review how [provider permissions, keys, application identity, session tools, and experimental approvals](/docs/security/access-control#authorization-boundaries) limit execution at different points.

## Credential protection

Provider credentials are encrypted at rest and used server-side. Composio API and session keys are stored as hashes. Read [Credential protection](/docs/security/access-control#credential-protection) for encryption, redaction, and webhook verification.

### Decryption and privileged access

The Cloud runtime decrypts credentials during execution. See [decryption and privileged access](/docs/security/access-control#decryption-and-privileged-access) for key separation, operator access, and customer-managed arrangements.

### Revocation and recovery

Follow [revocation and recovery guidance](/docs/security/access-control#revocation-and-recovery) if a key is exposed. Deleting a connection does not guarantee provider-side revocation.

## Your responsibilities

You authenticate your users and configure account access, tool selection, approvals, and retention. The [shared-responsibility table](/docs/security/shared-responsibility#your-responsibilities) identifies what Composio operates and what you own.

## Infrastructure, resilience, and testing

Review [infrastructure and resilience evidence](/docs/security/compliance#infrastructure-resilience-and-testing) for processing locations, testing, backups, and recovery questions.

## Reporting a vulnerability

Report security issues privately to [security@composio.dev](mailto:security@composio.dev). For account support or deletion requests, contact [support@composio.dev](mailto:support@composio.dev).

See [Previous incidents](/docs/security/previous-incidents) for published disclosures, historical impact, and remediation updates.
