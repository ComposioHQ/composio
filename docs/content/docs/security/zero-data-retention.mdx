Zero Data Retention (ZDR) stops Composio from storing the payloads of covered calls. In a project with ZDR on, Composio runs each covered tool call and Proxy Execute request and returns the result without writing the request arguments, response data, or error text to its execution logs. The log for each call keeps metadata only, such as IDs, the tool, timing, and the HTTP status code.

<Callout type="info">
ZDR is an organization-level add-on. It is not available on the free plan. Paid plans can add it for a usage-based price (see [pricing](https://composio.dev/pricing)), and the Enterprise plan includes it. An organization admin turns it on in **Organization Settings > Billing > Add-ons**. On paid plans, ZDR does not cover calls through Composio Managed apps. See [What ZDR does not cover](#what-zdr-does-not-cover).
</Callout>

## How ZDR works

For each covered call, Composio writes a log that holds metadata only:

| Data | Fields |
| --- | --- |
| Stored | Log, project, connected account, auth config, and API key IDs. The user ID you pass. The toolkit slug, tool slug, and tool version. Session, sandbox, and request IDs. The SDK source, runtime, and framework. Start time, end time, and duration. The HTTP status code and whether the call errored. |
| Not stored | Request arguments, response data, and error text. |

Composio stores the user ID you pass with every call, including in ZDR projects. Use opaque user IDs, such as an internal database key, rather than emails or names.

## Scope

When an organization admin turns on ZDR, they choose its scope:

- **All projects** turns on ZDR for every current project. While every project has ZDR on, each project that you create in the dashboard also starts with ZDR on.
- **Selected projects** turns on ZDR for the projects you pick.

Admins can also turn ZDR on or off for one project in **Project Settings > General > Zero Data Retention**.

ZDR covers requests that authenticate with a ZDR project's API key, session, or MCP URL.

<Callout type="warn">
ZDR applies per project. A project without ZDR stores payloads under the [standard data retention policy](/docs/security/data-retention), even when other projects in your organization have ZDR on. Send requests that need ZDR only to projects that have it on.
</Callout>

## What ZDR covers

In a ZDR project, ZDR covers these calls:

- Tool execution, both direct execution and tool calls inside sessions.
- [Proxy Execute](/docs/extending-sessions/proxy-execute) requests.

If Composio cannot read the project's setting when it logs a Proxy Execute request, it does not store the request or response payload.

On the Enterprise plan, ZDR also covers calls through Composio Managed apps. On paid plans, it does not.

Trigger event logs in a ZDR project also omit payloads, but ZDR does not cover triggers.

## What ZDR does not cover

ZDR does not cover the following, even in a ZDR project. For how long Composio keeps logs, files, and sandbox data, see [Data retention](/docs/security/data-retention).

| Feature | Details | What to do |
| --- | --- | --- |
| Composio Managed apps on paid plans | Calls through auth configs that use Composio's own OAuth app are covered only on the Enterprise plan. | [Create an auth config with your own OAuth app](/docs/authentication/custom-app-vs-managed-app#create-a-custom-auth-config) for each toolkit that needs ZDR. Connections made through the managed app keep using it, so each user connects again through the new auth config. You can also [contact sales](https://composio.dev/contact?utm_source=docs&cta_placement=docs-zero-data-retention) about the Enterprise plan. |
| Triggers | Composio receives, processes, and delivers trigger events through systems that ZDR does not cover. | Do not use triggers for data that needs ZDR. |
| Sandbox | The sandbox includes the Workbench and remote Bash. Sessions also offload large responses to it. Sessions turn on the sandbox by default. | [Disable the sandbox](#disable-the-sandbox-in-sessions) when you create sessions. |
| Files | Files that tools upload or download, including binary responses from Proxy Execute, are staged in temporary storage behind signed links. A link expires after 1 hour by default, and you can set the expiry per project from 1 second to 24 hours. Composio cleans up staged files after 24 hours. | Do not use tools that upload or download files for data that needs ZDR. |
| Requests with the `x-debug: true` header | Composio archives these requests for debugging. | Do not send this header from ZDR projects. |
| Tool search in sessions | Composio can cache search queries to improve results. | Keep sensitive data out of search queries. If your agent does not need to discover tools, use the [direct tools preset](/docs/configuring-sessions#direct-tools-preset), which turns off session meta tools such as tool search. |
| Third parties | The destination apps you connect, your model provider, external MCP servers, and your own logs keep their own data policies. | Review each provider's data policy, and set retention for your own logs. |
| Your Composio account | Composio stores your account, billing records, project configuration, and encrypted credentials. | No action is needed. ZDR applies to call payloads, not to these records. |

### Disable the sandbox in sessions

Turn off the sandbox when you create a session:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()

session = composio.sessions.create(
    user_id="user_123",
    sandbox={"enable": False},
)
```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from '@composio/core';
const composio = new Composio({ apiKey: 'your_api_key' });
// ---cut---
const session = await composio.create("user_123", {
  sandbox: { enable: false },
});
```
</Tab>
</Tabs>

See [Disabling the sandbox](/docs/configuring-sessions#disabling-the-sandbox) for what changes in the session.

## Always stored

Composio stores audit logs and telemetry on every plan, and ZDR does not change them:

- **Audit logs** record who did what and when, including the metadata row for each tool call.
- **Telemetry** is the metrics, traces, application logs, error reports, and usage metering that Composio uses to run and bill the service. Telemetry can include error messages returned by providers.

## Existing data

ZDR is not retroactive. Logs written before ZDR was turned on for a project keep their payloads until they age out under the [standard retention policy](/docs/security/data-retention#how-long-logs-are-retained), which keeps tool execution and trigger event logs for up to one year. To request earlier deletion, email [support@composio.dev](mailto:support@composio.dev) with the project ID.

When you turn ZDR off, Composio stores payloads again for new calls. It never stored the payloads of calls made while ZDR was on, so it cannot recover them.

## Turn ZDR on or off

Only organization admins can turn ZDR on or off. Other members can see its status but cannot change it.

### Paid plans and the Enterprise plan

1. In the dashboard, open [**Organization Settings > Billing**](https://dashboard.composio.dev/~/org/settings/billing?utm_source=docs&utm_medium=content&utm_campaign=docs-zero-data-retention).
2. Under **Add-ons**, turn on **Zero Data Retention**.
3. Choose **All projects** or **Selected projects**. If you choose Selected projects, pick the projects.
4. Review the price and what ZDR does not cover, then confirm. ZDR has no separate agreement to sign.

To change which projects have ZDR on, select the project count next to the switch, such as **All projects** or **2 of 5 projects**. To turn ZDR off, turn off **Zero Data Retention** in the same place. To turn ZDR on or off for one project, open [**Project Settings > General**](https://dashboard.composio.dev/~/project/settings/general?utm_source=docs&utm_medium=content&utm_campaign=docs-zero-data-retention) and use the **Zero Data Retention** setting.

### Free plan

ZDR is not available on the free plan. Projects that already had **Don't store data** on keep ZDR on, and an admin can turn it off. Turning it back on requires a paid plan.

### Projects that used Don't store data

ZDR is the setting formerly called **Don't store data** under **Log storage** in Project Settings. Every project kept its setting when it was renamed. Projects that had **Don't store data** now show ZDR on, and projects that had **Store all logs** show ZDR off.

## Projects created through the API

Projects created through the API do not inherit your organization's ZDR choice. They start with ZDR off unless the create request sets `config.log_visibility_setting` to `dont_store_data`. You can also turn ZDR on for them in the dashboard.

Any project with ZDR off, including one created through the API, stops new dashboard projects from starting with ZDR on, because ZDR is no longer on for every project.

## Verify ZDR

1. Send a test call from a ZDR project, such as a tool call made with that project's API key.
2. Open the call's log in the dashboard.
3. Check that the log shows metadata only, with no request arguments, response data, or error text.

If a new log from a ZDR project shows request or response content, email [support@composio.dev](mailto:support@composio.dev) with the log ID and timestamp.
