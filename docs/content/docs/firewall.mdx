Firewall lets you block actions you don't want your agent to take, or tool results you don't want it to receive. For example, you can stop your agent from:

- sharing internal pricing with customers
- posting about unreleased products in public Slack channels
- receiving emails that contain a password or API key
- receiving Salesforce or HubSpot records that contain customers' personal details

Your agent can still use the same tools for everything else.

<Callout type="info">
Custom prompt checks and prompt injection detection are available on paid plans, with [usage-based pricing](https://composio.dev/pricing/platform). Webhooks are available on the Enterprise plan.
</Callout>

Firewall is built on [hooks](/docs/hooks), which run before or after each tool call your agent makes. There are three kinds of checks you can add.

## Custom prompt checks

You describe what you want blocked in natural language, and any tool call or result that matches it is blocked. This is how you'd stop your agent from sharing internal pricing with customers, or from reading emails that contain a password.

See [Custom prompt checks](/docs/hooks/custom-prompt-checks) for examples and for how to write a condition.

## Prompt injection detection

A built-in check scans every tool result for prompt injection, and blocks the result before it reaches your agent.

See [Prompt injection detection](/docs/hooks/prompt-injection-detection) for how to turn it on.

## Webhooks

With a webhook, each tool call is sent to an endpoint you host, and you respond to allow it, block it, or modify it. Use one when a check depends on your own systems. For example, you can scan tool calls for PII with your own detection service, check each tool call against your own permission or approval system, or strip secrets from a tool's result before your agent reads it.

See [Webhooks](/docs/hooks/webhooks) for how to set one up.
