Community integrations extend Composio without requiring a first-party provider package in this monorepo. They usually build on one of these stable surfaces:

- Provider adapters that wrap Composio tools for another agent framework.
- Modifier hooks such as `beforeExecute` and `afterExecute`.
- Direct REST or SDK calls for tool discovery, execution, connection management, and triggers.

Use this page to find community-maintained integrations and to understand where a new integration should live.

## Choosing an integration shape

Create a community package when the integration depends on another framework's release cycle, ownership model, or plugin registry. Link to it from docs instead of copying the package into the Composio monorepo.

Use Composio modifiers when the integration needs to inspect or govern tool calls without changing the provider itself. `beforeExecute` can block or rewrite a tool call before it reaches the external service, and `afterExecute` can record audit data from the result.

Build a first-party provider only when Composio maintainers intend to own the package, publish it with Composio's release process, and keep it compatible with the target framework.

## Listing a community integration

Open a docs PR with:

- Package or repository link.
- Maintainer or owning organization.
- Supported language and framework.
- Minimal install snippet.
- Security model, especially if the integration can execute tools, manage auth, or inspect arguments.
- Test or example links in the integration repository.
