The Pi provider adapts Composio tools for [`@earendil-works/pi-coding-agent`](https://www.npmjs.com/package/@earendil-works/pi-coding-agent), so a Pi session can search Composio tools, manage app connections, execute tools, and optionally drive Composio's remote workbench. Unlike the other providers, `PiProvider` ships its own hook interface, which you use to intercept, allow, deny, or rewrite every helper call before the model sees the result.

<Callout type="warning">
  The Pi provider is experimental and currently ships from `@composio/experimental` for TypeScript
  projects.
</Callout>

## Dynamic session helpers

For most Pi apps, expose the dynamic helper tools. They let the model discover exact Composio tool slugs before it executes, request missing connections, and run workbench commands when you enable them.

<Steps>
<Step>
**Install**

```bash
npm install @composio/core @composio/experimental @earendil-works/pi-coding-agent
```

</Step>

<Step>
**Configure API keys**

```txt title=".env"
COMPOSIO_API_KEY=xxxxxxxxx
```

</Step>

<Step>
**Create a Composio session and Pi tools**

```typescript
// @noErrors
import { Composio } from '@composio/core';
import { PiProvider, createPiComposioSystemPrompt } from '@composio/experimental';
import {
  createAgentSession,
  DefaultResourceLoader,
  getAgentDir,
  SessionManager,
} from '@earendil-works/pi-coding-agent';

const composio = new Composio({
  apiKey: process.env.COMPOSIO_API_KEY,
  provider: new PiProvider(),
});

const composioSession = await composio.sessions.create('user_123', {
  toolkits: ['github', 'gmail'],
  manageConnections: {
    enable: true,
    callbackUrl: 'https://your-app.example.com/auth/callback',
  },
  workbench: { enable: true },
});

const composioTools = composio.provider.createSessionTools({
  sessionId: composioSession.sessionId,
  search: composioSession.search.bind(composioSession),
  execute: composioSession.execute.bind(composioSession),
  callbackUrl: 'https://your-app.example.com/auth/callback',
  includeWorkbenchTools: true,
  connections: {
    getToolkitStates: toolkits => composioSession.toolkits({ toolkits }),
    authorizeToolkit: (toolkit, options) => composioSession.authorize(toolkit, options),
  },
  hooks: {
    execute: (ctx, next) => {
      if (ctx.request.toolSlug === 'COMPOSIO_MANAGE_CONNECTIONS') {
        return ctx.deny('Use composio_manage_connections instead.');
      }
      return next();
    },
    onAuthLink: async ctx => {
      await sendConnectionLinkToUser(ctx.url);
      return { message: 'Connection link sent out-of-band.' };
    },
  },
});

const loader = new DefaultResourceLoader({
  cwd: process.cwd(),
  agentDir: getAgentDir(),
  systemPromptOverride: () =>
    createPiComposioSystemPrompt(composioSession.sessionId, {
      includeWorkbenchTools: true,
    }),
});
await loader.reload();

const { session: piSession } = await createAgentSession({
  cwd: process.cwd(),
  resourceLoader: loader,
  sessionManager: SessionManager.inMemory(process.cwd()),
  customTools: composioTools,
  tools: [
    'composio_search_tools',
    'composio_manage_connections',
    'composio_execute_tool',
    'composio_remote_workbench',
    'composio_remote_bash',
  ],
});

await piSession.prompt('Find my open GitHub issues and summarize the blockers.');
```

</Step>
</Steps>

The provider creates these Pi tools:

- `composio_search_tools` searches Composio for exact tool slugs and schemas.
- `composio_manage_connections` checks connection state and initiates auth for missing toolkits.
- `composio_execute_tool` executes an exact Composio tool slug.
- `composio_remote_workbench` runs Python in the Composio remote workbench, and requires `includeWorkbenchTools: true`.
- `composio_remote_bash` runs short bash commands in the remote workbench filesystem, and requires `includeWorkbenchTools: true`.

You can rename any of these helpers through the `names` option on `createSessionTools`, and the constants live on `PI_COMPOSIO_SESSION_TOOL_NAMES`.

## Hooks

Hooks are the Pi provider's distinctive feature: middleware that wraps each helper so you own what runs and what the model sees. Pass a `hooks` object to `createSessionTools`, and each hook receives a context and a `next` function. Call `await next()` to run the default Composio behavior and get its result before it reaches the model, return that result to pass it through, return another value to replace what the model sees, or call `ctx.deny(reason)` to block the call with a model-visible error. Skip `next()` entirely to handle the operation yourself.

Every hook is `(ctx, next) => unknown | Promise<unknown>`. The `ctx` object carries a mutable `ctx.request` you can rewrite in place, a read-only `ctx.context` with the tool call id, source tool, and session id, and the `ctx.deny(reason: string)` helper. The same deny result is exported as `denyPiToolCall(reason)` from `@composio/experimental` if you prefer to build it directly.

```typescript
// @noErrors
const composioTools = composio.provider.createSessionTools({
  sessionId: composioSession.sessionId,
  search: composioSession.search.bind(composioSession),
  execute: composioSession.execute.bind(composioSession),
  hooks: {
    search: (ctx, next) => {
      ctx.request.toolkits = ctx.request.toolkits?.map(toolkit =>
        toolkit === 'slack' ? 'slackbot' : toolkit
      );
      return next();
    },
    execute: async (ctx, next) => {
      if (ctx.request.toolSlug.startsWith('COMPOSIO_')) {
        return ctx.deny('Meta tools are blocked.');
      }

      const result = await next();
      const file = await saveLargeOutput(result);
      return file ? { message: `Output saved to ${file}` } : result;
    },
    remoteBash: (ctx, next) => {
      if (ctx.request.command.includes('rm -rf')) {
        return ctx.deny('Destructive bash commands are blocked.');
      }
      return next();
    },
    onAuthLink: async (ctx, next) => {
      await sendConnectionLinkToUser(ctx.url);
      return shouldShowLinkToModel(ctx) ? next() : { message: 'Connection link sent out-of-band.' };
    },
  },
});
```

Available hooks, each keyed on `PiSessionHooks`:

- `search(ctx, next)` wraps tool discovery. Rewrite `ctx.request.query` or `ctx.request.toolkits` before search runs.
- `manageConnections(ctx, next)` wraps connection checks and auth. Inspect `ctx.request.toolkits` and `ctx.request.reinitiateAll`.
- `execute(ctx, next)` wraps tool execution. Read or rewrite `ctx.request.toolSlug`, `ctx.request.args`, and `ctx.request.account`, and call `ctx.manageConnections(toolkits)` to connect a missing app inline.
- `remoteWorkbench(ctx, next)` wraps the remote Python helper. Rewrite `ctx.request.code_to_execute` and friends; calling `next()` routes through your `execute` hook too.
- `remoteBash(ctx, next)` wraps the remote bash helper through `ctx.request.command`; calling `next()` also routes through your `execute` hook.
- `onAuthLink(ctx, next)` runs for any auth link found in a result. Read `ctx.url`, `ctx.toolkit`, and `ctx.result`, then call `next()` to keep the model-visible result or return a replacement.

The `execute`, `remoteWorkbench`, and `remoteBash` request types are typed as `PiExecuteHookContext`, `PiRemoteWorkbenchHookContext`, and `PiRemoteBashHookContext`, so your editor surfaces the exact fields on `ctx.request`.

## Static tool wrapping

If you already know exactly which tools to expose, initialize Composio with `PiProvider` and fetch the tools directly.

```typescript
// @noErrors
import { Composio } from '@composio/core';
import { PiProvider } from '@composio/experimental';
import { createAgentSession, SessionManager } from '@earendil-works/pi-coding-agent';

const composio = new Composio({
  apiKey: process.env.COMPOSIO_API_KEY,
  provider: new PiProvider(),
});

const tools = await composio.tools.get('user_123', {
  tools: ['GITHUB_CREATE_ISSUE'],
});

const { session } = await createAgentSession({
  cwd: process.cwd(),
  sessionManager: SessionManager.inMemory(process.cwd()),
  customTools: tools,
  tools: ['GITHUB_CREATE_ISSUE'],
});

await session.prompt('Create a GitHub issue for the failing test.');
```
