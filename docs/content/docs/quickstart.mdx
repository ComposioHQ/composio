Build an agent that chooses Composio tools at runtime. Type a task, connect an app if needed, and continue in the same conversation.

This example uses Python and OpenAI Agents. A Composio session gives the agent tool discovery, account connections, and execution. It exposes only a small set of meta tools, so app schemas are loaded when needed. You can use the same pattern with any [supported provider or framework](/docs/providers).

## Prerequisites

You need:

- [`uv`](https://docs.astral.sh/uv/) to create the Python project and install its dependencies.
- A `COMPOSIO_API_KEY` from [Composio Settings](https://dashboard.composio.dev/~/project/settings/api-keys?utm_source=docs&utm_medium=content&utm_campaign=docs-quickstart).
- An `OPENAI_API_KEY` from [OpenAI](https://platform.openai.com/api-keys).

## Build the agent

<Steps>
<Step>
<StepTitle>Create the project</StepTitle>

Create a Python 3.10 project and enter its directory:

```bash
uv init --app --python 3.10 composio-quickstart
cd composio-quickstart
```

</Step>
<Step>
<StepTitle>Install the packages</StepTitle>

```bash
uv add python-dotenv composio composio-openai-agents openai-agents
```

</Step>
<Step>
<StepTitle>Set your API keys</StepTitle>

Create a `.env` file in the project root:

```bash title=".env"
COMPOSIO_API_KEY=your_composio_api_key
OPENAI_API_KEY=your_openai_api_key
```

Keep `.env` out of source control:

```bash
echo ".env" >> .gitignore
```

</Step>
<Step>
<StepTitle>Add the agent</StepTitle>

Replace `main.py` with this complete program:

```python title="main.py"
import sys

from agents import Agent, Runner, SQLiteSession
from composio import Composio
from composio_openai_agents import OpenAIAgentsProvider
from dotenv import load_dotenv

load_dotenv()

composio = Composio(provider=OpenAIAgentsProvider())
session = composio.sessions.create(user_id="quickstart-user")

agent = Agent(
    name="Composio assistant",
    instructions=(
        "Use Composio tools to complete the request. "
        "If a connection is required, share its Connect Link and wait. "
        "Ask for confirmation before creating, updating, or deleting data."
    ),
    tools=session.tools(),
)

conversation = SQLiteSession("quickstart-conversation")

def run_task(task: str) -> None:
    result = Runner.run_sync(
        starting_agent=agent,
        input=task,
        session=conversation,
    )
    print(f"Assistant: {result.final_output}\n")

if len(sys.argv) > 1:
    run_task(" ".join(sys.argv[1:]))
else:
    print("Ask me to work with your apps. Type 'exit' to quit.")
    while True:
        task = input("You: ").strip()
        if task.lower() == "exit":
            break
        if task:
            run_task(task)
```

</Step>
<Step>
<StepTitle>Run it</StepTitle>

```bash
uv run main.py
```

To run one task without an interactive prompt, pass it as an argument:

```bash
uv run main.py "Find the three most recent open issues in composiohq/composio"
```

Enter any task that needs an app tool. For example:

- `Find the three most recent open issues in a public GitHub repository.`
- `Summarize my unread emails from today.`
- `Turn these release notes into a Linear issue: ...`

These are examples, not a sequence. If a task needs access to an account, the agent gives you a Connect Link. Open it, approve the connection, and tell the agent to continue.

</Step>
</Steps>

## What just happened?

- `OpenAIAgentsProvider` formats Composio tools for OpenAI Agents.
- `composio.sessions.create()` creates a Composio session for `quickstart-user`. The session scopes connections and tool calls to that ID.
- Composio sessions persist. In an application, store `session.session_id` and restore it with `composio.use(session_id)` instead of creating a new session for every turn. See [Reusing a session](/docs/how-composio-works#how-sessions-behave).
- `session.tools()` gives the agent a small set of meta tools for finding, connecting, and running app tools. It does not load thousands of tool schemas into the model context.
- `SQLiteSession` stores the OpenAI conversation history on disk. It is separate from the Composio session.

<Callout type="warn" title="Use your application's user ID in production">
`quickstart-user` is only for this local example. Replace it with a stable ID from your database. Each ID gets separate connections and tool calls.
</Callout>

You can inspect the selected tools, inputs, responses, and timing with the [Logs API](/reference/api-reference/logs).
