Build an interactive agent that can work across your apps. You give it a task; the agent finds the right Composio tools, asks you to connect an app when needed, and runs the tools for that task.

This guide uses Python and OpenAI Agents to keep the setup short. The Composio pattern—create a session for a user, then give its tools to your agent—is the same across [supported providers and frameworks](/docs/providers).

## Prerequisites

You need:

- A terminal with [`uv`](https://docs.astral.sh/uv/) installed. `uv` installs and manages the required Python version for this project.
- A `COMPOSIO_API_KEY` from [Composio Settings](https://dashboard.composio.dev/~/project/settings/api-keys?utm_source=docs&utm_medium=content&utm_campaign=docs-quickstart).
- An `OPENAI_API_KEY` from [OpenAI](https://platform.openai.com/api-keys).

## Build your agent

<Steps>
<Step>
<StepTitle>Initialize the project</StepTitle>

Create an application with Python 3.10 or newer, then enter the new directory:

```bash
uv init --app --python 3.10 composio-quickstart
cd composio-quickstart
```

</Step>
<Step>
<StepTitle>Install the dependencies</StepTitle>

```bash
uv add python-dotenv composio composio-openai-agents openai-agents
```

</Step>
<Step>
<StepTitle>Add your API keys</StepTitle>

Create `.env` in the project root:

```bash title=".env"
COMPOSIO_API_KEY=your_composio_api_key
OPENAI_API_KEY=your_openai_api_key
```

Keep the file out of source control:

```bash
echo ".env" >> .gitignore
```

</Step>
<Step>
<StepTitle>Create the agent</StepTitle>

Replace the generated `main.py` with this complete program:

```python title="main.py"
from agents import Agent, Runner, SQLiteSession
from composio import Composio
from composio_openai_agents import OpenAIAgentsProvider
from dotenv import load_dotenv

load_dotenv()

composio = Composio(provider=OpenAIAgentsProvider())

# A Composio session scopes tools and connected accounts to this user.
composio_session = composio.sessions.create(user_id="quickstart-user")
tools = composio_session.tools()

agent = Agent(
    name="Composio assistant",
    instructions=(
        "Help the user complete tasks with Composio tools. "
        "Search for relevant tools before acting. "
        "If an app is not connected, share the Connect Link and wait. "
        "Confirm the target and details before consequential actions."
    ),
    tools=tools,
)

# This is chat history for OpenAI Agents, separate from the Composio session.
conversation = SQLiteSession("quickstart-conversation")

print("Ask me to work across your apps. Type 'exit' to quit.")
while True:
    task = input("You: ").strip()
    if task.lower() == "exit":
        break
    if not task:
        continue

    result = Runner.run_sync(
        starting_agent=agent,
        input=task,
        session=conversation,
    )
    print(f"Assistant: {result.final_output}\n")
```

</Step>
<Step>
<StepTitle>Run the agent</StepTitle>

```bash
uv run main.py
```

Try a task that is useful to you. For example:

- `Find the three most recent open issues in a public GitHub repository.`
- `Summarize my unread emails from today.`
- `Turn these release notes into a new Linear issue: ...`

These are examples, not a required sequence. The agent discovers tools based on whatever task you enter.

If a task needs access to one of your apps, the agent returns a Connect Link. Open the link, approve the connection, then tell the agent to continue. The same `quickstart-user` can reuse that connection for later tasks.

</Step>
</Steps>

## How the tool router works

The code follows the same four-part flow you will use in an application:

1. `Composio(...)` adapts Composio tools to your agent framework.
2. `composio.sessions.create(user_id=...)` creates a [session](/docs/how-composio-works) for one user and scopes that user's connections and tool calls.
3. `session.tools()` returns a small set of meta tools—not thousands of app-tool schemas. These meta tools let the agent search, authenticate, and execute at runtime.
4. Your agent decides which tools fit each request. When a connection is missing, the same session can provide a Connect Link before the agent continues.

This is why the example is not tied to Gmail, GitHub, Linear, or any single workflow. The task changes; the session pattern does not.

<Callout type="warn" title="Use your application's user ID in production">
`quickstart-user` is only for this local example. In your application, pass the signed-in user's stable database ID so every person's connections and tool calls stay isolated.
</Callout>

To inspect a run, including the selected tools, inputs, responses, and timing, use the [Logs API](/reference/api-reference/logs).
