The **Composio plugin for Claude Code** helps Claude discover and run the right Composio CLI command when a task involves an external app. It is a thin, CLI-based plugin: the plugin adds Claude Code hooks and a connection command, while the `composio` CLI handles tool search, execution, and authentication.

The plugin does **not** bundle an MCP server or a skill. If you want to add the remote Composio MCP server to Claude Code, see [Composio Connect](/docs/composio-connect).

## What you get

| Component                             | Purpose                                                                                                                                                                                                   |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SessionStart hook**                 | Tells Claude about Composio's `search` → `execute` workflow, reports CLI authentication status, and warms a local cache of popular toolkits. It runs when a session starts, resumes, clears, or compacts. |
| **UserPromptSubmit hook**             | Nudges Claude toward `composio search` when your prompt names an app in the local toolkit cache. It uses the cache and does not make a network request for each prompt.                                   |
| **`/composio-connect <app>` command** | Connects an app with `composio link` and managed OAuth, then verifies the connection.                                                                                                                     |

The Composio CLI installs the full `composio-cli` skill separately when you sign in. That skill contains the detailed CLI reference; it is not packaged inside this plugin.

## Install

<Steps>
<Step>
<StepTitle>Install and set up Composio</StepTitle>

If the CLI is not already installed, run:

```bash
curl -fsSL https://composio.dev/install | bash
composio login
composio setup --target claude
```

Login authenticates the CLI. Setup then adds the GitHub-hosted marketplace, installs and enables `composio@composio`, and installs the matching `composio-cli` skill. Setup is safe to rerun.

</Step>
<Step>
<StepTitle>Try it</StepTitle>

Ask Claude to act on an app, for example: _"List my open GitHub pull requests."_ Claude can search for the appropriate tool, ask you to connect GitHub if necessary, and execute it.

You can also connect an app directly:

```text
/composio-connect github
```

</Step>
</Steps>

### Manual plugin fallback

If you need to register the plugin directly in Claude Code, add the marketplace:

In Claude Code, run:

```text
/plugin marketplace add ComposioHQ/composio-plugin-cc
```

This adds Composio's GitHub-hosted marketplace. It does not install the plugin yet.

Then install the plugin:

```text
/plugin install composio@composio
```

Finish the local prerequisites with `composio login` and `composio --install-skill claude` if they are not already ready. `composio setup --target claude` is preferred for plugin and skill installation because it verifies those pieces together.

## Team setup

To make the marketplace and plugin available to everyone working in a repository, add this to the project's `.claude/settings.json`:

```json title=".claude/settings.json"
{
  "extraKnownMarketplaces": {
    "composio": {
      "source": {
        "source": "github",
        "repo": "ComposioHQ/composio-plugin-cc"
      }
    }
  },
  "enabledPlugins": {
    "composio@composio": true
  }
}
```

Claude Code prompts teammates to trust and enable the plugin when they open the project. Each teammate still needs the `composio` CLI installed and must sign in on their machine.

## How it works

The plugin keeps the integration lightweight and lets the CLI own its capabilities:

1. **Session context** — the SessionStart hook tells Claude to use Composio for external apps, surfaces CLI authentication status, and caches a small list of popular toolkits.
2. **Prompt routing** — the UserPromptSubmit hook checks the prompt against that local cache. When it recognizes an app, it reminds Claude to use Composio's just-in-time tool search.
3. **Tool discovery and execution** — Claude runs `composio search "<task>"`, then `composio execute` with the selected tool. If an app is not connected, it runs `composio link <app>` to start managed OAuth.
4. **CLI-provided guidance** — the separately installed `composio-cli` skill gives Claude the full command and workflow reference.

The hooks guide Claude; they do not expose tools or execute app actions themselves.

## Updating

Plugin updates and CLI updates are separate. Update the marketplace checkout and reload plugins in Claude Code:

```text
/plugin marketplace update composio
/reload-plugins
```

Update the CLI to receive the latest Composio commands, tool-routing behavior, and generated skill:

```bash
composio upgrade
```

## Plugin or MCP setup?

The Claude Code plugin and the API-key MCP setup are two different ways to use Composio:

|                                 | Claude Code plugin                                                     | Composio Connect MCP                                      |
| ------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------- |
| Runtime                         | Local `composio` CLI                                                   | Remote MCP server                                         |
| Tool access                     | Claude runs `composio search`, `composio execute`, and `composio link` | Claude calls Composio's MCP meta-tools                    |
| Claude Code integration         | Session and prompt hooks plus `/composio-connect`                      | MCP tools registered with `claude mcp add`                |
| Skill                           | Installed and updated separately by the CLI                            | No CLI skill required                                     |
| Initial Composio authentication | `composio login`                                                       | Consumer API key in the MCP configuration                 |
| Updates                         | Update both the marketplace plugin and CLI                             | Server-side; the MCP configuration remains in Claude Code |

Choose the plugin when you want Claude Code to use the local CLI and its scripting workflows. Choose [Composio Connect](/docs/composio-connect) when you want an MCP-native setup or the same remote MCP interface across multiple clients.

## Troubleshooting

### The plugin installs, but Claude cannot run Composio

Confirm the CLI is available and that you are signed in:

```bash
composio --version
composio whoami
```

If the first command fails, [install the CLI](#install). If the second reports that you are signed out, run `composio login`.

### The CLI skill is missing

The plugin does not bundle the `composio-cli` skill. Rerun `composio setup --target claude`, or install the skill explicitly:

```bash
composio --install-skill claude
```

### Claude does not receive an app-specific nudge

The UserPromptSubmit hook only matches apps in its cached popular-toolkit list. Claude can still use Composio for any supported app: ask it to run `composio search "<task>"`, or connect the app with `/composio-connect <app>`.

### An app is not connected or a tool call fails

Run `composio link <app>` to connect the app, then retry the action. For CLI-specific diagnostics, use the troubleshooting guidance in the installed `composio-cli` skill. For the separate MCP integration, see [Composio Connect troubleshooting](/docs/composio-connect#troubleshooting).

For marketplace registration, plugin loading, or hook errors, see the [Claude Code plugin troubleshooting documentation](https://code.claude.com/docs/en/plugins-reference#common-issues).
