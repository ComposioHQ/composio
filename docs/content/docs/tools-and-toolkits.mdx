A **toolkit** is a collection of related tools for a service. The `github` toolkit, for example, contains tools for creating issues, managing pull requests, and starring repositories.

A **tool** is an individual action your agent can execute. Each tool has an input schema (its parameters) and an output schema (what it returns), and follows a `{TOOLKIT}_{ACTION}` naming pattern, like `GITHUB_CREATE_ISSUE`.

## Meta tools

In a [session](/docs/how-composio-works), your agent doesn't load every tool into context. It works through **meta tools**, a small fixed set that search the catalog, fetch schemas, authenticate users, and execute app tools at runtime. The agent searches for what it needs, connects the user if required, then executes, all within the same session.

See the [Meta Tools reference](/reference/meta-tools) for each tool's input and output schema.

If you already know which tools the agent should use, the [direct tools preset](/docs/configuring-sessions#direct-tools-preset) exposes them directly from `session.tools()` and turns the meta tools off.

## What toolkits can my agent reach?

Every toolkit in the catalog is discoverable by default. Create a session without a `toolkits` parameter and the agent can find any of them through search at runtime. To restrict the set, pass `toolkits` when you create the session. See [Enable and disable toolkits](/docs/toolkits/enable-and-disable-toolkits).

You can also bind local, in-process tools to a session with the experimental [custom tools and toolkits](/docs/toolkits/custom-tools-and-toolkits) API.

## Authentication

Tools execute with the user's authenticated credentials. Once a user connects their GitHub account, every GitHub tool runs with their permissions. For OAuth toolkits, Composio uses [managed apps](/docs/custom-app-vs-managed-app) by default; bring your own app when you need your own branding, scopes, or consent screen. If a tool needs a connection the user hasn't made yet, the agent prompts them through `COMPOSIO_MANAGE_CONNECTIONS`.
