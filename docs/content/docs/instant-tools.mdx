Instant Tools let your agent run supported tools without waiting for a user to connect a provider account. Composio supplies the provider access for those calls. You can still use the same tool with your user's own account when you want their provider identity, quota, or terms.

## Find a supported tool

Start with the [tool catalog](/reference/api-reference/tools/getTools). A supported tool includes `instant.supported: true`. Its optional `instant.price` describes the additional Instant charge and any discount. Unsupported tools omit `instant`. A toolkit includes `instant.supported: true` when at least one of its tools supports Instant, so check the tool before running it.

```json
{
  "slug": "EXA_SEARCH",
  "instant": {
    "supported": true,
    "price": {
      "description": "See the current per-search rate in the tool catalog."
    }
  }
}
```

The description above illustrates the response shape, not a price quote. Read the current tool record for its rate. Prices vary by tool and unit, and an Instant charge is **additional to standard tool-call charges and platform fees**. A `discount` is a percentage from 0 to 100. Only You.com and Parallel have a 100% Instant discount in this release; the regular rate remains visible in `description`.

## Use Instant in a Session

Instant is enabled by default when your project setting allows it. Create a Session and use a supported tool. You don't need an `instant` block for the default behavior.

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
session = composio.sessions.create(user_id="user_123", toolkits=["exa"])
result = session.execute("EXA_SEARCH", arguments={"query": "Composio documentation"})
print(result.data)
```
</Tab>
<Tab value="TypeScript">
```typescript
import { Composio } from "@composio/core";

const composio = new Composio();
const session = await composio.create("user_123", { toolkits: ["exa"] });
const result = await session.execute("EXA_SEARCH", { query: "Composio documentation" });
console.log(result.data);
```
</Tab>
</Tabs>

Check the tool's current [input schema](/reference/api-reference/tools/getToolsByToolSlug) before constructing arguments. You can also pass `session.tools()` to your agent as in the [Quickstart](/docs/quickstart). A Session exposed through [MCP](/docs/sessions-via-mcp) uses the same Instant policy.

## Choose which tools can use Instant

The outer `toolkits` and `tools` filters decide which tools exist in the Session. The nested `instant` filters can narrow Instant access within that set. They cannot restore a toolkit excluded by the outer filters. Omit the nested filters to keep Instant available for every supported tool in the Session.

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa", "firecrawl"],
    instant={
        "toolkits": {"enable": ["exa"]},
        "tools": {"exa": {"enable": ["EXA_SEARCH"]}},
        "return_charge": True,
    },
)
```
</Tab>
<Tab value="TypeScript">
```typescript
import { Composio } from "@composio/core";

const composio = new Composio();
const session = await composio.create("user_123", {
  toolkits: ["exa", "firecrawl"],
  instant: {
    toolkits: { enable: ["exa"] },
    tools: { exa: { enable: ["EXA_SEARCH"] } },
    returnCharge: true,
  },
});
```
</Tab>
</Tabs>

Each nested filter accepts either `enable` or `disable`. `return_charge` in Python (`returnCharge` in TypeScript) defaults to `false`. It controls whether an Instant charge appears in the immediate execution response, not whether a call can incur one. An `instant` object after `instant: false` enables Instant again; on update, omitted nested fields preserve their stored values.

To disable Instant for one Session, call `session.update(instant=False)` in Python or `session.update({ instant: false })` in TypeScript. Turning Instant off never enables a toolkit that the outer filters disabled.

## Keep Instant but disable connected accounts

If you want a Session to use Instant without your users' connected accounts or API keys, set `connected_account_usage` to `False` in Python or `connectedAccountUsage: false` in TypeScript. This is separate from `connected_accounts`, which selects account IDs, and `manage_connections`, which controls the connection flow. The default is `true`.

```python
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
    connected_account_usage=False,
)
```

Automatic routing can use Instant when a connected credential is missing or unusable before dispatch. An explicit account choice or authorization failure does not silently change identity, and a failed provider call is not retried on another account.

## Read an Instant charge

Set `return_charge` (`returnCharge` in TypeScript) to `true` when you need the actual Instant amount in an execution result. Only an Instant execution includes `instant`. When the amount is known, it includes `instant.charge`; a fully discounted successful call reports `amount: "0"`. If the amount is unknown, `instant` is an empty object and `charge` is omitted.

```json
{
  "data": { "results": [] },
  "error": null,
  "log_id": "log_abc123",
  "instant": {
    "charge": { "amount": "0.01", "currency": "USD", "charged_by": "composio" }
  }
}
```

TypeScript converts `charged_by` to `chargedBy`. A batch execution reports one aggregate `instant.charge` on the batch response when every Instant amount is known; child results do not carry a charge. If any Instant amount is unknown, the batch omits `charge`. The charge is the amount Composio charges for Instant access, after any discount. Standard tool-call charges and platform fees remain separate.

## Choose the access route

| Route | Provider account | Instant charge |
|---|---|---|
| Tool requiring no connection | None needed | None |
| Your user's connected account | The user's account or API key | None |
| Instant Tool | Composio-supplied access for a supported tool | May apply |

Composio-managed auth supplies OAuth application credentials, but the user still connects their own account. It does not by itself make a tool Instant. A toolkit can mix tools from all three routes. Direct tool execution outside a Session does not inherit its Instant policy, and Instant access does not support arbitrary proxy calls.

The project setting controls whether Sessions can use Instant and starts enabled by default. You can disable it in project settings; a Session cannot override an off project setting. See [Configuring Sessions](/docs/configuring-sessions) for the other Session filters and the [Session API reference](/reference/api-reference/tool-router/postToolRouterSession) for the complete request.
