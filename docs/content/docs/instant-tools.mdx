Your agent should be able to run a web search without making every user set up an Exa account or handle a separate bill. Instant tools makes that possible: Composio handles provider access and billing. Run a search, get its results, and see the actual charge for the call.

<Callout type="warning" title="Experimental access">
  Reach out to [support@composio.dev](mailto:support@composio.dev) to get access to Instant tools and confirm supported tools and rates. Once access is granted, turn on `enable_instant` in your project settings. A Session cannot override a project where this setting is off. The code below uses the currently released SDK fields; the planned tool-level listing fields are not in the public API yet.
</Callout>

## Run one search

Install `composio` and `python-dotenv`, then put `COMPOSIO_API_KEY` in a `.env` file as in the [Quickstart](/docs/quickstart), and ask support to confirm that `EXA_SEARCH` is enabled for your project. This Python example runs the search and prints its result and actual charge when a charge is returned:

```python
from dotenv import load_dotenv
from composio import Composio

load_dotenv()
composio = Composio()
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
    premium_usage={
        "toolkits": {"enable": ["exa"]},
        "return_premium_charge": True,
    },
)
result = session.execute(
    "EXA_SEARCH",
    arguments={"query": "Composio documentation"},
)
if result.error:
    raise RuntimeError(f"Search failed: {result.error}")

print(result.data)
if result.premium_charge is not None:
    print(result.premium_charge["amount"], result.premium_charge["currency"])
else:
    print("No charge returned; check the execution log and project billing")
```

The result is the tool's search response. The printed amount is the charge for this execution, not a fixed Exa price. Check the current tool input schema before changing the arguments. Confirm the supported tools and rates with support before production use; neither the existence of `EXA_SEARCH` nor the example guarantees a specific rate or that this project has access. See [tool execution logs](/docs/poc-to-prod/stream-logs-to-a-siem) for the charge record.

## Coverage and routing

Instant tools are individual tools within an app, not every tool in an app. Some actions still require the user's own provider connection. Today’s [toolkit listing API](/reference/api-reference/toolkits/getToolkits) does not indicate which tools support the instant route or filter by it. Its `no_auth` and `composio_managed_auth_schemes` fields do not mean Instant tools support. The planned tool listing field is `instant` on each supported tool, not an app-level label. This change is not yet in the public API. Confirm current coverage and prices with support.

A connection you explicitly select takes priority and does not fall back to another account on failure. Otherwise, an available user or shared connection takes priority over Composio's provider account. When no supported provider route exists, use the normal connection flow. Composio-managed OAuth still asks the user to connect their own account; it is not access to Instant tools. This route does not support arbitrary provider requests through proxy execution.

## Control which calls may incur charges

First get access from support. Then turn on `enable_instant` in your project settings to use Instant tools. This is a project setting, not a field to pass to the current SDK. The Session policy below controls eligible calls after project access is granted and the setting is on; it does not turn the project setting on.

The released Session policy is named `premium_usage` in Python and REST, or `premiumUsage` in TypeScript. These are existing API field names, not a new product or tier name. Once the project is enabled, an omitted policy permits eligible calls by default. To block charged calls in a particular Session, create it with `premium_usage=False` (TypeScript: `premiumUsage: false`), or call `session.update(premium_usage=False)` later. Your own connected-account routes remain available.

Top-level `toolkits` determines which tools the Session can discover and run. `premium_usage.toolkits` separately restricts which eligible tools can incur these charges. To allow only Exa and only `EXA_SEARCH`, use:

```python
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
    premium_usage={
        "toolkits": {"enable": ["exa"]},
        "tools": {"exa": {"enable": ["EXA_SEARCH"]}},
        "return_premium_charge": True,
    },
)
```

Each filter takes either `enable` or `disable`, not both. A `tools.exa` rule by itself does not block charged calls in other toolkits. `return_premium_charge` controls whether the immediate response includes charge detail, not whether a call may spend. Supplying any policy object when updating a Session that was set to `false` enables the policy again if the project allows it. Session search and MCP use the same Session policy; direct execution outside a Session does not inherit it. See [Configuring Sessions](/docs/configuring-sessions) for general filters and the [create Session reference](/reference/api-reference/tool-router/postToolRouterSession) for the shipped request schema.
