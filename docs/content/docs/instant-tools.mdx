Instant Tools let your Session run supported tools without an end-user provider connection. A Composio Instant account provides access for eligible tools. Instant usage charges for those calls come from your organization's available balance.

<Callout type="warning" title="Experimental access">
  This feature requires a project setting that is not yet self-service. Email [support@composio.dev](mailto:support@composio.dev) to enable it for your project and confirm which tools and rates are available. Session configuration cannot override a project where the setting is off.
</Callout>

Once the project setting is enabled, new Sessions can use eligible Instant Tools by default, even if `instant` is omitted. Set `instant=False` in Python or `instant: false` in TypeScript when creating a Session that must not incur Instant usage charges.

Project configuration uses `enable_instant` in API requests and responses. The SDK has no project-settings setter; configure the project before creating a Session. Existing project and Session settings saved under the previous premium names must be saved again under the Instant names. The previous names are not aliases.

## Find eligible tools

Use `instant_account_available` in the public catalog to find Instant Tools. For example, list Exa's tools and read the boolean on each item:

```bash
curl 'https://backend.composio.dev/api/v3.1/tools?toolkit_slug=exa&limit=100' \
  -H "x-api-key: $COMPOSIO_API_KEY"
```

The field is available on toolkit list, multi-fetch, and detail responses, and tool list and detail responses, through both `/api/v3` and `/api/v3.1`. Session tool-list responses expose the same field on each returned tool.

| Catalog item | Meaning of `instant_account_available: true` |
|---|---|
| Toolkit | At least one tool in this toolkit supports an Instant account. Check the individual tools before selecting one. |
| Tool | This tool's slug is on its toolkit's Instant allowlist. |

Follow `next_cursor` to read subsequent pages. To check a specific tool, use the [tool detail API](/reference/api-reference/tools/getToolsByToolSlug):

```bash
curl 'https://backend.composio.dev/api/v3.1/tools/EXA_SEARCH' \
  -H "x-api-key: $COMPOSIO_API_KEY"
```

Catalog support is independent of your project's Instant setting and Session policy. A value of `true` does not enable execution or authorize charges. Custom toolkits and tools return `false`, even if they share a slug with a supported native resource.

Catalog and Session tool-list responses fall back to `instant_account_available: false` if availability metadata cannot be read.

The catalog has no Instant-only filter. Use the boolean to identify supported items in your results. `no_auth` and `composio_managed_auth_schemes` describe different authentication properties and do not indicate Instant Tools support. During Experimental access, ask [support@composio.dev](mailto:support@composio.dev) to enable your project and confirm current rates before allowing Instant usage in a production Session.

## Create a Session

After your project is enabled, create a Session. This example makes Exa available and permits Instant usage for its eligible tools:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
    instant={
        "toolkits": {"enable": ["exa"]},
        "return_instant_charge": True,
    },
)
```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from "@composio/core";

const composio = new Composio();
const session = await composio.create("user_123", {
  toolkits: ["exa"],
  instant: {
    toolkits: { enable: ["exa"] },
    returnInstantCharge: true,
  },
});
```
</Tab>
</Tabs>

Top-level `toolkits` controls which tools the Session can discover and run. Omit it to make all toolkits discoverable. `instant.toolkits` separately restricts which eligible tools can incur Instant usage charges. Omitting `instant.toolkits` does not restrict Instant usage: eligible tools remain available when the project and Session permit them. `return_instant_charge` defaults to `false` and only controls whether the actual charge appears in the immediate tool response. An Instant toolkit can still contain tools that need a connected account; Instant account coverage is tool-specific.

## Find and run a tool

Pass `session.tools()` to your agent as in the [Quickstart](/docs/quickstart), so it can discover and run eligible tools. If your agent uses MCP, expose the same Session through `session.mcp` as described in [Using sessions via MCP](/docs/sessions-via-mcp). The Instant usage policy applies to that Session in either path; your agent does not need a separate Instant usage setting.

### Read charge details in Python

With `instant.return_instant_charge` enabled, `session.execute()` returns charge details when available in the typed `instant_charge` field on `ToolRouterSessionExecuteResponse`. Read it from the result above:

```python
charge = result.instant_charge
if charge is not None:
    print(charge["amount"], charge["currency"], charge["charged_by"])
```

The `InstantCharge` type is exported from `composio.types` and includes `amount`, `currency`, and `charged_by`. Python provider integrations and mixed local/remote multi-tool execution also preserve these charge details.

## Control Instant usage

`instant` is a Session policy in both SDKs. It does not enable a toolkit that top-level `toolkits` excludes, and it does not change a connected account you explicitly selected.

The toolkit filter and per-tool filter intersect. A `tools.exa` rule alone does not disable Instant usage for other eligible toolkits. Use `instant.toolkits` when you need a toolkit allowlist. Each filter accepts either `enable` or `disable`, not both.

The examples below use Python and REST field names. In TypeScript, use `instant` and `returnInstantCharge`, and read the charge from `instantCharge` on the tool result.

| Session value | Effect |
|---|---|
| Omitted or `{}` | Permits Instant usage for eligible tools, subject to the project setting and normal Session filters. The charge is not returned in tool responses by default. |
| `false` | Disables Instant usage for that Session. Your own connected-account routes remain available. |
| `{ "toolkits": { "enable": ["exa"] } }` | Permits Instant usage only for listed toolkits. Use `disable` instead to exclude selected toolkits. |
| `{ "tools": { "exa": { "enable": ["EXA_SEARCH"] } } }` | Narrows Instant usage to selected tools within a toolkit. |
| `{ "return_instant_charge": true }` | Requests the actual `instant_charge` in an eligible Session tool response. On create, this changes charge visibility, not permission to spend. On update, it also re-enables Instant usage on a Session set to `false`, like any other object. |

For example, keep Exa and Firecrawl available, but permit Instant usage only for `EXA_SEARCH`:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa", "firecrawl"],
    instant={
        "toolkits": {"enable": ["exa"]},
        "tools": {"exa": {"enable": ["EXA_SEARCH"]}},
    },
)
```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from "@composio/core";
const composio = new Composio();
// ---cut---
const session = await composio.create("user_123", {
  toolkits: ["exa", "firecrawl"],
  instant: {
    toolkits: { enable: ["exa"] },
    tools: { exa: { enable: ["EXA_SEARCH"] } },
  },
});
```
</Tab>
</Tabs>

To stop Instant usage on an existing Session, update its policy:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
session.update(instant=False)
```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from "@composio/core";
const composio = new Composio();
const session = await composio.create("user_123");
// ---cut---
await session.update({ instant: false });
```
</Tab>
</Tabs>

On patch, omitted `instant` fields keep their existing values. Supplying any object after `false`, even one that only sets `return_instant_charge`, enables this Session policy again, provided the project allows it.

## Know which account runs the tool

An Instant account is a provider account held by Composio for specific tools. It is different from **Composio-managed auth**, where Composio supplies OAuth application credentials but your user still connects their own account. Composio-managed auth alone does not make a tool Instant.

If you select a connected account explicitly, that route wins and does not fall back to the Instant account on failure. Otherwise, available user or shared connections take priority over an Instant account. If the chosen tool is not supported by an Instant account, it follows the normal connection flow.

Session search tells you when an Instant account serves a toolkit. The toolkit's connection status includes `instant_account.allowed_tool_slugs` (`instantAccount.allowedToolSlugs` in TypeScript), which lists the tools that run on it. Any other tool in that toolkit needs the user's own connection.

To explicitly select the Composio Instant account, pass `account="instant_account"` to Python `session.execute()` or `{ account: 'instant_account' }` as the TypeScript execution options. For direct `composio.tools.execute()`, pass `connected_account_id="instant_account"` in Python or `connectedAccountId: 'instant_account'` in TypeScript. This selection does not fall back to another credential if the call fails.

Instant accounts cannot run arbitrary provider requests through proxy execution. Use supported tool actions. Direct execution outside a Session does not inherit its `instant` policy.
