# Instant Tools

An Instant Tool is a specific tool inside a toolkit that works with zero setup: your end user connects nothing, and the call either runs on a Composio hosted account or is free. Tool calls to paid Instant Tools are charged to your organization's Balance at that tool's per-call price.

Instant describes availability, not exclusivity. One tool, two ways to run it: the same Instant Tool runs on the hosted account out of the box, or on your end user's own key when they want their own quota and terms, or need data-handling terms the hosted account does not cover, such as a zero data retention (ZDR) arrangement with the provider.

## The model

- **A toolkit is the catalog unit.** Toolkits group related tools (for example, `exa` groups Exa's search tools).
- **An Instant Tool is one tool inside a toolkit, not a kind of toolkit.** Eligibility is per tool: within a toolkit, only some tools may be Instant.
- **The same toolkit can mix both kinds.** Instant Tools and bring your own key (BYOK) tools sit side by side in one toolkit.
- **The same tool can run both ways.** An Instant Tool runs on the hosted account with zero setup, or on the user's own key when they bring one. Tools that are not Instant always follow the normal connection flow with the user's own account.
- **"Instant Tools" the product is the collection** of every Instant Tool across all toolkits. There is no "instant app" and no "instant toolkit": nothing about a toolkit as a whole makes it Instant.

Each Instant Tool has its own per-call price. There are no tiers and no bundles: one tool call to a paid Instant Tool on the hosted account produces one charge against your Balance. Calls on the user's own key do not touch your Balance.

| Term | Meaning |
| --- | --- |
| Instant Tool | A tool that works with zero setup: it runs on a hosted account or is free |
| Hosted account | A provider account held by Composio that runs the call on behalf of your users |
| Bring your own key (BYOK) | The call runs on your or your end user's own provider account and credentials |
| Balance | Your organization's prepaid Balance for Instant Tool calls on hosted accounts |
| Charge | The amount deducted from the Balance for one paid tool call |
| Tool call | One execution of a tool |

> **Early access:** Instant Tools are enabled per organization. Reach out to [support@composio.dev](mailto:support@composio.dev) to get access and to confirm current per-tool prices.

> **Zero data retention (ZDR) is not enabled for Instant Tools.** Calls that run on Composio's hosted account are not covered by ZDR. If a workload requires ZDR, run the same tool on the user's own key instead, where retention follows the provider's own terms and can offer ZDR. Using your own key changes which account runs the call; it does not by itself guarantee zero data retention. Contractual ZDR requires its own arrangement with the provider, or Composio's Enterprise track.

## Enable Instant Tools [#enable-instant-tools]

Access is granted per organization by support. Once granted, enable Instant Tools per project:

1. Open your project in the dashboard.
2. Go to **Settings → General → Configuration**.
3. Turn on **Premium usage**. This toggle appears only after support grants your organization access.

Session configuration cannot override a project where the setting is off.

Once the project setting is enabled, new Sessions can use eligible Instant Tools by default, even if `premium_usage` is omitted. Set `premium_usage=False` in Python or `premiumUsage: false` in TypeScript when creating a Session that must not incur charges.

## Find eligible tools [#find-eligible-tools]

Instant coverage is per tool, not per toolkit. Neither the [toolkit listing API](/reference/api-reference/toolkits/getToolkits) nor the tools listing API returns Instant eligibility, hosted-account availability, or per-tool prices, and neither offers an Instant filter. Their `no_auth` and `composio_managed_auth_schemes` fields mean different things and should not be used as substitutes.

The discovery surface is Session search: `POST /api/v3/tool_router/session/{session_id}/search` (see the [tool router API reference](/reference/api-reference/tool-router)) returns `toolkit_connection_statuses[].hosted_account.allowed_tool_slugs` (`hostedAccount.allowedToolSlugs` in TypeScript), which lists the tools of that toolkit that run on the Composio hosted account. Any other tool in the toolkit needs the user's own connection. During early access, confirm current per-tool prices with [support@composio.dev](mailto:support@composio.dev) before allowing paid Instant Tools in a production Session.

## Create a Session [#create-a-session]

After your project is enabled, create a Session. This example makes Exa available and permits charges for its eligible tools:

Python:

```python
from composio import Composio

composio = Composio()
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
    premium_usage={
        "toolkits": {"enable": ["exa"]},
        "return_premium_charge": True,
    },
)

```

TypeScript:

```typescript
// @noErrors
import { Composio } from "@composio/core";

const composio = new Composio();
const session = await composio.create("user_123", {
  toolkits: ["exa"],
  premiumUsage: {
    toolkits: { enable: ["exa"] },
    returnPremiumCharge: true,
  },
});

```

Top-level `toolkits` controls which tools the Session can discover and run. Omit it to make all toolkits discoverable. `premium_usage.toolkits` (or `premiumUsage.toolkits` in TypeScript) separately restricts which eligible tools can incur charges. Omitting `premium_usage.toolkits` does not restrict charging: eligible tools remain available when the project and Session permit them. `return_premium_charge` defaults to `false` and only controls whether the actual charge appears in the immediate tool response. A toolkit with Instant Tools can still contain tools that need a connected account; hosted account coverage is tool-specific.

## Find and run a tool [#find-and-run-a-tool]

Pass `session.tools()` to your agent as in the [Quickstart](/docs/quickstart), so it can discover and run eligible tools. If your agent uses MCP, expose the same Session through `session.mcp` as described in [Using sessions via MCP](/docs/sessions-via-mcp). The charge policy applies to that Session in either path; your agent does not need a separate setting.

Python:

```python
tools = session.tools()  # Pass these to your agent framework.

```

TypeScript:

```typescript
import { Composio } from "@composio/core";
const composio = new Composio();
const session = await composio.create("user_123");
// ---cut---
const tools = await session.tools(); // Pass these to your agent framework.

```

To run a known tool yourself, use the Session's `execute` method:

Python:

```python
result = session.execute("EXA_SEARCH", arguments={"query": "Composio documentation"})

```

TypeScript:

```typescript
import { Composio } from "@composio/core";
const composio = new Composio();
const session = await composio.create("user_123");
// ---cut---
const result = await session.execute("EXA_SEARCH", { query: "Composio documentation" });

```

Check the current [tool input schema](/reference/api-reference/tools/getToolsByToolSlug) before constructing arguments. A tool appearing in a toolkit does not mean hosted account access is available for that tool. Use Session search to confirm which tools run on the hosted account, and confirm per-tool prices with support during early access.

### Read charge details in Python [#read-charge-details-in-python]

With `premium_usage.return_premium_charge` enabled, `session.execute()` returns charge details when available in the typed `premium_charge` field on `ToolRouterSessionExecuteResponse`. Read it from the result above:

```python
charge = result.premium_charge
if charge is not None:
    print(charge["amount"], charge["currency"], charge["charged_by"])

```

The `PremiumCharge` type is exported from `composio.types` and includes `amount`, `currency`, and `charged_by`. Python provider integrations and mixed local/remote multi-tool execution also preserve these charge details.

## Control charges on a Session [#control-premium-usage]

`premium_usage` is a Session policy (`premiumUsage` in TypeScript) that controls which eligible tools may charge your Balance. It does not enable a toolkit that top-level `toolkits` excludes, and it does not change a connected account you explicitly selected.

The toolkit filter and per-tool filter intersect. A `tools.exa` rule alone does not disable charges for other eligible toolkits. Use `premium_usage.toolkits` when you need a toolkit allowlist. Each filter accepts either `enable` or `disable`, not both.

The examples below use Python and REST field names. In TypeScript, use `premiumUsage` and `returnPremiumCharge`, and read the charge from `premiumCharge` on the tool result.

| Session value | Effect |
| --- | --- |
| Omitted or `{}` | Permits charges for eligible tools, subject to the project setting and normal Session filters. The charge is not returned in tool responses by default. |
| `false` | Disables charges for that Session. Your own connected-account routes remain available. |
| `{ "toolkits": { "enable": ["exa"] } }` | Permits charges only for listed toolkits. Use `disable` instead to exclude selected toolkits. |
| `{ "tools": { "exa": { "enable": ["EXA_SEARCH"] } } }` | Narrows charging to selected tools within a toolkit. |
| `{ "return_premium_charge": true }` | Requests the actual `premium_charge` in an eligible Session tool response. On create, this changes charge visibility, not permission to spend. On update, it also re-enables charging on a Session set to `false`, like any other object. |

For example, keep Exa and Firecrawl available, but permit charges only for `EXA_SEARCH`:

Python:

```python
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa", "firecrawl"],
    premium_usage={
        "toolkits": {"enable": ["exa"]},
        "tools": {"exa": {"enable": ["EXA_SEARCH"]}},
    },
)

```

TypeScript:

```typescript
// @noErrors
const session = await composio.create("user_123", {
  toolkits: ["exa", "firecrawl"],
  premiumUsage: {
    toolkits: { enable: ["exa"] },
    tools: { exa: { enable: ["EXA_SEARCH"] } },
  },
});

```

To stop charges on an existing Session, update its policy:

Python:

```python
session.update(premium_usage=False)

```

TypeScript:

```typescript
// @noErrors
await session.update({ premiumUsage: false });

```

On patch, omitted `premium_usage` fields keep their existing values. Supplying any object after `false`, even one that only sets `return_premium_charge`, enables this Session policy again, provided the project allows it.

## Know which account runs the tool [#know-which-account-runs-the-tool]

An Instant Tool can run on either account: the hosted account, or the user's own key. The choice is per call, not per tool.

A hosted account is a provider account held by Composio for specific tools. It is different from Composio-managed auth, where Composio supplies OAuth application credentials but your user still connects their own account. Composio-managed auth alone does not make a tool Instant.

If you select a connected account explicitly, that route wins and does not fall back to the hosted account on failure. Passing `connected_account_id="hosted_account"` on execute selects the hosted account explicitly; the call fails rather than falling back when the hosted account cannot serve that tool. Otherwise, available user or shared connections take priority over a hosted account. If the chosen tool is not supported by a hosted account, it follows the normal connection flow. Bring-your-own-key calls are billed by the provider to the key's owner; they do not touch your Balance and follow the provider's own data terms.

Session search tells you when a hosted account serves a toolkit. The toolkit's connection status includes `hosted_account.allowed_tool_slugs` (`hostedAccount.allowedToolSlugs` in TypeScript), which lists the tools that run on it. Any other tool in that toolkit needs the user's own connection.

Hosted accounts cannot run arbitrary provider requests through proxy execution. Use supported tool actions. Direct execution outside a Session does not inherit its `premium_usage` policy.

See [Configuring Sessions](/docs/configuring-sessions) for general toolkit and tool filters and the [create Session API reference](/reference/api-reference/tool-router/postToolRouterSession) for the complete request schema.

## Build consumer-facing products [#build-consumer-facing-products]

Instant Tools separate three audiences. Keep their language separate:

- **Developer surfaces** (your dashboard, billing views, internal logs) can talk money: Balance, charge, per-call price.
- **Consumer surfaces** (anything your end users see) carry zero money words. No "balance", "charge", "price", or "premium" in end-user UI. Show the feature, not the meter: "Search the web", never "Premium search, $0.01 per call".
- **Agent-facing strings** (tool names, descriptions, and error messages your agent reads) stay purely functional: what the tool does, what it needs, what happened. No pricing or marketing language, so the agent picks a tool because it fits the task, not because of what it costs.
