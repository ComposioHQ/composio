An Instant Tool is a single tool inside a toolkit that a Session can run with zero setup: your end user connects nothing, and the call either runs on a Composio hosted account or is free. A hosted account is a provider account that Composio holds and runs the call on, on behalf of your users. The alternative is bring your own key (BYOK), where the call runs on your or your end user's own provider account and credentials.

Instant describes availability, not exclusivity. One tool, two ways to run it: the same Instant Tool runs on the hosted account out of the box, or on the user's own key when they want their own quota and terms, or need data-handling terms the hosted account does not cover, such as a zero data retention (ZDR) arrangement with the provider.

Paid Instant Tool calls on the hosted account are charged per call to your organization's Balance, the prepaid balance your organization holds for Instant Tool calls. Calls on the user's own key do not touch your Balance.

<Callout type="warn" title="Limited availability">
Instant Tools are enabled per organization during early access. Email [support@composio.dev](mailto:support@composio.dev) to get access and to confirm current per-tool prices. Access then needs a project setting that is not self-service yet: an organization admin turns on **Premium usage** in the project's settings. Session configuration cannot override a project where the setting is off.
</Callout>

## The Instant model

- **A toolkit is the catalog unit.** Toolkits group related tools (for example, `exa` groups Exa's search tools).
- **An Instant Tool is one tool inside a toolkit, not a kind of toolkit.** Eligibility is per tool: within a toolkit, only some tools may be Instant.
- **The same toolkit can mix both kinds.** Instant Tools and BYOK tools sit side by side in one toolkit.
- **The same tool can run both ways.** An Instant Tool runs on the hosted account with zero setup, or on the user's own key when they bring one. Tools that are not Instant always follow the normal connection flow with the user's own account.
- **"Instant Tools" the product is the collection** of every Instant Tool across all toolkits. There is no "instant app" and no "instant toolkit": nothing about a toolkit as a whole makes it Instant.

Each Instant Tool has its own per-call price. There are no tiers and no bundles: one call to a paid Instant Tool on the hosted account produces one charge against your Balance.

## Enable Instant Tools

Access is granted per organization by support. Once granted, enable Instant Tools per project:

1. Open your project in the dashboard.
2. Go to **Settings → General → Configuration**.
3. Turn on **Premium usage**. This toggle appears only after support grants your organization access.

Once the project setting is enabled, new Sessions can use eligible Instant Tools by default, even if `premium_usage` is omitted. Set `premium_usage=False` in Python or `premiumUsage: false` in TypeScript when creating a Session that must not incur charges.

## Find eligible tools

Instant coverage is per tool, not per toolkit. Neither the [toolkit listing API](/reference/api-reference/toolkits/getToolkits) nor the tools listing API returns Instant eligibility, hosted-account availability, or per-tool prices, and neither offers an Instant filter. Their `no_auth` and `composio_managed_auth_schemes` fields mean different things and should not be used as substitutes.

The discovery surface is Session search: `POST /api/v3/tool_router/session/{session_id}/search` (see the [tool router API reference](/reference/api-reference/tool-router)) returns `toolkit_connection_statuses[].hosted_account.allowed_tool_slugs` (`hostedAccount.allowedToolSlugs` in TypeScript), which lists the tools of that toolkit that run on the Composio hosted account. A tool not in that list either runs free without an account or follows the normal connection flow with the user's own account.

Session search is query-driven: its connection statuses cover the toolkits its results surface, not a complete catalog of eligible tools. During early access, confirm the complete supported set and current per-tool prices with [support@composio.dev](mailto:support@composio.dev) before allowing paid Instant Tools in a production Session.

## Create a Session

After your project is enabled, create a Session. Premium usage is the umbrella term for any paid usage across any tool, charged on top of the tool call; unpriced calls never produce it. `premium_usage` (`premiumUsage` in TypeScript) is the Session policy that decides which eligible tools may charge your Balance, and Instant Tools are one capability it controls. This example makes Exa available and permits charges for its eligible tools:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
    premium_usage={
        "toolkits": {"enable": ["exa"]},
        "return_premium_charge": True,
    },
)

```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from "@composio/core";

const composio = new Composio();
const session = await composio.create("user_123", {
  toolkits: ["exa"],
  premiumUsage: {
    toolkits: { enable: ["exa"] },
    returnPremiumCharge: true,
  },
});

```
</Tab>
</Tabs>

Top-level `toolkits` controls which tools the Session can discover and run. Omit it to make all toolkits discoverable. `premium_usage.toolkits` separately restricts which eligible tools can incur charges, and omitting it does not restrict charging: eligible tools remain available when the project and Session permit them. `return_premium_charge` defaults to `false` and only controls whether the actual charge appears in the immediate tool response. A toolkit with Instant Tools can still contain tools that need a connected account; hosted account coverage is tool-specific.

If your agent uses MCP, expose the same Session through `session.mcp` as described in [Using sessions via MCP](/docs/sessions-via-mcp). The charge policy applies to that Session in either path; your agent does not need a separate setting.

Within a Session, you can select an account explicitly with `account` in Python or `options.account` in TypeScript; an explicit connected-account choice wins and does not fall back to the hosted account on failure. The special value `connected_account_id="hosted_account"` exists only on the [direct execute endpoint](/reference/api-reference/tools/postToolsExecuteByToolSlug) (`POST /api/v3/tools/execute/{tool_slug}`), outside a Session: it routes the call to the hosted account and fails rather than falling back when the hosted account cannot serve that tool. Direct execution outside a Session does not inherit its `premium_usage` policy.

## Know which account runs the tool

An Instant Tool can run on either account: the hosted account, or the user's own key. The choice is per call, not per tool.

A hosted account is different from Composio-managed auth, where Composio supplies OAuth application credentials but your user still connects their own account. Composio-managed auth alone does not make a tool Instant.

Unless you select a connected account explicitly, available user or shared connections take priority over a hosted account. If the chosen tool is not supported by a hosted account, it follows the normal connection flow. Bring-your-own-key calls are billed by the provider to the key's owner; they do not touch your Balance and follow the provider's own data terms.

Session search tells you when a hosted account serves a toolkit. The toolkit's connection status includes `hosted_account.allowed_tool_slugs` (`hostedAccount.allowedToolSlugs` in TypeScript), which lists the tools that run on it. A tool not in that list either runs free without an account or needs the user's own connection.

Hosted accounts cannot run arbitrary provider requests through proxy execution. Use supported tool actions.

<Callout type="warn" title="Zero data retention is not enabled for Instant Tools">
Calls that run on Composio's hosted account are not covered by zero data retention (ZDR), an arrangement where the provider retains nothing from the call. If a workload requires ZDR, run the same tool on the user's own key instead, where retention follows the provider's own terms and can offer ZDR. Using your own key changes which account runs the call; it does not by itself guarantee zero data retention. Contractual ZDR requires its own arrangement with the provider, or Composio's Enterprise track.
</Callout>

## Control charges on a Session

`premium_usage` controls which eligible tools may charge your Balance. It does not enable a toolkit that top-level `toolkits` excludes, and it does not change a connected account you explicitly selected.

The toolkit filter and per-tool filter intersect. A `tools.exa` rule alone does not disable charges for other eligible toolkits. Use `premium_usage.toolkits` when you need a toolkit allowlist. Each filter accepts either `enable` or `disable`, not both.

The examples below use Python and REST field names. In TypeScript, use `premiumUsage` and `returnPremiumCharge`, and read the charge from `premiumCharge` on the tool result.

| Session value | Effect |
| --- | --- |
| Omitted or `{}` | Permits charges for eligible tools, subject to the project setting and normal Session filters. The charge is not returned in tool responses by default. |
| `false` | Disables charges for that Session. Your own connected-account routes remain available. |
| `{ "toolkits": { "enable": ["exa"] } }` | Permits charges only for listed toolkits. Use `disable` instead to exclude selected toolkits. |
| `{ "tools": { "exa": { "enable": ["EXA_SEARCH"] } } }` | Narrows charging to selected tools within a toolkit. |
| `{ "return_premium_charge": true }` | Requests the actual charge in an eligible Session tool response. On create, this changes charge visibility, not permission to spend. On update, it also re-enables charging on a Session set to `false`, like any other object. |

For example, keep Exa and Firecrawl available, but permit charges only for `EXA_SEARCH`:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa", "firecrawl"],
    premium_usage={
        "toolkits": {"enable": ["exa"]},
        "tools": {"exa": {"enable": ["EXA_SEARCH"]}},
    },
)

```
</Tab>
<Tab value="TypeScript">
```typescript
// @noErrors
const session = await composio.create("user_123", {
  toolkits: ["exa", "firecrawl"],
  premiumUsage: {
    toolkits: { enable: ["exa"] },
    tools: { exa: { enable: ["EXA_SEARCH"] } },
  },
});

```
</Tab>
</Tabs>

To stop charges on an existing Session, update its policy:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
<Tab value="Python">
```python
session.update(premium_usage=False)

```
</Tab>
<Tab value="TypeScript">

On patch, omitted `premium_usage` fields keep their existing values. Supplying any object after `false`, even one that only sets `return_premium_charge`, enables this Session policy again, provided the project allows it.

## Read the charge

Each paid Instant Tool call produces a premium usage charge: the amount deducted from your Balance for that call. With `premium_usage.return_premium_charge` enabled, `session.execute()` returns the charge in the typed `premium_charge` field on `ToolRouterSessionExecuteResponse`:

```python
charge = result.premium_charge
if charge is not None:
    print(charge["amount"], charge["currency"], charge["charged_by"])

```

The `PremiumCharge` type is exported from `composio.types` and includes `amount`, `currency`, and `charged_by`. In TypeScript, read `premiumCharge` from the tool result. A multi-tool execute returns one aggregate of the eligible successful calls. Python provider integrations and mixed local and remote multi-tool execution also preserve these charge details.

When the Balance is exhausted, paid calls fail with a `402` error: "Payment required - Wallet balance is exhausted; add credits to resume premium tool calls or connect your account".
