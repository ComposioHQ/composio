Connected accounts are authenticated connections between your users and toolkits. After users authenticate (see [Authenticating tools](/docs/tools-direct/authenticating-tools)), you can manage these accounts throughout their lifecycle.

Composio handles background token refresh for supported OAuth connections. You can inspect connection state, start a new authorization when needed, and enable, disable, revoke, or delete connections.

## List accounts

Retrieve all connected accounts with optional filters:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>

```python
accounts = composio.connected_accounts.list(
    user_ids=[user_id]

active_accounts = composio.connected_accounts.list(
    user_ids=[user_id],
    statuses=["ACTIVE"]
)
```

### Get account credentials

Connected-account responses describe the authentication state. Sensitive credential fields in `account.state.val` are [redacted by default](#credential-masking), for both Composio-managed and custom auth configs. This object is not a source of usable provider tokens for your own tools.

To call a provider API, use [Proxy Execute](/docs/extending-sessions/proxy-execute), which injects credentials server-side. For custom business logic, use [session extension tools](/docs/extending-sessions/custom-tools-and-toolkits). See [Token custody architecture](/docs/security/token-custody) for the boundaries between your application, Composio, and the provider.

## Refresh credentials

Composio's background token refresh uses the provider's refresh mechanism when the connection supports it. It does not require you to call an SDK refresh method on a schedule. Providers can still reject a grant after revocation, a policy change, or an OAuth app configuration change.

<Callout type="warn">
`composio.connected_accounts.refresh()` in Python and `composio.connectedAccounts.refresh()` in TypeScript are deprecated re-initiation methods. They are separate from background token refresh and no longer validate credentials. TypeScript ignores `validateCredentials` and logs a warning when you set it.
</Callout>

### Start a new authorization

When a user needs to reconnect, create a fresh [hosted Connect Link](/docs/tools-direct/authenticating-tools#hosted-authentication-connect-link) with `connected_accounts.link()` in Python or `connectedAccounts.link()` in TypeScript. Use the intended user ID and auth config, redirect the user to the returned URL, and wait for the connection to become `ACTIVE`.

Hosted links expire after 10 minutes. Generate a new link when the previous flow expires. Use the connected-account ID returned by the completed flow; do not assume reauthorization preserves the previous ID.

By default, `link()` refuses a second active connection for the same user and auth config. If you need to validate a replacement while keeping the original connection, pass `allow_multiple=True` in Python or `allowMultiple: true` in TypeScript. Verify the replacement's upstream identity and access, then update your application's account selection before removing the original.

To change permissions, [update the scope configuration](/docs/authentication/controlling-scopes#update-scopes-on-an-existing-config) before starting the new authorization. Reconnecting the same unchanged config does not add a missing permission or remove a permission it still requests.

### Diagnose authorization failures

A stored `ACTIVE` status means the connection flow completed and credentials were stored. It does not prove the provider accepts those credentials now. Check the provider status and error inside the tool or proxy response as well as the connection's status reason.

| Symptom | What to check |
| --- | --- |
| Authentication did not complete within 10 minutes | Start a fresh hosted link. This is an authorization-flow timeout, not evidence of a failed background refresh. |
| A previously working connection returns provider `401` | Confirm which connected-account ID the execution used. Inspect its status reason and use a safe read or profile action to check current provider access. |
| A connection returns `403` or insufficient scopes | Compare the tool's permissions with the scopes available to the OAuth app and granted during authorization. Repeated reconnects to the same config will not fix an unavailable scope. |
| Connections repeatedly expire after successful use | Check refresh permissions and provider app policy. Share the affected account IDs, execution IDs, timestamps, and redacted provider errors with support so the refresh history can be investigated. |

For custom OAuth, preserve permissions required for ongoing access, such as Microsoft's `offline_access` or Salesforce's `refresh_token`, when choosing tool-specific scopes. Changes to a toolkit's default scopes don't rewrite the scopes saved on an existing auth config. If an existing config omits a refresh permission, add it to the config's `scopes` and authorize a new connection.

Never send access tokens, refresh tokens, client secrets, or API keys when reporting an authorization failure.

## Enable and disable accounts

Change account status without deleting. Set to INACTIVE to pause access, or ACTIVE to restore. Useful for:
- Pausing access during subscription lapses
- Temporary disconnection

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
# Disable an account
disabled = composio.connected_accounts.disable(connected_account_id)
print(f"Account disabled status: {disabled.success}")

# Re-enable when needed
enabled = composio.connected_accounts.enable(connected_account_id)
print(f"Account enabled status: {enabled.success}")
```
  </Tab>
  <Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';
const composio = new Composio({ apiKey: 'your_api_key' });
const connectedAccountId = 'ca_123';
// ---cut---
// Disable an account
const disabled = await composio.connectedAccounts.disable(connectedAccountId);
console.log('Account disabled status:', disabled.success);

// Re-enable when needed
const enabled = await composio.connectedAccounts.enable(connectedAccountId);
console.log('Account enabled status:', enabled.success);
```
  </Tab>
</Tabs>

<Callout type="warn">
INACTIVE accounts cannot execute tools. Tool execution will fail until the status is changed.
</Callout>

## Revoke accounts

To revoke upstream tokens and mark a connection `REVOKED`, call `composio.connected_accounts.revoke(connected_account_id)` in Python or `await composio.connectedAccounts.revoke(connectedAccountId)` in TypeScript. Upstream token revocation is best effort. The call fails if the toolkit does not support programmatic revocation or the account is not in a revokable state.

## Complete deferred OAuth

If your project has an OAuth callback verifier configured, Composio redirects to your verifier with a single-use session URI before activating the connection. Verify the person's identity in your application, then redeem the URI with `composio.connected_accounts.complete_auth(user_id=user_id, session_uri=session_uri)` in Python or `await composio.connectedAccounts.completeAuth({ userId, sessionUri })` in TypeScript.

Composio checks project ownership and the connection's user ID before completing the token exchange. An expired or already redeemed URI returns a `404`.

## Credential masking

By default, sensitive fields in connected account responses are partially masked for security. This affects fields like `access_token`, `refresh_token`, `api_key`, `bearer_token`, `password`, and other secrets.

Instead of returning full values, the API returns the first 4 characters followed by `...`:

```json
{
  "access_token": "gho_...",
  "refresh_token": "ghr_...",
  "api_key": "sk-l..."
}
```

Values shorter than 4 characters are replaced with `REDACTED`.

This applies to the Get Connected Account and List Connected Accounts endpoints for both Composio-managed and custom auth configs. The API redacts these fields before returning the response to your application.

If your use case requires calling a provider API directly, use [Proxy execute](/docs/extending-sessions/proxy-execute). Composio injects the connected account's credentials server-side.

## Multiple accounts

Users can connect multiple accounts for the same toolkit (e.g., personal and work Gmail).

<Callout type="warn">
**For Composio-managed OAuth, prefer `link()`.** The `initiate()` examples below will stop working for Composio-managed OAuth auth configs starting **2026-05-08** (new orgs) / **2026-07-03** (all orgs). `link()` provides hosted authentication and is unaffected by the rollout. Like `initiate()`, it refuses to create a second active connection for the same user and auth config unless you pass `allow_multiple=True` (Python) or `allowMultiple: true` (TypeScript). See [Connect Link authentication](/docs/tools-direct/authenticating-tools#hosted-authentication-connect-link), the [migration guide](/docs/auth-configuration/migrating-initiate-to-link), or the [changelog entry](/docs/changelog/2026/04/24).

The `initiate()` examples remain accurate for **custom auth configs** (your own OAuth app) and **non-OAuth schemes** (API key, bearer, basic) — those are unaffected.
</Callout>

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
# First account
try:
    first_account = composio.connected_accounts.initiate(
        user_id=user_id,
        auth_config_id=auth_config_id
    )
    print(f"First account redirect URL: {first_account.redirect_url}")
    connected_first_account = first_account.wait_for_connection()
    print(f"First account status: {connected_first_account.status}")
except Exception as e:
    print(f"Error initiating first account: {e}")

# Second account - must explicitly allow multiple
try:
    second_account = composio.connected_accounts.initiate(
        user_id=user_id,
        auth_config_id=auth_config_id,
        allow_multiple=True  # Required for additional accounts
    )
    print(f"Second account redirect URL: {second_account.redirect_url}")
    connected_second_account = second_account.wait_for_connection()
    print(f"Second account status: {connected_second_account.status}")
except Exception as e:
    print(f"Error initiating second account: {e}")
```
  </Tab>
  <Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';
const composio = new Composio({ apiKey: 'your_api_key' });
const userId = 'user_123';
const authConfigId = 'ac_123';
// ---cut---
// First account
try {
  const firstAccount = await composio.connectedAccounts.initiate(
    userId,
    authConfigId
  );
  console.log('First account redirect URL:', firstAccount.redirectUrl);
  const connectedFirstAccount = await firstAccount.waitForConnection();
  console.log('First account status:', connectedFirstAccount.status);
} catch (error) {
  console.error('Error initiating first account:', error);
}

// Second account - must explicitly allow multiple
try {
  const secondAccount = await composio.connectedAccounts.initiate(
    userId,
    authConfigId,
    {
      allowMultiple: true  // Required for additional accounts
    }
  );
  console.log('Second account redirect URL:', secondAccount.redirectUrl);
  const connectedSecondAccount = await secondAccount.waitForConnection();
  console.log('Second account status:', connectedSecondAccount.status);
} catch (error) {
  console.error('Error initiating second account:', error);
}
```

</Tabs>

### Execute with a specific account

When you have multiple accounts, specify which one to use with `connected_account_id`:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
# Execute tool with a specific connected account
result = composio.tools.execute(
    "GMAIL_GET_PROFILE",
    user_id=user_id,
    connected_account_id=connected_account_id,  # Specify which account to use
    version="20251111_00",
    arguments={}
)
print(f"Tool executed: {result}")
```
  </Tab>
  <Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';
const composio = new Composio({ apiKey: 'your_api_key' });
const userId = 'user_123';
const connectedAccountId = 'ca_123';
// ---cut---
// Execute tool with a specific connected account
const result = await composio.tools.execute('GMAIL_GET_PROFILE', {
  userId: userId,
  connectedAccountId: connectedAccountId,  // Specify which account to use
  version: '20251111_00',
  arguments: {}
});
console.log('Tool executed:', result);
```
