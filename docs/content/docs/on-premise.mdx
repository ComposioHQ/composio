Composio supports on-premise deployments using [Helm charts](https://helm.sh/) on Kubernetes.

<Callout type="info">
On-premise deployments are available on the Composio Enterprise plan. Contact sales at [composio.dev/contact](https://composio.dev/contact) to get access.
</Callout>

## Architecture

| Service | Port | Description |
|---------|------|-------------|
| **Apollo** | 9900 | API server — OAuth, business logic, database operations |
| **Thermos** | 8180 | Workflow execution and tools management |
| **Mercury** | 8080 | Tool execution runtime (Knative serverless) |
| **MCP** | 3000 | Management portal |
| **Redis** | 6379 | Caching |

Mercury connects to Apollo for backend operations. Thermos connects to both Apollo and Mercury for workflow execution. All services share a PostgreSQL database (via external secret) and Redis for caching.

## Prerequisites

1. Kubernetes cluster (11+ CPU cores, 28+ GiB memory)
2. [Helm](https://helm.sh/) v3
3. PostgreSQL database (v17+ recommended)
4. [Knative Serving](https://knative.dev/) installed on the cluster (auto-installed by the chart via a pre-install hook)
5. Access to the [Composio enterprise portal](https://enterprise.composio.io/composio-rodent)

## Kubernetes Secrets

Create the PostgreSQL connection secret:

```bash
kubectl create secret generic external-postgres-secret \
  --from-literal=url="postgresql://<USER>:<PASSWORD>@<HOST>:5432/composiodb?sslmode=require" \
  -n <NAMESPACE>
```

All other secrets (admin token, encryption keys, API keys, Redis URL) are auto-generated by the chart on first install and persisted across upgrades. To set them explicitly, use the `secrets` section in `values.yaml`:

```yaml
secrets:
  adminToken: ""              # Auto-generated 32-char token if empty
  encryptionKey: ""           # Auto-generated 32-char key if empty
  temporalEncryptionKey: ""   # Auto-generated 32-char key if empty
  bootstrapApiKey: ""         # Auto-generated 32-char key if empty
```

<Callout type="warn">
Store your `encryptionKey` securely. Losing it makes existing encrypted data unrecoverable.
</Callout>

To retrieve auto-generated secrets after install:

```bash
kubectl get secret composio-composio-secrets -o jsonpath="{.data.APOLLO_ADMIN_TOKEN}" | base64 -d
kubectl get secret composio-composio-secrets -o jsonpath="{.data.ENCRYPTION_KEY}" | base64 -d
kubectl get secret composio-composio-secrets -o jsonpath="{.data.COMPOSIO_API_KEY}" | base64 -d
```

## Installation

### Option 1: Helm repository

```bash
helm repo add composio https://composiohq.github.io/helm-charts
helm repo update

helm install composio composio/composio \
  -f values.yaml \
  -n <NAMESPACE> \
  --create-namespace \
  --timeout 15m
```

### Option 2: Replicated OCI registry (enterprise)

```bash
helm upgrade --install composio \
  oci://registry.composio.io/composio-rodent/unstable/composio \
  --version 0.1.40 \
  --values ./values.yaml \
  -n <NAMESPACE> \
  --timeout 15m
```

## Configuration Reference

All configuration is set through `values.yaml`. Below is the complete reference organized by section.

### Global

```yaml
global:
  environment: production       # "development" or "production"
  domain: composio.example.com  # Domain used for Knative serving and ingress
  imagePullSecrets:
    - name: ecr-secret          # Required for pulling images from private registries
```

### External PostgreSQL

The chart expects a PostgreSQL connection string via a Kubernetes secret. This is the recommended setup for production.

```yaml
externalPostgreSQL:
  enabled: true
  urlSecret:
    name: "external-postgres-secret"   # K8s secret name
    key: "url"                         # Key containing the connection string
```

All services (Apollo, MCP, Thermos, DB init) read `DATABASE_URL` from this secret.

To use the bundled PostgreSQL instead (development only):

```yaml
postgresql:
  enabled: true
  auth:
    postgresPassword: "postgres123"
    username: "composio"
    password: "composio123"
    database: "composio"
  primary:
    persistence:
      enabled: true
      size: 8Gi
    resources:
      requests: { memory: "4Gi", cpu: "2" }
      limits: { memory: "4Gi", cpu: "2" }
```

### Redis

Bundled Redis is enabled by default via the Bitnami subchart.

```yaml
redis:
  auth:
    enabled: true
    password: "redis123"        # Change in production
  master:
    persistence:
      enabled: true
      size: 8Gi
    resources:
      requests: { memory: "4Gi", cpu: "2" }
      limits: { memory: "4Gi", cpu: "2" }
  replica:
    persistence:
      enabled: true
      size: 8Gi
    resources:
      requests: { memory: "4Gi", cpu: "2" }
      limits: { memory: "4Gi", cpu: "2" }
```

The chart auto-generates the `REDIS_URL` secret in the format `redis://:<password>@<release>-redis-master:6379` and passes it to Apollo.

To use an external Redis instead:

```yaml
redis:
  enabled: false

externalRedis:
  enabled: true
  secretRef: "composio-composio-secrets"
  key: "REDIS_URL"
```

### Apollo (API Server)

Main API service handling OAuth, business logic, and storage.

```yaml
apollo:
  replicaCount: 1
  image:
    repository: composio/apollo
    tag: "v1.7"
    pullPolicy: Always
  service:
    type: NodePort              # NodePort, ClusterIP, or LoadBalancer
    port: 9900
    nodePort: 30900             # Only used with type: NodePort
  baseUrl: "http://composio-apollo:9900"
  resources:
    requests: { memory: "4Gi", cpu: "2" }
    limits: { memory: "4Gi", cpu: "2" }
  database:
    urlSecret:
      name: "external-postgres-secret"
      key: "url"
```

The following environment variables are set automatically by the template:
- `SELF_HOSTED=true`
- `THERMOS_URL` — points to the Thermos service
- `MCP_BASE_URL` — points to the MCP service
- `REDIS_URL`, `ENCRYPTION_KEY`, `APOLLO_ADMIN_TOKEN` — from the auto-generated secrets

#### SMTP (for magic link login)

```yaml
apollo:
  smtp:
    enabled: true
    smtpAuthorEmail: "noreply@your-company.com"
```

Add the SMTP connection string as a secret:

```bash
kubectl create secret generic composio-smtp-secret \
  --from-literal=SMTP_CONNECTION_STRING="smtp://<user>:<pass>@<host>:<port>" \
  -n <NAMESPACE>
```

#### Object Storage

Only needed for file-related toolkit operations.

<Tabs groupId="storage-provider">
<Tab value="S3 / GCS">
```yaml
apollo:
  objectStorage:
    backend: "s3"
    s3:
      bucketName: "composio-storage"
      region: "us-east-1"
```

For AWS, use [IRSA](https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html). For GCP, use Workload Identity with HMAC credentials.
</Tab>
<Tab value="Azure Blob Storage">
```yaml
apollo:
  objectStorage:
    backend: "azure_blob_storage"
    azure:
      tempContainerName: "composio-temp"
      permanentContainerName: "composio-permanent"
```

```bash
kubectl create secret generic composio-azure-secret \
  --from-literal=AZURE_CONNECTION_STRING="<connection-string>" \
  -n <NAMESPACE>
```
</Tab>
</Tabs>

### Thermos (Workflow Engine)

Executes workflows, manages tools, and communicates with Mercury for tool execution via HTTP.

```yaml
thermos:
  replicaCount: 1
  image:
    repository: composio/thermos
    tag: "endpoint"
    pullPolicy: Always
  service:
    type: ClusterIP
    port: 8180
  baseUrl: "http://composio-thermos:8180"
  resources:
    requests: { memory: "4Gi", cpu: "2" }
    limits: { memory: "4Gi", cpu: "2" }
```

Thermos automatically connects to:
- Apollo via `APOLLO_ENDPOINT`
- Mercury via `LAMBDA_USE_HTTP_ENDPOINT` (Knative internal URL)
- Temporal at `temporal-stack-frontend:7233`
- PostgreSQL via `DATABASE_URL` and `THERMOS_DATABASE_URL` (from the external-postgres-secret)

#### Autoscaling

```yaml
thermos:
  autoscaling:
    enabled: true
    minReplicas: 2
    maxReplicas: 5
```

### MCP (Management Portal)

Web-based management interface.

```yaml
mcp:
  replicaCount: 1
  image:
    repository: composio/mcp-server
    tag: "v1.7"
    pullPolicy: Always
  service:
    type: ClusterIP
    port: 3000
  baseUrl: "http://composio-mcp:3000"
  resources:
    requests: { memory: "4Gi", cpu: "2" }
    limits: { memory: "4Gi", cpu: "2" }
  database:
    urlSecret:
      name: "external-postgres-secret"
      key: "url"
```

MCP receives `AUTH_SECRET`, `COMPOSIO_API_KEY`, and `DATABASE_URL` automatically from the chart secrets.

### Mercury (Tool Execution Runtime)

Runs as a Knative service for serverless autoscaling. Mercury executes the actual tools and connects back to Apollo for context.

```yaml
mercury:
  enabled: true
  image:
    repository: composio/mercury
    tag: "latest"
    pullPolicy: Always
  service:
    type: ClusterIP
    port: 8080
  resources:
    requests: { memory: "8Gi", cpu: "4" }
    limits: { memory: "16Gi", cpu: "8" }
  containerConcurrency: 0      # 0 = unlimited concurrent requests per container
  timeoutSeconds: 300           # Max request duration in seconds
  autoscaling:
    minScale: 1                 # Minimum running instances
    maxScale: 10                # Maximum instances
    target: 80                  # CPU utilization target (%)
  knative:
    minReplicas: 3
    replicas: 10
    maxReplicas: 20
```

#### Mercury Ingress

```yaml
mercury:
  ingress:
    enabled: true
    className: nginx
    host: mercury.composio.your-company.com
    tls: []
```

### Database Init Job

Runs as a Helm pre-install/pre-upgrade hook to run database migrations.

```yaml
dbInit:
  image:
    repository: composio/init
    tag: "v1.6"
    pullPolicy: Always
  adminEmail: "admin@your-company.com"   # Initial admin account email
  database:
    urlSecret:
      name: "external-postgres-secret"
      key: "url"
```

### AWS Configuration

Used by Mercury and Thermos for S3-compatible object storage (backed by the internal MinIO instance).

```yaml
aws:
  region: us-east-1
  s3:
    lambdaBucketName: "tools"           # Bucket for tool artifacts
  lambda:
    functionName: "mercury"
    image: "composio/mercury:latest"
```

### Knative

The chart installs Knative Serving v1.15.0 with Kourier networking automatically via a pre-install hook. The Knative serving domain is set from `global.domain`.

### Observability (OpenTelemetry)

```yaml
otel:
  enabled: true
  exporter:
    otlp:
      endpoint: "your-otel-collector:4317"
  traces:
    enabled: true
  metrics:
    enabled: true
    exportInterval: 60000

    enabled: true
```

### Security Context

All pods run with restricted security by default (GKE Autopilot compatible):

```yaml
global:
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    allowPrivilegeEscalation: false
    capabilities:
      drop: [ALL]
    seccompProfile:
      type: RuntimeDefault
  podSecurityContext:
    runAsNonRoot: true
    runAsUser: 1000
    fsGroup: 2000
```

Each service also accepts `podSecurityContext` and `securityContext` overrides individually.

## Upgrading

Check the [enterprise portal](https://enterprise.composio.io/composio-rodent/update) for the latest chart version.

```bash
helm upgrade composio composio/composio \
  -f values.yaml \
  -n <NAMESPACE> \
  --timeout 15m
```

<Callout type="warn">
**Upgrading from chart version 1.47 or below:** The default `redis.auth.password` changed from `"redis123"` to `""`. If using bundled Redis, set `redis.auth.password` explicitly or delete the Redis secret and restart the pod.
</Callout>

## Troubleshooting

### Check pod status

```bash
kubectl get pods -n <NAMESPACE>
```

All pods should be `Running` or `Completed`. DB-init jobs show `Completed` after migration.

### View logs

```bash
kubectl logs -f deployment/composio-apollo -n <NAMESPACE>
kubectl logs -f deployment/composio-thermos -n <NAMESPACE>
kubectl logs -f deployment/composio-mercury -n <NAMESPACE>
kubectl logs -f deployment/composio-mcp -n <NAMESPACE>
```

### Port forward for debugging

```bash
kubectl port-forward svc/composio-apollo 9900:9900 -n <NAMESPACE>
curl http://localhost:9900/health

kubectl port-forward svc/composio-mcp 3000:3000 -n <NAMESPACE>
```

### Common issues

| Issue | Fix |
|-------|-----|
| DB-init pods in CrashLoopBackOff | Verify `url` in your `external-postgres-secret` and database user permissions |
| Mercury pods failing | Check `securityContext` compatibility with your cluster's pod security policies |
| Thermos can't reach Mercury | Verify Knative serving is running: `kubectl get ksvc -n composio` |
| Redis errors after upgrade | See upgrade note above about password change in chart v1.47 |
