From **13 November 2026**, the No Auth and shared-access routes for the toolkits below are being retired. This change supports growing usage while maintaining performance and quality for web search, browsing and AI tools via Composio.

[Instant](/docs/instant-tools) replaces them. It runs supported tools on Composio's provider accounts and charges your organization's Composio balance, so your users don't need their own provider credentials for those tools.

## Choose a replacement

All changes in this table take effect on **13 November 2026** for the developer platform.

| Toolkit | Change | Migration path |
| --- | --- | --- |
| Gemini (`gemini`) | No Auth/shared-key access ends; the toolkit remains | Use supported Gemini Instant tools or credentials connected by your users. |
| Yelp (`yelp`) | No Auth/shared-key access ends; the toolkit remains | Use eligible Yelp Instant tools or supported credentials connected by your users. |
| Browser Tool (`browser_tool`) | Legacy toolkit retired | Replace with supported Browser Use (`browser_use`) Instant tools. |
| Composio Search (`composio_search`) | Legacy toolkit retired | Choose Exa (`exa`), Tavily (`tavily`), or SerpAPI (`serpapi`) tools for your use case. |
| Text to PDF (`text_to_pdf`) | Toolkit removed | PDF.co (`pdf_co`) Instant supports URL-based conversion. |
| WeatherMap (`weathermap`) | Toolkit removed | Use supported AccuWeather (`accu_weather`) Instant tools and update requests and response handling. |
| SeatGeek (`seat_geek`) | No Auth/shared-key access ends | SeatGeek will be available through Composio Instant. |

These alternatives aren't interchangeable APIs, and Instant support is per tool. [Check each tool's support, rate, and input schema](/docs/instant-tools#find-supported-tools-and-rates) before replacing it.

## Update your Session

First, [enable Instant and check your organization's balance](/docs/instant-tools#enable-instant). If your agent already uses Sessions, keep your agent integration and change only the affected toolkit references.

For example, replace the legacy `composio_search` toolkit with `exa`:

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
session = composio.sessions.create(
    user_id="user_123",
    toolkits=["exa"],
)
tools = session.tools()
```
</Tab>
<Tab value="TypeScript">
```typescript
import { Composio } from "@composio/core";

const composio = new Composio();
const session = await composio.create("user_123", {
  toolkits: ["exa"],
});
const tools = await session.tools();
```
</Tab>
<Tab value="API">
```bash
SESSION_ID=$(curl -s -X POST https://backend.composio.dev/api/v3.1/tool_router/session \
  -H "x-api-key: $COMPOSIO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"user_123","toolkits":{"enable":["exa"]}}' \
  | jq -r '.session_id')

curl -X GET https://backend.composio.dev/api/v3.1/tool_router/session/$SESSION_ID/tools \
  -H "x-api-key: $COMPOSIO_API_KEY"
```
</Tab>
</Tabs>

Pass `tools` to your existing agent as usual, using your framework's [provider adapter](/docs/providers). Keep your other required toolkits in the `toolkits` list.

You don't need to add an `instant` setting; Sessions permit eligible Instant usage by default. If your Session sets `instant=false`, restricts Instant to other toolkits, or selects a provider account explicitly, update that policy. See [Control Instant usage](/docs/instant-tools#control-instant-usage) and [Know which account runs the tool](/docs/instant-tools#know-which-account-runs-the-tool).

Enabling Instant doesn't rewrite tool slugs, arguments, or response handling. Update or recreate existing Sessions that still reference retired toolkits, and update saved Session configurations so future Sessions use the replacements.

## If you call tools directly

`composio.tools.execute()` is a different execution path from Sessions. A Session's `instant` policy doesn't configure direct-tool calls.

To keep direct execution, replace retired tool references and [select the Instant account explicitly](/docs/instant-tools#use-instant-with-direct-tool-execution). An older toolkit version isn't a way to preserve retired shared access.

Alternatively, follow [Migrate from Direct Tools to Sessions](/docs/migration-guide/direct-to-sessions). This is a separate migration; agents already using Sessions don't need it.

## Verify before the cutoff

1. Check [Instant pricing](https://composio.dev/pricing) and the published rate for each replacement tool.
2. Replace affected toolkit and tool references, including saved configurations. Check request and response differences for each replacement.
3. Test your agent or direct execution path, then [check the execution logs](/docs/instant-tools#balance-usage-and-troubleshooting) for the credential source and charge.
4. Check existing Sessions and pinned direct-tool versions. A successful replacement call doesn't prove every old workflow has migrated.

After the cutoff, affected legacy executions will stop working. If you need help mapping a tool or adapting a workflow, contact [support@composio.dev](mailto:support@composio.dev).

## Optional Session setup helper

[Download the Python helper](/assets/migrations/migrate_no_auth_to_instant.py) to preview and create a replacement Session with explicit toolkit and tool allowlists. It requires Python 3.10 or later and uses only the standard library. It is for Sessions only.

Save the file locally, inspect it, then preview a request:

```bash
python3 migrate_no_auth_to_instant.py --user-id user_123 --tool exa:EXA_SEARCH
```

Use your existing application user ID and repeat `--tool toolkit:TOOL_SLUG` for each required tool. The preview makes no network requests. The helper doesn't guess equivalents for retired tools or adapt their arguments and responses.

After enabling Instant for the intended project, set `COMPOSIO_API_KEY` for that project. Review the selected tools and their published rates, then create the replacement Session:

```bash
python3 migrate_no_auth_to_instant.py --user-id user_123 --tool exa:EXA_SEARCH --apply
```

`--apply` checks each tool's current identity, Instant support and published rate, then creates one Session. It doesn't run provider tools, edit existing Sessions, change project settings, or rewrite your application. Use the returned Session ID in your application and test the workflow separately.

If creation times out or returns an ambiguous server error, check your project before trying again. The helper never retries automatically.
