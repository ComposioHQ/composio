Composio is retiring v1 webhook triggers. On `{{sunset_date}}`, v1 trigger instances stop receiving events. To keep events flowing, recreate each affected trigger on v2 before then.

v2 webhook triggers verify the provider's signature on every incoming event, so nobody else can send spoofed events to your triggers. See [Custom OAuth webhooks](/docs/setting-up-triggers/custom-oauth-webhooks) for how this works.

## Who needs to migrate

You need to migrate if you have webhook triggers on any of these toolkits:

| Toolkit | What to do |
|---|---|
| GitHub | Recreate with the **same slug** |
| Outlook | Recreate with the **same slug**. Rename `OUTLOOK_OUTLOOK_*` slugs to `OUTLOOK_*` |
| Slack, Slackbot | Switch to a **new slug** |
| Jira | Switch to a **new slug** |
| Linear | Switch to a **new slug** |
| Trello | Switch to a **new slug** |
| Google Calendar, Google Super | Switch to a **new slug** |

Polling triggers aren't affected, and neither are webhook triggers on other toolkits. For the exact replacements, see [Old and new trigger slugs](#old-and-new-trigger-slugs).

If you use Composio-managed OAuth, the v2 webhook endpoint is already set up for you. If you use your own OAuth app, set up its [webhook endpoint](/docs/setting-up-triggers/custom-oauth-webhooks) before you create the v2 triggers.

### 1. List your triggers

Find the trigger instances that use a v1 slug from the [slug table](#old-and-new-trigger-slugs). Include disabled instances so you don't miss any. Note each instance's `id`, `trigger_name`, `connected_account_id`, and `trigger_config`.

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
  <Tab value="Python">
```python
from composio import Composio

composio = Composio()

# Add every v1 slug from the table below that you use.
v1_slugs = ["GITHUB_COMMIT_EVENT", "SLACK_RECEIVE_MESSAGE", "JIRA_NEW_ISSUE_TRIGGER"]

cursor = None
while True:
    page = composio.triggers.list_active(
        trigger_names=v1_slugs,
        show_disabled=True,
        cursor=cursor,
    )
    for trigger in page.items:
        print(trigger.id, trigger.trigger_name, trigger.connected_account_id, trigger.trigger_config)
    if not page.next_cursor:
        break
    cursor = page.next_cursor
```

### 2. Create the v2 triggers by slug

For each v1 trigger, create its replacement by naming the v2 slug from the [slug table](#old-and-new-trigger-slugs). Pass the same connected account. Trigger configs can differ between the old and new slug, so [inspect the new trigger type](/docs/setting-up-triggers/creating-triggers#inspect-the-trigger-type) and pass the config it asks for.

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
  <Tab value="Python">
```python
from composio import Composio

composio = Composio()

# Replaces a v1 SLACK_RECEIVE_MESSAGE trigger on the same connected account.
# The SDK overload omits the supported user_id + connected_account_id combination.
trigger = composio.triggers.create(  # type: ignore[call-overload]
    slug="SLACK_CHANNEL_MESSAGE_RECEIVED",
    user_id="user-id-123435",
    connected_account_id="ca_def456",
    trigger_config={"channel_id": "C0123456789"},
)
print(f"v2 trigger created: {trigger.trigger_id}")
```

#### GitHub and Outlook: delete the v1 trigger first

If the v2 slug is the same as the v1 slug, delete the v1 instance before you create the new one. Creating a trigger with the same slug, connected account, and config returns the existing v1 instance instead of creating a v2 one. Events that happen between the delete and the create aren't delivered, so run the two calls back to back.

Recreating a trigger that's already on v2 is harmless. If you can't tell which of your GitHub and Outlook triggers are on v1, recreate all of them.

### 3. Update your event handler

The event envelope doesn't change: v2 events arrive at the same [subscription or webhook URL](/docs/setting-up-triggers/subscribing-to-events) in the same format. Some details inside it do change, so update your handler where it relies on them:

- **Trigger ID.** Each v2 instance has a new ID. Update any stored trigger IDs or `trigger_id` filters.
- **Trigger slug.** For toolkits that switch slugs, `metadata.trigger_slug` carries the new slug. Route on the new slug, or on both slugs while you migrate.
- **Payload.** A new slug can have a different `data` schema from the old one. Check the trigger type's payload schema and update your parsing.

### 4. Confirm an event arrives

Cause a matching event in the provider, such as posting a Slack message or pushing a commit. Check that your handler receives it with the v2 trigger's ID and slug. If nothing arrives, follow [Troubleshooting triggers](/docs/setting-up-triggers/troubleshooting).

### 5. Delete the v1 triggers

Once v2 events are arriving, delete the v1 instance so your handler doesn't get the same event twice.

## Why create by slug

Create each v2 trigger by naming its v2 slug. Don't loop over the list from step 1 and recreate each `trigger_name` it returns:

- **The list returns v1 slugs.** Creating a deprecated slug such as `SLACK_RECEIVE_MESSAGE` creates another v1 trigger.
- **Creating returns an existing match.** If a trigger with the same slug, connected account, and config exists, you get that instance back instead of a new one.

## Old and new trigger slugs

### GitHub

These slugs stay the same. Recreate each instance as described in [GitHub and Outlook](#github-and-outlook-delete-the-v1-trigger-first).

| v1 slug | v2 slug |
|---|---|
| `GITHUB_COMMIT_EVENT` | `GITHUB_COMMIT_EVENT` |
| `GITHUB_ISSUE_ADDED_EVENT` | `GITHUB_ISSUE_ADDED_EVENT` |
| `GITHUB_LABEL_ADDED_EVENT` | `GITHUB_LABEL_ADDED_EVENT` |
| `GITHUB_PULL_REQUEST_EVENT` | `GITHUB_PULL_REQUEST_EVENT` |
| `GITHUB_STAR_ADDED_EVENT` | `GITHUB_STAR_ADDED_EVENT` |

### Outlook

| v1 slug | v2 slug |
|---|---|
| `OUTLOOK_OUTLOOK_MESSAGE_TRIGGER` or `OUTLOOK_MESSAGE_TRIGGER` | `OUTLOOK_MESSAGE_TRIGGER` |
| `OUTLOOK_OUTLOOK_SENT_MESSAGE_TRIGGER` or `OUTLOOK_SENT_MESSAGE_TRIGGER` | `OUTLOOK_SENT_MESSAGE_TRIGGER` |
| `OUTLOOK_OUTLOOK_EVENT_TRIGGER` or `OUTLOOK_EVENT_TRIGGER` | `OUTLOOK_EVENT_TRIGGER` |
| `OUTLOOK_OUTLOOK_EVENT_CHANGE_TRIGGER` or `OUTLOOK_EVENT_CHANGE_TRIGGER` | `OUTLOOK_EVENT_CHANGE_TRIGGER` |
| `OUTLOOK_OUTLOOK_CONTACT_TRIGGER` or `OUTLOOK_CONTACT_TRIGGER` | `OUTLOOK_CONTACT_TRIGGER` |

### Slack and Slackbot

Slackbot uses the same mapping with a `SLACKBOT_` prefix. For example, `SLACKBOT_RECEIVE_MESSAGE` becomes `SLACKBOT_CHANNEL_MESSAGE_RECEIVED`. Several v1 message triggers merge into `SLACK_CHANNEL_MESSAGE_RECEIVED`. Set its config to receive the same messages.

| v1 slug | v2 slug | v2 config |
|---|---|---|
| `SLACK_RECEIVE_MESSAGE` | `SLACK_CHANNEL_MESSAGE_RECEIVED` | |
| `SLACK_RECEIVE_BOT_MESSAGE` | `SLACK_CHANNEL_MESSAGE_RECEIVED` | `is_bot_message: true` |
| `SLACK_RECEIVE_GROUP_MESSAGE` | `SLACK_CHANNEL_MESSAGE_RECEIVED` | `channel_type: "group"` |
| `SLACK_RECEIVE_MPIM_MESSAGE` | `SLACK_CHANNEL_MESSAGE_RECEIVED` | `channel_type: "mpim"` |
| `SLACK_RECEIVE_THREAD_REPLY` | `SLACK_CHANNEL_MESSAGE_RECEIVED` | `is_thread_reply: true` |
| `SLACK_RECEIVE_DIRECT_MESSAGE` | `SLACK_DIRECT_MESSAGE_RECEIVED` | |
| `SLACK_REACTION_ADDED` | `SLACK_MESSAGE_REACTION_ADDED` | |
| `SLACK_REACTION_REMOVED` | `SLACK_MESSAGE_REACTION_REMOVED` | |
| `SLACK_CHANNEL_CREATED` | No v2 replacement | |

### Jira

The v2 Jira triggers filter by project ID, not project key. Check the new config before you create them.

| v1 slug | v2 slug |
|---|---|
| `JIRA_NEW_ISSUE_TRIGGER` | `JIRA_ISSUE_CREATED` |
| `JIRA_UPDATED_ISSUE_TRIGGER` | `JIRA_ISSUE_UPDATED` |
| `JIRA_NEW_PROJECT_TRIGGER` | No v2 replacement. Jira doesn't send project-created webhooks to OAuth apps, so this trigger doesn't receive events. Delete it. |

### Linear

v2 Linear webhook triggers cover public teams. For private teams, use the polling triggers.

| v1 slug | v2 slug (public teams) | Polling slug (private teams) |
|---|---|---|
| `LINEAR_ISSUE_CREATED_TRIGGER` | `LINEAR_PUBLIC_TEAM_ISSUE_CREATED` | `LINEAR_PRIVATE_TEAM_ISSUE_CREATED` |
| `LINEAR_ISSUE_UPDATED_TRIGGER` | `LINEAR_PUBLIC_TEAM_ISSUE_PROPERTIES_UPDATED` | `LINEAR_PRIVATE_TEAM_ISSUE_PROPERTIES_UPDATED` |
| `LINEAR_COMMENT_EVENT_TRIGGER` | `LINEAR_PUBLIC_TEAM_COMMENT_CREATED` | `LINEAR_PRIVATE_TEAM_COMMENT_CREATED` |

### Trello

| v1 slug | v2 slug |
|---|---|
| `TRELLO_NEW_CARD_TRIGGER` | `TRELLO_CARD_CREATED` |
| `TRELLO_NEW_BOARD_TRIGGER` | `TRELLO_BOARD_ADDED_TO_WORKSPACE` |
| `TRELLO_UPDATED_CARD_TRIGGER` | `TRELLO_CARD_UPDATED`. It watches the whole board, so filter on the card ID in your handler. |
| `TRELLO_ARCHIVED_CARD_TRIGGER` | `TRELLO_CARD_UPDATED`. Archived cards arrive with `card.closed` set to `true`. |
| `TRELLO_NEW_ACTIVITY_TRIGGER` | No v2 replacement. Trello doesn't send the event this trigger matches, so it doesn't receive events. Delete it. |

### Google Calendar and Google Super

| v1 slug | v2 slug |
|---|---|
| `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_CHANGE_TRIGGER` | `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_SYNC_TRIGGER` |
| `GOOGLESUPER_GOOGLE_CALENDAR_EVENT_CHANGE_TRIGGER` | `GOOGLESUPER_GOOGLE_CALENDAR_EVENT_SYNC_TRIGGER` |

If you only need one kind of change, Google Calendar also has `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_CREATED_TRIGGER`, `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_UPDATED_TRIGGER`, and `GOOGLECALENDAR_EVENT_CANCELED_DELETED_TRIGGER`. The Google Super triggers receive events by polling.
