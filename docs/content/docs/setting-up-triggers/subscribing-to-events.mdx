Once a trigger is active, its events come to you. There are two ways to receive them, and both deliver the same payload:

- **Locally**, with an SDK subscription (`subscribe()`). No public URL, no signing. Use this while developing.
- **In production**, at one webhook URL you register per project. Composio `POST`s every event there.

## Receive events locally

`subscribe()` streams events straight to your process over a WebSocket. No webhook URL, no tunnel.

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
from composio import Composio

composio = Composio()

subscription = composio.triggers.subscribe()

@subscription.handle(trigger_id="your_trigger_id")
def handle_event(data):
    print(f"Event received: {data}")

subscription.wait_forever()
```
  </Tab>
  <Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';

const composio = new Composio();

await composio.triggers.subscribe(
  data => {
    console.log('Event received:', data);
  },
  { triggerId: 'your_trigger_id' }
);
```
  </Tab>
</Tabs>

You can filter the stream by `triggerId`, `triggerSlug`, `connectedAccountId`, `toolkits`, or `userId`. Pass no filters to receive every trigger event in the project.

## Receive events in production

Register your webhook URL once per project. Composio then `POST`s every trigger event to it. Set it from the SDK:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
from composio import Composio

composio = Composio()

subscription = composio.triggers.set_webhook_subscription(
    webhook_url="https://your-app.com/webhooks/composio",
)
print(f"Delivering events to {subscription['webhook_url']}")
# Store subscription['secret'] to verify signatures
```
  </Tab>
  <Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from '@composio/core';

const composio = new Composio();

const subscription = await composio.triggers.setWebhookSubscription({
  webhookUrl: 'https://your-app.com/webhooks/composio',
});
console.log(`Delivering events to ${subscription.webhookUrl}`);
// Store subscription.secret to verify signatures
```
  </Tab>
</Tabs>

The first call creates the subscription; later calls update the same one. You can also set the URL in [dashboard settings](https://dashboard.composio.dev/~/project/settings/webhook) or with the [Webhook Subscriptions API](/reference/api-reference/webhook-subscriptions).

<Callout type="warn">
The response includes a `secret`. Store it securely and use it to [verify webhook signatures](/docs/webhook-verification). Every production handler should verify.
</Callout>

<Callout>
Your webhook endpoint must be publicly reachable. Composio's outbound IPs are dynamic, so IP allowlists and VPN-only endpoints won't work. Authenticate payloads with [signature verification](/docs/webhook-verification) instead.
</Callout>

## Handling events

In your handler, pass the incoming request to `parse()`. It returns the typed, normalized payload. Pass `verifySecret` and it verifies the signature first, so one call both authenticates and parses.

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
import os
from composio import Composio

composio = Composio()

@app.post("/webhooks/composio")
async def webhook_handler(request: Request):
    result = composio.triggers.parse(
        body=await request.body(),
        headers=request.headers,
        verify_secret=os.environ["COMPOSIO_WEBHOOK_SECRET"],
    )

    event = result["payload"]
    if event["trigger_slug"] == "GITHUB_COMMIT_EVENT":
        data = event["payload"]
        print(f"New commit by {data['author']}: {data['message']}")

    return {"status": "ok"}
```
  </Tab>
  <Tab value="TypeScript">
```typescript
// @noErrors
import { Composio } from '@composio/core';

const composio = new Composio();

// Next.js App Router, Hono, or any Fetch-style handler
export async function POST(request: Request) {
  const result = await composio.triggers.parse(request, {
    verifySecret: process.env.COMPOSIO_WEBHOOK_SECRET,
  });

  const event = result.payload;
  if (event.triggerSlug === 'GITHUB_COMMIT_EVENT') {
    const data = event.payload;
    console.log(`New commit by ${data.author}: ${data.message}`);
  }

  return Response.json({ status: 'ok' });
}
```
  </Tab>
</Tabs>

In TypeScript, `parse()` accepts a Fetch `Request` (Next.js App Router, Hono) or an Express-style `{ body, headers }`. In Python, pass the request directly on sync frameworks (Flask, Django), or pass `body=` and `headers=` when the framework reads the body asynchronously (FastAPI, as above). Either way, hand it the **raw** request body, not a pre-parsed object, or signature verification can't reproduce the signed bytes. Omit `verifySecret`/`verify_secret` to parse without verifying (handy for local replays).

<Callout>
Composio delivers other project events (like [connection expiry](/docs/authentication#connection-lifecycle)) to this same URL. `parse()` returns those too. Route on `result.payload.triggerSlug` and ignore what you don't handle.
</Callout>

### Inspecting trigger payload schemas

Each trigger type declares the shape of the `data` it sends. Inspect it before you write your handler:

<Tabs groupId="language" items={['Python', 'TypeScript']} persist>
  <Tab value="Python">
```python
from composio import Composio

composio = Composio()

trigger_type = composio.triggers.get_type("GITHUB_COMMIT_EVENT")
print(trigger_type.payload)
# {"properties": {"author": {...}, "id": {...}, "message": {...}, "timestamp": {...}, "url": {...}}}
```
  </Tab>
  <Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';

const composio = new Composio();

const triggerType = await composio.triggers.getType('GITHUB_COMMIT_EVENT');
console.log(triggerType.payload);
// {"properties": {"author": {...}, "id": {...}, "message": {...}, "timestamp": {...}, "url": {...}}}
```
  </Tab>
</Tabs>

### Webhook payload shape

Every trigger event arrives in the same envelope. `metadata` tells you where the event came from; `data` holds the event itself, in the shape the trigger type declares.

```json
{
  "id": "msg_abc123",
  "type": "composio.trigger.message",
  "metadata": {
    "log_id": "log_abc123",
    "trigger_slug": "GITHUB_COMMIT_EVENT",
    "trigger_id": "ti_xyz789",
    "connected_account_id": "ca_def456",
    "auth_config_id": "ac_xyz789",
    "user_id": "user-id-123435"
  },
  "data": {
    "commit_sha": "a1b2c3d",
    "message": "fix: resolve null pointer",
    "author": "jane"
  },
  "timestamp": "2026-01-15T10:30:00Z"
}
```

| `metadata` field | What it tells you |
|-------|-------------------|
| `trigger_id` | Which trigger instance fired this event |
| `trigger_slug` | The trigger type (for example `GITHUB_COMMIT_EVENT`) |
| `connected_account_id` | Which connected account it belongs to |
| `user_id` | Which user it's for |
| `auth_config_id` | Which auth config was used |

<Callout>
This is the V3 payload, the default for new organizations. See [webhook payload versions](/docs/webhook-verification#webhook-payload-versions) for V2 and V1.
</Callout>

## Test your webhook handler locally

To exercise the full production path (including signature verification) against a handler running on your machine, you need events to reach `localhost`. Three options, easiest first.

### Composio CLI (no tunnel)

The CLI streams realtime events and forwards each one to your local URL, signed exactly like production. No public URL, no tunnel.

```bash
composio dev triggers listen --forward "http://localhost:8000/webhooks/composio"
```

Events are signed with `COMPOSIO_WEBHOOK_SECRET` if it's set, otherwise the CLI prints a generated secret to verify against. Filter the stream with `--toolkits`, `--trigger-slug`, or `--trigger-id`, and tee events to a file with `--out events.jsonl`.

### ngrok

Expose your local server with [ngrok](https://ngrok.com):

```bash
ngrok http 8000
```

Then point your subscription at the printed URL:

```bash
curl -X POST https://backend.composio.dev/api/v3.1/webhook_subscriptions \
  -H "X-API-KEY: <your-composio-api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "webhook_url": "https://your-ngrok-url.ngrok-free.app/webhooks/composio",
    "enabled_events": ["composio.trigger.message"]
  }'
```

### Cloudflare Tunnel

[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) does the same without an account for quick runs:

```bash
cloudflared tunnel --url http://localhost:8000
```

Use the printed `trycloudflare.com` URL as your `webhook_url`, the same way as the ngrok example above.

Events now reach your local server at `http://localhost:8000/webhooks/composio`.
