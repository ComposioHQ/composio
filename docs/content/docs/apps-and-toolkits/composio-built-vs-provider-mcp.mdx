When a product ships more than one toolkit, you pick one slug and pass it. This page is how to pick.

A **Composio Built** toolkit is one Composio builds and maintains against the product's public API. A [**Provider MCP**](/docs/apps-and-toolkits/provider-mcps) toolkit connects to the product's own hosted MCP server. Both are catalog toolkits, available to every project, and both behave the same way inside a session. The catalog's Type filter carries these two labels, plus Custom for servers your own project registered. They differ in who maintains the tools, and that has consequences.

## How they compare

| | Composio Built | {ProviderMcpIcon} Provider MCP |
| --- | --- | --- |
| Who maintains the tools | Composio | The product's team |
| What it connects to | The product's public API | The product's own hosted MCP server |
| Slug | Anything that doesn't end in `_mcp`, like `notion` | Ends in `_mcp`, like `notion_mcp` |
| Tool naming | `NOTION_CREATE_PAGE` | `NOTION_MCP_NOTION_CREATE_PAGES` |
| Auth | OAuth2, API Key, Bearer Token, or Basic, often with [Composio managed auth](/docs/authentication/custom-app-vs-managed-app) | Whatever the product's server declares, most often DCR OAuth |
| [Triggers](/docs/triggers) | Available on many toolkits | None |
| Staying current | Composio regenerates and versions the toolkit | A sync produces a new dated version |

Neither is a subset of the other. Tool lists differ in both directions, and there's no general rule that one supersedes the other.

## Decide in this order

Open the app drawer, or the comparison strip on either toolkit's detail page, and read these facts.

<Figure width={1456} height={839} src="/images/docs/toolkit-apps/toolkit-detail-notion-mcp.jpg" alt="The notion_mcp toolkit page with a DCR OAuth pill, the Notion toolkits comparison strip, and a tools table of NOTION_MCP_ slugs" caption="The Notion toolkits strip on either sibling's detail page compares tools, authentication, and ownership side by side." />

1. **Auth your users can complete.** The usual decider, read per toolkit rather than per label. A Composio Built toolkit often offers [Composio managed](/docs/authentication/custom-app-vs-managed-app) OAuth2 or an API key. A Provider MCP toolkit most often uses DCR OAuth against the product's own server, and some need no auth, so read the auth pills rather than assuming from the label.
2. **Triggers.** [Triggers](/docs/triggers) exist only on Composio Built toolkits. If your agent has to react to events, that settles it.
3. **Tool coverage, checked in both directions.** A Provider MCP toolkit can expose capabilities only the product's own server offers, and it can also cover less of the product's API. Compare both tool lists before assuming the `_mcp` one is bigger or newer.
4. **Which account your users already have.** [Siblings never share a connection](/docs/apps-and-toolkits#sibling-toolkits-never-share-a-connection), so prefer the toolkit your user is already connected to.

Then pick one sibling per session or task, so your users authenticate once. [Configuring sessions](/docs/configuring-sessions#sibling-toolkits) has the enable and disable recipes.

<Callout type="info" title="Sometimes the labels tell you nothing">
Not every App splits one of each kind. The Slack app holds `slack` and `slackbot`, both Composio Built, differing by the identity the tools act as. When both siblings carry the same label, decide from the tool list and the auth instead.
</Callout>

## If neither fits

The catalog is what Composio already runs. If no toolkit covers the product, or you need tools only your team can provide, register your own remote MCP server as a [Custom MCP](/docs/extending-sessions/custom-mcp) and you get a project-private `CUSTOM_*` toolkit that works like a catalog toolkit inside your project.

## If an agent picks at runtime

- **Use the slug you were given.** If the request or the session config names `notion` or `notion_mcp`, use exactly that toolkit.
- **Decide from facts you can already read.** Auth schemes, whether the user already has a connected account, each tool list, and trigger counts are all observable. Prefer the toolkit the user is already connected to, then the one whose auth they can complete.
- **Don't read `_mcp` as newer, bigger, or already connected.** It only means the tools come from the product's own server.
- **State which slug you chose** when the toolkit was ambiguous, so the user can redirect you.
