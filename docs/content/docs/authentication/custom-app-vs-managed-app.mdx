Composio supports two ways to authenticate users with toolkits.

- **[Composio-managed apps](/toolkits/managed-auth)**: Composio registers and maintains OAuth apps for popular toolkits such as GitHub, Gmail, and Slack. You don't register an OAuth app.
- **Custom auth configs**: You provide your own OAuth app, API key, bearer token, or other credentials and tell Composio to use them for a toolkit.

A Composio-managed app works in production, but it isn't built for production scale. Move to your own app before you scale.

Both options use Composio to store and refresh connected-account credentials. Choosing your own OAuth app changes app ownership, branding, scopes, and provider quota, not [token custody](/docs/security/token-custody#oauth-app-ownership-and-token-custody).

## What a managed app gives you

- **No app registration.** You skip the provider's developer portal, client credentials, redirect URIs, and app review.
- **A fast start.** Create a session and connect a test account right away. Composio requests a default set of scopes for each toolkit.

You can still [white-label the Connect Link page](/docs/authentication/white-labeling-authentication#customizing-the-connect-link) with your logo and app title on a managed app.

## What a managed app limits

- **Shared provider quota.** Provider quotas that apply per OAuth app are shared by every Composio customer on the managed app, so traffic you don't control counts against the limit your users depend on. Your own app gets its own quota. See [provider quota errors](/reference/rate-limits#provider-quota-errors).
- **Composio's name on the consent screen.** Users see Composio's app name when they approve access, not yours.
- **Composio's scope set.** You can [adjust scopes](/docs/authentication/controlling-scopes) on a managed config, but only within what Composio's app is set up to request. A scope outside that set needs your own app.
- **Slower polling triggers.** Managed auth enforces a 2-minute minimum polling interval. Your own app can use shorter intervals where supported.

## When to move to your own app

Move before you scale. Switching later means existing users reconnect, so the cost grows with your user count. Also move when any of these apply:

- **You need your app name on OAuth consent screens.** Your product or your enterprise customers require your branding end to end.
- **You need custom scopes.** Composio's scopes may not include everything you need, for example write access to a specific Google API.
- **You're hitting provider rate limits.** Your own app stops sharing quota with other Composio customers.
- **You need faster polling triggers.**
- **You're connecting to a custom instance.** Self-hosted or regional variants, such as a private Salesforce subdomain, need their own OAuth app.

Some toolkits have no managed app at all. See [Toolkits without managed auth](#toolkits-without-managed-auth).

Already have users on a managed app? Follow [Move from a Composio-managed app to your own OAuth app](/docs/migration-guide/managed-to-own-app) to switch while existing connections keep working.

## Create a custom auth config

To check whether Composio provides the OAuth app for a toolkit, see [Managed OAuth apps](/toolkits/managed-auth). The steps below use the dashboard. To create auth configs in code instead, for example one per customer, see [Programmatic auth configs](/docs/authentication/programmatic-auth-configs).

<Steps>
<Step>
<StepTitle>Create the auth config in the Composio dashboard</StepTitle>

In the [Composio dashboard](https://dashboard.composio.dev/~/project/auth-configs?utm_source=docs&utm_medium=content&utm_campaign=docs-custom-app-vs-managed-app):

1. Click **Create**
2. Select the toolkit
3. Choose the auth scheme (OAuth2, API Key, Bearer Token, etc.)
4. Follow the dashboard instructions for the required credential fields

For OAuth toolkits, the dashboard shows the redirect URI to add in the provider's developer portal.
</Step>

<Step>
<StepTitle>Collect credentials from the provider</StepTitle>

For OAuth toolkits, register an app in the provider's developer portal and add the redirect URI from the dashboard. Then copy the **Client ID** and **Client Secret** back into Composio.

For API key, bearer token, basic auth, or other auth schemes, collect the credential fields the toolkit requires and enter them in the dashboard.

Step-by-step OAuth guides: [Google](https://composio.dev/auth/googleapps) | [GitHub](https://composio.dev/auth/github) | [Slack](https://composio.dev/auth/slack) | [HubSpot](https://composio.dev/auth/hubspot) | [All toolkits](https://composio.dev/auth)
</Step>

<Step>
<StepTitle>Save and copy the auth config ID</StepTitle>

After you enter the required credentials, click **Create Auth Config** and copy the auth config ID (for example, `ac_1234abcd`).
</Step>

<Step>
<StepTitle>Pass the auth config ID in your session</StepTitle>

Creating the auth config isn't enough on its own. A session uses your config only when you pass its ID to `authConfigs`, keyed by toolkit. Toolkits you leave out keep using Composio managed auth.

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
session = composio.create(
    user_id="user_123",
    auth_configs={
        "github": "ac_your_github_config",
        # toolkits not listed here still use Composio managed auth
    },
)
```
</Tab>
<Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';

const composio = new Composio();
const session = await composio.create("user_123", {
  authConfigs: {
    github: "ac_your_github_config",
    // toolkits not listed here still use Composio managed auth
  },
});
```
</Tab>
<Tab value="API">
```bash
# toolkits not listed in auth_configs still use Composio managed auth
curl -X POST https://backend.composio.dev/api/v3.1/tool_router/session \
  -H "x-api-key: $COMPOSIO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"user_id": "user_123", "auth_configs": {"github": "ac_your_github_config"}}'
```
</Tab>
</Tabs>
</Step>
</Steps>

## Mixing per toolkit

You don't have to pick one approach for all toolkits. Use your own credentials for toolkits where users see consent screens (GitHub, Google, Slack) and Composio managed auth for the rest. Each toolkit gets its own auth config independently.

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
<Tab value="Python">
```python
session = composio.create(
    user_id="user_123",
    auth_configs={
        "github": "ac_your_github_config",
        "google": "ac_your_google_config",
        # everything else uses Composio managed auth automatically
    },
)
```
</Tab>
<Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';
const composio = new Composio();
// ---cut---
const session = await composio.create("user_123", {
  authConfigs: {
    github: "ac_your_github_config",
    google: "ac_your_google_config",
    // everything else uses Composio managed auth automatically
  },
});
```
</Tab>
<Tab value="API">
```bash
# everything else uses Composio managed auth automatically
curl -X POST https://backend.composio.dev/api/v3.1/tool_router/session \
  -H "x-api-key: $COMPOSIO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user_123",
    "auth_configs": {"github": "ac_your_github_config", "google": "ac_your_google_config"}
  }'
```
</Tab>
</Tabs>

### Toolkits without managed auth

Some OAuth toolkits do not have a Composio-managed OAuth app. Check [Managed OAuth apps](/toolkits/managed-auth) to find them. For API keys, instance details, and other authentication methods, check the individual pages in the [toolkit catalog](/toolkits).
