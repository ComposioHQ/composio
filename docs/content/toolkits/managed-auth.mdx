Composio can provide the OAuth app that your users authorize when they connect a toolkit. You do not need to register an OAuth app or supply its client ID and client secret. This page lists which toolkits have one. To learn how managed apps work and what they share, see [Composio-managed apps](/docs/authentication/managed-apps).

<Callout type="info">
Managed OAuth apps work in production. Because the OAuth app is shared, you may run into shared provider rate limits as your usage grows. For higher volume, we recommend your own OAuth app. See [Managed vs custom auth](/docs/authentication/custom-app-vs-managed-app) and [Avoid and recover from rate limits](/docs/poc-to-prod/avoid-rate-limits).
</Callout>

Your users still authorize their accounts through a [Connect Link](/docs/tools-direct/authenticating-tools#hosted-authentication-connect-link). Composio stores and refreshes the resulting tokens. See [Authentication](/docs/authentication) for the full connection flow.

This catalog identifies who provides the OAuth app, not which execution framework you must use. For per-user OAuth with application-owned tools, follow [Managed authentication for your own tools](/docs/authentication/managed-auth-for-custom-tools). Your code can call provider endpoints through the authenticated proxy without predefined tools, MCP, or an LLM.

This page covers only toolkits that support OAuth. It does not list toolkits that use only API keys, bearer tokens, Basic auth, or no authentication.

## When Composio provides the OAuth app

For a toolkit with managed OAuth, Composio maintains the OAuth app registration, client credentials, and redirect URI. Your users sign in to the provider and approve the requested permissions.

## When you provide the OAuth app

Register your own OAuth app when a toolkit does not have managed OAuth. Then create a custom auth config with the app's client ID and client secret.

You can also provide your own OAuth app to show your app name on the consent screen, request custom scopes, or use a separate rate-limit quota.

See [Managed vs custom auth](/docs/authentication/custom-app-vs-managed-app) for setup steps and trade-offs.

## Slack managed apps

Slack is the one toolkit with two Composio managed apps. You don't register anything with Slack for either one. Slack has approved Standard but not Legacy. The two apps get different Slack rate limits and receive different triggers.

| App | Approved by Slack | Slack rate limits | Triggers |
|---|---|---|---|
| Standard | Yes | Higher | Every Slack trigger except the four below |
| Legacy | No | Lower | Every Slack trigger |

Slack gives approved apps higher limits on its API methods than unapproved ones. See [Slack's rate limits](https://docs.slack.dev/apis/web-api/rate-limits) for the numbers.

Standard does not receive these message triggers:

- `SLACK_CHANNEL_MESSAGE_RECEIVED`
- `SLACK_DIRECT_MESSAGE_RECEIVED`
- `SLACK_RECEIVE_BOT_MESSAGE`
- `SLACK_RECEIVE_MESSAGE`

Use Standard unless your product reacts to new Slack messages. Pick Legacy when you need one of these four triggers and your traffic fits under the lower limits.

To move existing Slack users from Legacy to Standard, follow [Move Slack to the Standard managed app](/docs/migration-guide/slack-legacy-to-standard).

Use your own Slack app when you need message triggers and your app name on the Slack consent screen, or scopes that neither managed app requests. Follow the [Slack OAuth guide](https://composio.dev/auth/slack), then [create a custom auth config](/docs/authentication/custom-app-vs-managed-app#create-a-custom-auth-config).

## Find an OAuth toolkit

Search for a toolkit to check whether Composio provides a managed OAuth app.

- **Composio-managed OAuth available** means that you can use Composio's OAuth app.
- **Bring your own OAuth app** means that you must register an OAuth app with the provider and create a custom auth config.

Some toolkits support more than one authentication method. A toolkit appears under **Composio-managed OAuth available** when Composio manages at least one OAuth method. Open the toolkit page to check each method.

## Check with the API

Fetch the toolkit and read its managed auth schemes (`composio_managed_auth_schemes` in the API and Python, `composioManagedAuthSchemes` in TypeScript):

<Tabs groupId="language" items={['Python', 'TypeScript', 'API']} persist>
<Tab value="Python">
```python
from composio import Composio

composio = Composio()
toolkit = composio.toolkits.get("gmail")
print(toolkit.composio_managed_auth_schemes)
```
</Tab>
<Tab value="TypeScript">
```typescript
import { Composio } from '@composio/core';

const composio = new Composio({ apiKey: process.env.COMPOSIO_API_KEY });
const toolkit = await composio.toolkits.get('gmail');
console.log(toolkit.composioManagedAuthSchemes);
```
</Tab>
<Tab value="API">
```bash
curl -X GET https://backend.composio.dev/api/v3.1/toolkits/gmail \
  -H "x-api-key: $COMPOSIO_API_KEY"
```
</Tab>
</Tabs>

If `composio_managed_auth_schemes` contains the toolkit's OAuth method, Composio provides the OAuth app. If the field does not contain that method, register your own OAuth app and supply its client ID and client secret.
