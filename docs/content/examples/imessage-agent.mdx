Most Composio toolkits call a remote API. Some capabilities only exist on one machine, and iMessage is the classic case: there's no iMessage cloud API, so the agent has to run on your Mac and drive Messages.app directly.

This example builds exactly that, a terminal agent that **texts on your behalf from your own Mac** and reaches the rest of your apps (Gmail, Calendar, GitHub, Slack) through the Composio catalog in the same breath.

```
you  ›  read my last email and text KJ a summary
you  ›  text mom i'm running 10 min late
you  ›  what did Sarah and I last text about?
```

The pattern is the takeaway, not iMessage specifically: **a Composio custom toolkit that executes in-process**, registered on the same session as the catalog, surfaced to [eve](https://github.com/vercel/eve) through the [eve provider](/docs/providers/eve). Swap the iMessage internals for any local capability and everything else stays. Every file you need is on this page.

## Setup

You need a [Composio API key](https://dashboard.composio.dev) and macOS (the iMessage tools drive Messages.app, Contacts.app, and the local `chat.db`).

<Steps>
<Step>
**Install**

```bash
npm install @composio/core @composio/experimental eve
```

</Step>
<Step>
**Configure**

```txt title=".env.local"
COMPOSIO_API_KEY=xxxxxxxxx
COMPOSIO_USER_ID=me
```

</Step>
<Step>
**Grant macOS permissions** (prompted on first use): Automation for Messages, Contacts access, and Full Disk Access to read `chat.db`.
</Step>
</Steps>

## The custom toolkit

A custom toolkit is a named group of custom tools. Each tool declares an input schema and an `execute` that runs locally. Here is `SEND`, which shells out to AppleScript to drive Messages.app:

```ts title="imessage/send-message.ts"
import { experimental_createTool } from '@composio/core';
import { z } from 'zod/v3'; // Composio's custom-tool API expects zod/v3
import { runAppleScript } from './applescript.js';

const SEND_SCRIPT = `on run {targetBuddy, targetText}
  tell application "Messages"
    set targetService to 1st service whose service type = iMessage
    send targetText to buddy targetBuddy of targetService
  end tell
end run`;

// A short "think + type" pause so messages aren't instant.
function humanDelayMs(text: string): number {
  const think = 800 + Math.random() * 1700;
  const typing = text.length * (40 + Math.random() * 40);
  return Math.min(think + typing, 12_000);
}

export const sendMessage = experimental_createTool('SEND', {
  name: 'Send iMessage',
  description: "Send an iMessage from the user's Mac to a phone number or iMessage email.",
  preload: true, // surface it in session.tools() without a search step
  inputParams: z.object({
    to: z.string().describe('Phone number (e.g. +15551234567) or iMessage email.'),
    text: z.string().describe('Message body to send.'),
  }),
  execute: async ({ to, text }) => {
    await new Promise(r => setTimeout(r, humanDelayMs(text)));
    await runAppleScript(SEND_SCRIPT, [to, text]);
    return { sent: true, to };
  },
});
```

Group your tools into a toolkit. The full project also ships `FIND_CONTACT` (fuzzy contact lookup over Contacts.app), `READ_MESSAGES` (recent messages from `chat.db`), and `RECALL`/`REMEMBER` (per-contact memory), each built the same way:

```ts title="imessage/index.ts"
import { experimental_createToolkit } from '@composio/core';
import { sendMessage } from './send-message.js';
import { findContact } from './find-contact.js';
import { readMessages } from './read-messages.js';
import { recallContact, rememberContact } from './memory.js';

export function createImessageToolkit() {
  return experimental_createToolkit('IMESSAGE', {
    name: 'iMessage',
    description: "Send and read iMessages, look up contacts, and remember people, locally on the user's Mac.",
    tools: [sendMessage, findContact, readMessages, recallContact, rememberContact],
  });
}
```

The toolkit depends only on `@composio/core`, so it drops into any Composio agent. Custom tools execute in-process through `session.execute`, which is why they aren't on the MCP URL yet.

## Register the provider and toolkit

Set the [eve provider](/docs/providers/eve) on the client, and register the toolkit on the session. The session now exposes the catalog meta-tools **and** the local `LOCAL_IMESSAGE_*` tools from one place:

```ts title="composio.ts"
import { Composio } from '@composio/core';
import { EveProvider } from '@composio/experimental';
import { createImessageToolkit } from './imessage/index.js';

const composio = new Composio({
  apiKey: process.env.COMPOSIO_API_KEY,
  provider: new EveProvider(),
});

export const session = composio.sessions.create(process.env.COMPOSIO_USER_ID, {
  workbench: { enable: false }, // a texting agent doesn't need the remote sandbox
  experimental: { customToolkits: [createImessageToolkit()] },
});
```

## Hand the tools to eve

eve discovers tools from files. `defineComposioTools(session)` returns the resolver that gives eve `session.tools()`, so one line wires up everything:

```ts title="agent/tools/composio.ts"
import { defineComposioTools } from '@composio/experimental';
import { session } from '../../composio.js';

export default defineComposioTools(session);
```

```ts title="agent/agent.ts"
import { defineAgent } from 'eve';

export default defineAgent({
  model: 'google/gemini-2.5-flash',
});
```

That's the whole integration. Run `eve dev` and talk to it. The agent can text a contact, read a thread, and act across every connected app, with auth handled in chat through `COMPOSIO_MANAGE_CONNECTIONS`.
