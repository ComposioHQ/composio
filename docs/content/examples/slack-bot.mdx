This example puts an agent in Slack, where a whole team can talk to it, and wires it so the agent can actually *do* things like open a PR, check a calendar, or search a Notion workspace, on behalf of whoever is typing.

The agent is [Pi](https://github.com/earendil-works/pi-coding-agent), but the agent is the easy part. The work is the four Composio pieces that turn "an agent in a terminal" into "an agent in your workspace":

1. **Triggers** deliver every Slack message to your server as a webhook.
2. **Sessions** give each user their own scoped toolset, so the agent acts as *them*.
3. **A shared connection** lets the bot speak as the workspace bot, with one install for everyone.
4. **The proxy** reaches the Slack Web API endpoints the toolkit doesn't wrap as tools.

You bring a Composio API key and an agent runtime. Composio brings the workspace.

## Setup

You need a [Composio API key](https://dashboard.composio.dev), a publicly reachable URL for your server, and [Bun](https://bun.sh).

Create the client once and reuse it:

```ts
// @noErrors
import { Composio } from '@composio/core';

export const composio = new Composio({ apiKey: process.env.COMPOSIO_API_KEY });
```

## Install the bot

This is a one-time script. A Slack bot needs a Slack app to authenticate as and a stream of events. Composio gives you both, so you never register a webhook with Slack or hold a bot token.

The `slackbot` toolkit ships with Composio-managed OAuth, so you don't bring your own Slack app. Create an [auth config](/docs/authentication) that declares the scopes the bot needs:

```ts
// @noErrors
const authConfig = await composio.authConfigs.create('slackbot', {
  type: 'use_composio_managed_auth',
  name: 'workspace-bot',
  credentials: {
    scopes: ['app_mentions:read', 'channels:history', 'chat:write', 'reactions:write', 'users:read'],
    user_scopes: ['search:read'],
  },
});
```

Install it as a **[shared connection](/docs/authenticating-users/shared-connections)** so a single OAuth approval serves the whole workspace. Start a setup session, authorize `slackbot`, and send the admin to the returned URL:

```ts
// @noErrors
const setup = await composio.create('setup:workspace-bot', {
  toolkits: ['slackbot'],
  authConfigs: { slackbot: authConfig.id },
  manageConnections: true,
});

const request = await setup.authorize('slackbot', {
  callbackUrl: `${process.env.APP_URL}/setup/callback`,
  experimental: { accountType: 'SHARED' },
});

console.log(request.redirectUrl); // redirect the admin here to approve
```

When the admin returns, open the connection to everyone, point Composio at your webhook, and create the triggers. The `updateAcl` call is what makes the shared connection usable by every user. More on that in [Share one Slack connection](#share-one-slack-connection).

```ts
// @noErrors
async function onSetupCallback(connectedAccountId: string) {
  // Persist connectedAccountId for the bot server. You pin it into every session later.
  await composio.connectedAccounts.updateAcl(connectedAccountId, { allowAllUsers: true });

  await composio.triggers.setWebhookSubscription({
    webhookUrl: `${process.env.APP_URL}/webhooks/composio`,
  });

  await composio.triggers.create('setup:workspace-bot', 'SLACKBOT_CHANNEL_MESSAGE_RECEIVED', {
    triggerConfig: { is_bot_message: false },
  });
  await composio.triggers.create('setup:workspace-bot', 'SLACKBOT_DIRECT_MESSAGE_RECEIVED', {
    triggerConfig: {},
  });
}
```

A webhook subscription is the *pipe*; each trigger is a *tap*. Together they stream channel messages and DMs to your server.

## Give each user a session

The key move: each Slack user gets their own Composio session. When Alice asks the bot to open a GitHub issue, it opens as *Alice*, against her GitHub connection, with her permissions.

A [session](/docs/configuring-sessions) is a per-user handle. Create one keyed to the Slack thread and reuse it so the agent keeps context across the conversation:

```ts
// @noErrors
async function sessionForThread(userId: string, threadKey: string, sharedSlackConnectionId: string) {
  const existing = threadStore.get(threadKey);
  if (existing) return composio.use(existing.sessionId);

  const session = await composio.create(userId, {
    connectedAccounts: { slackbot: [sharedSlackConnectionId] },
    manageConnections: { enable: true, callbackUrl, waitForConnections: true },
  });

  threadStore.set(threadKey, { sessionId: session.sessionId, userId });
  return session;
}
```

The session sets who the agent acts as and pins the shared Slack connection. It puts no ceiling on toolkits: the agent reaches any of the 1000+ apps through search and connects them on demand.

## Turn the session into agent tools

Rather than hand the model hundreds of raw tool schemas, give it three meta-tools (search, manage connections, execute) and let it discover what it needs at runtime. The `@composio/experimental` **Pi provider** builds exactly those from a session: you describe *capabilities* and it wires the tools.

```ts
// @noErrors
import { PiProvider } from '@composio/experimental';

const piProvider = new PiProvider();

function toolsForSession(session) {
  return piProvider.createSessionTools({
    sessionId: session.sessionId,
    callbackUrl,
    search: (params) => session.search(params),
    execute: (toolSlug, args, options) => session.execute(toolSlug, args, options),
    connections: {
      getToolkitStates: (toolkits) => session.toolkits({ toolkits }),
      authorizeToolkit: async (toolkit) => {
        const request = await session.authorize(toolkit, { callbackUrl });
        return { status: 'needs_connection', redirectUrl: request.redirectUrl };
      },
      isConnected: (state) => state.connection?.isActive ?? false,
    },
  });
}
```

Each capability is a session method doing the work:

- `session.search({ query })` runs a semantic search across 1000+ toolkits, so "open a bug report" finds `GITHUB_CREATE_ISSUE`.
- `session.toolkits({ toolkits })` reports which apps this user has already connected.
- `session.authorize(toolkit)` starts an OAuth flow and returns a link to DM the user when something isn't connected.
- `session.execute(toolSlug, args)` runs the tool against this user's connection.

## Run the agent and reply

Feed the tools to Pi and let it loop. When it's done, post the reply with `SLACKBOT_SEND_MESSAGE`. Sending a Slack message is just another tool the session runs against the shared connection, so the reply lands as the workspace bot.

```ts
// @noErrors
import { createAgentSession, SessionManager } from '@earendil-works/pi-coding-agent';
import type { IncomingTriggerPayload } from '@composio/core';

async function handleSlackMessage(event: IncomingTriggerPayload) {
  const session = await sessionForThread(event.userId, threadKey(event), sharedSlackConnectionId);

  const { session: pi } = await createAgentSession({
    sessionManager: SessionManager.inMemory(cwd),
    customTools: toolsForSession(session),
    tools: ['composio_search_tools', 'composio_manage_connections', 'composio_execute_tool'],
  });

  let reply = '';
  pi.subscribe((e) => {
    if (e.type === 'message_update' && e.assistantMessageEvent.type === 'text_delta') {
      reply += e.assistantMessageEvent.delta;
    }
  });
  await pi.prompt(event.payload?.text ?? '');
  pi.dispose();

  await session.execute('SLACKBOT_SEND_MESSAGE', {
    channel: event.payload?.channel,
    thread_ts: event.payload?.thread_ts,
    text: reply,
  });
}
```

When the agent hits an app the user hasn't connected, `composio_manage_connections` calls `session.authorize`, you DM them the link, and the run resumes once they approve. That resume works because the session was created with `waitForConnections: true`.

## Reach the gaps with the proxy

Most Slack actions are `SLACKBOT_*` tools the agent runs with `session.execute`. For the few endpoints Composio doesn't wrap as a tool, like the assistant typing indicator, drop down to the **proxy** and call the Slack Web API directly. It uses the pinned connection's auth, so you still never touch a token.

```ts
// @noErrors
await session.proxyExecute({
  toolkit: 'slackbot',
  endpoint: 'https://slack.com/api/assistant.threads.setStatus',
  method: 'POST',
  body: { channel_id: channel, thread_ts: threadTs, status: 'Working on it…' },
});
```

`proxyExecute` returns `{ status, data, headers }`. `GET` endpoints pass query values as `parameters` instead of a `body`:

```ts
// @noErrors
const user = await session.proxyExecute({
  toolkit: 'slackbot',
  endpoint: 'https://slack.com/api/users.info',
  method: 'GET',
  parameters: [
    { in: 'query', name: 'user', value: userId },
    { in: 'query', name: 'include_locale', value: 'true' },
  ],
});
```

## Share one Slack connection

The bot acts in Slack as a single identity no matter who's talking to it. That's one connection, shared. By default a connected account is **PRIVATE**: only the `userId` that created it can use it. The install flow authorized it as **SHARED**, then the `updateAcl(connectedAccountId, { allowAllUsers: true })` call opened it to the whole workspace.

A shared connection is never resolved implicitly. You **pin** it into a session by ID, which is the `connectedAccounts: { slackbot: [sharedSlackConnectionId] }` line in `sessionForThread`. Now Alice's session has *her* GitHub connection but *the workspace's* Slack connection: the agent posts as the bot, and acts in other apps as Alice. The Slack token lives in Composio, so your app only ever stores a `ca_…` id.

Because the connection is shared, gate who you pin it for:

```ts
// @noErrors
function assertAllowed(teamId: string, userId: string) {
  const allowed = userId === `service:${teamId}` || userId.startsWith(`slack:${teamId}:`);
  if (!allowed) throw new Error(`Refusing to share the Slack connection with ${userId}`);
}
```

Tighten the ACL anytime with the same call: `allowedUserIds` for a targeted list, `notAllowedUserIds` to block specific people. It uses PATCH semantics, so pass only the fields you're changing.

## Wire up the webhook

Every event lands at one webhook URL. Verify the signature, acknowledge fast so Composio doesn't retry, and dispatch the work off the response path:

```ts
// @noErrors
Bun.serve({
  port: 3000,
  async fetch(req) {
    const url = new URL(req.url);
    if (req.method === 'POST' && url.pathname === '/webhooks/composio') {
      const { payload } = await composio.triggers.verifyWebhook({
        payload: await req.text(), // the raw, unparsed body
        secret: process.env.COMPOSIO_WEBHOOK_SECRET,
        id: req.headers.get('webhook-id'),
        timestamp: req.headers.get('webhook-timestamp'),
        signature: req.headers.get('webhook-signature'),
      });

      void handleSlackMessage(payload);
      return Response.json({ ok: true });
    }
    return new Response('Not found', { status: 404 });
  },
});
```

`verifyWebhook` returns a normalized [`IncomingTriggerPayload`](/docs/setting-up-triggers/subscribing-to-events): `triggerSlug`, `toolkitSlug`, `userId`, and the event `payload` with the Slack channel, text, and timestamps. That's everything `handleSlackMessage` needs.

## Full example

Two files: `install.ts` runs once to set up the bot, and `bot.ts` is the server. The server keeps a per-thread session and a short transcript, so the agent has memory across the conversation.

```ts title="install.ts"
// @noErrors
import { Composio } from '@composio/core';

const composio = new Composio({ apiKey: process.env.COMPOSIO_API_KEY });

// 1. Auth config with the scopes the bot needs.
const authConfig = await composio.authConfigs.create('slackbot', {
  type: 'use_composio_managed_auth',
  name: 'workspace-bot',
  credentials: {
    scopes: ['app_mentions:read', 'channels:history', 'chat:write', 'reactions:write', 'users:read'],
    user_scopes: ['search:read'],
  },
});

// 2. Authorize one shared connection for the whole workspace.
const setup = await composio.create('setup:workspace-bot', {
  toolkits: ['slackbot'],
  authConfigs: { slackbot: authConfig.id },
  manageConnections: true,
});
const request = await setup.authorize('slackbot', {
  callbackUrl: `${process.env.APP_URL}/setup/callback`,
  experimental: { accountType: 'SHARED' },
});
console.log('Approve the install:', request.redirectUrl);

// 3. On the OAuth callback, open the ACL and wire up events.
//    Persist connectedAccountId as SLACK_CONNECTION_ID for the bot server.
export async function onSetupCallback(connectedAccountId: string) {
  await composio.connectedAccounts.updateAcl(connectedAccountId, { allowAllUsers: true });
  await composio.triggers.setWebhookSubscription({ webhookUrl: `${process.env.APP_URL}/webhooks/composio` });
  await composio.triggers.create('setup:workspace-bot', 'SLACKBOT_CHANNEL_MESSAGE_RECEIVED', { triggerConfig: { is_bot_message: false } });
  await composio.triggers.create('setup:workspace-bot', 'SLACKBOT_DIRECT_MESSAGE_RECEIVED', { triggerConfig: {} });
}
```

```ts title="bot.ts"
// @noErrors
import { Composio } from '@composio/core';
import type { IncomingTriggerPayload } from '@composio/core';
import { PiProvider } from '@composio/experimental';
import { createAgentSession, SessionManager } from '@earendil-works/pi-coding-agent';

const composio = new Composio({ apiKey: process.env.COMPOSIO_API_KEY });
const piProvider = new PiProvider();

const SHARED_SLACK_CONNECTION_ID = process.env.SLACK_CONNECTION_ID;
const callbackUrl = `${process.env.APP_URL}/connections/callback`;

// Per-thread memory: one Composio session and a short transcript per Slack thread.
const threads = new Map<string, { sessionId: string; history: { role: string; content: string }[] }>();

const threadKey = (event: IncomingTriggerPayload) =>
  `${event.payload?.channel}:${event.payload?.thread_ts ?? event.payload?.ts}`;

async function sessionForThread(event: IncomingTriggerPayload) {
  const key = threadKey(event);
  const existing = threads.get(key);
  if (existing) return { session: await composio.use(existing.sessionId), memory: existing };

  const session = await composio.create(event.userId, {
    connectedAccounts: { slackbot: [SHARED_SLACK_CONNECTION_ID] },
    manageConnections: { enable: true, callbackUrl, waitForConnections: true },
  });
  const memory = { sessionId: session.sessionId, history: [] };
  threads.set(key, memory);
  return { session, memory };
}

function toolsForSession(session) {
  return piProvider.createSessionTools({
    sessionId: session.sessionId,
    callbackUrl,
    search: (params) => session.search(params),
    execute: (toolSlug, args, options) => session.execute(toolSlug, args, options),
    connections: {
      getToolkitStates: (toolkits) => session.toolkits({ toolkits }),
      authorizeToolkit: async (toolkit) => {
        const request = await session.authorize(toolkit, { callbackUrl });
        return { status: 'needs_connection', redirectUrl: request.redirectUrl };
      },
      isConnected: (state) => state.connection?.isActive ?? false,
    },
  });
}

async function handleSlackMessage(event: IncomingTriggerPayload) {
  const { session, memory } = await sessionForThread(event);

  // Typing indicator. assistant.threads.setStatus has no SLACKBOT_* tool, so use the proxy.
  await session
    .proxyExecute({
      toolkit: 'slackbot',
      endpoint: 'https://slack.com/api/assistant.threads.setStatus',
      method: 'POST',
      body: { channel_id: event.payload?.channel, thread_ts: event.payload?.thread_ts, status: 'Working on it…' },
    })
    .catch(() => {});

  const { session: pi } = await createAgentSession({
    sessionManager: SessionManager.inMemory(process.cwd()),
    customTools: toolsForSession(session),
    tools: ['composio_search_tools', 'composio_manage_connections', 'composio_execute_tool'],
  });

  let reply = '';
  pi.subscribe((e) => {
    if (e.type === 'message_update' && e.assistantMessageEvent.type === 'text_delta') {
      reply += e.assistantMessageEvent.delta;
    }
  });

  const prompt = [...memory.history.map((m) => `${m.role}: ${m.content}`), `user: ${event.payload?.text}`].join('\n');
  await pi.prompt(prompt);
  pi.dispose();

  await session.execute('SLACKBOT_SEND_MESSAGE', {
    channel: event.payload?.channel,
    thread_ts: event.payload?.thread_ts,
    text: reply,
  });

  memory.history.push({ role: 'user', content: event.payload?.text ?? '' }, { role: 'assistant', content: reply });
}

Bun.serve({
  port: 3000,
  async fetch(req) {
    const url = new URL(req.url);
    if (req.method === 'POST' && url.pathname === '/webhooks/composio') {
      const { payload } = await composio.triggers.verifyWebhook({
        payload: await req.text(),
        secret: process.env.COMPOSIO_WEBHOOK_SECRET,
        id: req.headers.get('webhook-id'),
        timestamp: req.headers.get('webhook-timestamp'),
        signature: req.headers.get('webhook-signature'),
      });
      void handleSlackMessage(payload);
      return Response.json({ ok: true });
    }
    return new Response('Not found', { status: 404 });
  },
});
```

## Run it

Run `bun install.ts` once to set up the bot, start the server with `bun bot.ts`, then `@mention` the bot in any channel. It opens a session as you, finds the tool it needs, runs it against your connections, and replies in thread as the workspace bot, usually within a few seconds.

The production version on GitHub builds on this with auth-link DMs, message chunking, reaction acks, and durable per-thread storage: [composio-slack-bot](https://github.com/ComposioHQ/composio-slack-bot).
