I recently became an EM, so now I run standup, and I've learned two things about it: it matters, and everyone hates it. Not the standup itself, just the part where every morning you keep track of and write down everything you did.

I mean, the evidence is right there: GitHub, Notion, Slack messages. If all of it is already recorded somewhere, an agent should be able to at least give me a draft, no? So I built one. It DMs each teammate their standup every morning, written from their own connected tools, and they post it with one tap.

Getting the agent to write the draft was the easy part: Composio for the tools, the [Vercel AI SDK](https://sdk.vercel.ai) for the model, a few lines. The fun was making it feel like *my* bot, with its own name and its own (frankly ridiculous) face:

## Setup

You need a [Composio API key](https://dashboard.composio.dev) and Node with [tsx](https://github.com/privatenumber/tsx). The first part (the agent) needs nothing else; the Slack bot comes later. The finished bot deploys to [Vercel](https://vercel.com) as two serverless functions, a cron and an interactivity handler, so there's no long-running server.

```bash
npm install @composio/core @composio/vercel ai dayjs
```

## The easy part: drafting a standup

Connecting a member's tools is a one-time click each: they authorize GitHub, Linear, Notion, whatever they want counted. After that, drafting their standup is a tool-router session and the AI SDK. This is the whole agent, three concepts deep.

### A session writes the draft

A [tool-router session](/docs/configuring-sessions) is the agent. Scope it to some toolkits, hand its research tools to the model, and let it investigate and write.

<FileBuildup name="draft" source="standup" step={1} />

### Only draft from connected tools

A draft should never invent activity from a tool the member hasn't connected. Ask Composio which catalogue toolkits are **ACTIVE** for them, filtered server-side with `statuses`, and scope the session to exactly those.

<FileBuildup name="draft" source="standup" step={2} />

### Keep the agent from connecting mid-draft

The router can also *manage* connections. During a draft you don't want that: if the agent hits a tool that needs auth, it should skip it, not start an OAuth flow. `manageConnections: false` removes those meta-tools from the session.

<FileBuildup name="draft" source="standup" step={3} />

That's the agent. It already writes a solid standup from a member's tools. Everything from here is about turning it into a Slack bot that's *yours*.

## Make it your own bot

I didn't want a generic integration posting as "Composio". I wanted *my* bot: its own name, its own face, posting under its own identity. That's [white-labelling](/docs/white-labeling-authentication), using your own Slack app's credentials instead of Composio-managed ones. It's more setup up front, but the bot is fully yours, and it's the same path you'd take to ship a bot to other workspaces.

<Steps>
<Step>
**Create the app from scratch.** At [api.slack.com/apps](https://api.slack.com/apps), click **Create an App**, choose **From scratch**, name it (mine is `Daily Standup Bot`), and pick your workspace. Set its display name and icon under Basic Information; that's the identity it posts as.

![Naming the Slack app and choosing a workspace](/images/standup-slackbot/create-app.png)
</Step>

<Step>
**Add the Bot Token Scopes.** Under **OAuth & Permissions**, add: `chat:write`, `im:write`, `channels:history`, `channels:read`, `users:read`, `users:read.email`, `team:read`. Then turn on **Interactivity** and point its Request URL at your deployment's `/api/interactivity`.

![Adding bot token scopes under OAuth & Permissions](/images/standup-slackbot/bot-scopes.png)
</Step>

<Step>
**Grab the app credentials.** On **Basic Information**, copy the **Client ID** and **Client Secret**. Composio drives the OAuth as your app with these.

![The app's Client ID and Secret under Basic Information](/images/standup-slackbot/app-credentials.png)
</Step>

<Step>
**Create an auth config and pick the `Slackbot` toolkit.** In the [Composio dashboard](https://app.composio.dev), click **Create Auth Config** and search `slackbot`. Choose **Slackbot**, *not* `Slack`: `Slackbot` posts as the bot identity, while `Slack` acts as an individual user.

![Choosing the Slackbot toolkit, not Slack](/images/standup-slackbot/auth-config-slackbot.png)
</Step>

<Step>
**Use your own credentials.** Pick **OAuth 2.0**, then **Your Own Credentials**, and paste the Client ID and Secret from before. Add `team:read` to the user token scopes. This is the white-label step: your app, your name, your face.

![Selecting Your Own Credentials and entering the Client ID and Secret](/images/standup-slackbot/auth-config-credentials.png)
</Step>

<Step>
**Save the auth config id.** Once created, copy its `ac_...` id into `COMPOSIO_SLACKBOT_AUTH_CONFIG_ID`. This one config is what every member's bot connection runs through.

![The created slackbot auth config with its ac_ id](/images/standup-slackbot/auth-config-created.png)
</Step>

<Step>
**Run the setup script to connect the bot.** It binds a session to your auth config, and if the bot isn't connected yet, hands you an OAuth link and waits. The connected account it leaves behind is the identity the bot posts as.

<FileBuildup name="setup" source="standup" />

The first run prints a link and waits:

```text
╭─────────────────────────────────────────────────────────╮
│  Daily Standup Bot: One-Time Setup                       │
╰─────────────────────────────────────────────────────────╯
  ✅ Auth config has the required user scopes.
  ·  Bot is not connected yet. Generating an authorization link…

  Open this URL in your browser to authorize the bot:

    https://backend.composio.dev/s/AbC123xy

  Waiting for you to complete the OAuth flow (Ctrl+C to abort)…
  ✅ Bot connected to Slack.

──────────────────────────────────────────────────────────────────────
  🎉 Setup complete. Invite the bot to your standup channel and
     point your Slack app's Interactivity Request URL at
     https://<your-deployment>/api/interactivity
──────────────────────────────────────────────────────────────────────
```

Open that link to approve the bot:

![Approving the bot's OAuth connection](/images/standup-slackbot/oauth-approve.png)

Approve it, and the connection goes live:

![Composio successfully connected to Slackbot](/images/standup-slackbot/connected.png)
</Step>
</Steps>

A script instead of clicking through the dashboard because it's idempotent and repeatable: re-run it after changing scopes (`--reconnect` in the real version), check it into the repo, and anyone forking the bot gets the same connection without a manual OAuth dance.

## Extend Composio with the proxy

Your bot can post now, but a standup bot should feel native: a daily DM with buttons, a draft you confirm or edit in a modal. Those aren't all `SLACKBOT_*` tools. This is where you extend Composio with the **proxy**: `proxyExecute` calls any Slack Web API endpoint as a connected account, no token, including the ones the named tools don't wrap (like `views.open` for modals).

<FileBuildup name="proxy" source="standup" step={1} />

The connected account is just a parameter. Pass the bot's to post as the bot; pass a member's own Slack account and the standup posts under *their* name, which is exactly how **Confirm** posts the finished update.

<FileBuildup name="proxy" source="standup" step={2} />

From these two calls, every interactive piece, the reminder menu, the Draft / Connect / Confirm / Edit buttons, the edit modal, is plain Block Kit posted through the proxy.

## The whole project

The three pieces above are the spine. The real bot wires them into a Vercel cron that DMs each due member on their schedule, an interactivity handler for the buttons and modals, and a small catalogue of toolkits each person can connect. Browse the tree, the Composio files are flagged:

## Run it

Set your four environment variables, run `npx tsx scripts/setup.ts` once to connect your bot, then `vercel deploy`. On schedule, each member gets a DM. They tap **Draft**, the agent researches their connected tools and writes a standup in a few seconds, and **Confirm** posts it into the day's thread under their own name. Tap **Connect more tools** to add a source, and the next draft includes it.
