The agent is the easy part. [Pi](https://github.com/earendil-works/pi-coding-agent) does the reasoning; Composio gives it 1000+ apps to act on. In three lines you have an agent that can open a PR, check a calendar, or search a Notion workspace for one user.

The work is everything around it: putting that agent in Slack, where a whole team talks to it, and making it act as *each* person while posting as one bot. That's a handful of Composio pieces:

1. **Triggers** deliver every Slack message to your server as a webhook.
2. **Sessions** give each user their own scoped toolset, so the agent acts as *them*.
3. **A shared connection** lets the bot speak as the workspace bot, with one install for everyone.
4. **Redirected auth links** keep OAuth out of the channel: when an app isn't connected, the bot DMs the user a link and resumes on approval.
5. **The proxy** reaches the Slack Web API endpoints the toolkit doesn't wrap as tools.

## Install the bot

A Slack bot needs a Slack app to authenticate as and a stream of events. Composio gives you both, so you never register a webhook with Slack or hold a bot token. The `slackbot` toolkit ships with Composio-managed OAuth, and you install it as one **[shared connection](/docs/authenticating-users/shared-connections)** for the whole workspace.

A few things carry the weight, so it's worth knowing what to watch for:

- **A [session](/docs/configuring-sessions) per user.** Each Slack thread gets its own session keyed to the Slack user. When Alice asks the bot to open a GitHub issue, it opens as *Alice*, against her GitHub connection, with her permissions. Reusing the session across a thread is what gives the agent memory.
- **One shared Slack connection.** By default a connected account is **PRIVATE** — only its creator can use it. The install authorized the Slack connection as **SHARED** and opened its ACL, so you can **pin** it into anyone's session. Alice's session then has *her* GitHub connection but *the workspace's* Slack connection: it posts as the bot, acts elsewhere as Alice.
- **Redirected auth links.** When the agent reaches for an app the user hasn't connected, the tool result contains a one-time Composio connect URL. You never want that in the channel or in the model's context. The bot extracts it, **redacts** it from the tool output, DMs it to the user privately, and — because the session was created with `manageConnections` + `waitForConnections` — the run picks back up the moment they approve.
- **The proxy for the gaps.** Most Slack actions are `SLACKBOT_*` tools. The few that aren't (the typing indicator, opening a DM channel) drop down to `session.proxyExecute`, which calls the Slack Web API with the pinned connection's auth.

## Run it

Run `bun install.ts` once to set up the bot, start the server with `bun bot.ts`, then `@mention` the bot in any channel. It opens a session as you, finds the tool it needs, runs it against your connections, and replies in thread as the workspace bot, usually within a few seconds. Ask it to do something in an app you haven't connected yet and it DMs you a link first, then continues once you approve.
