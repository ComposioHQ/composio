---
title: 'Instant triggers for Gmail and Google Calendar'
description: 'Gmail and Google Calendar triggers now fire the moment something changes, instead of on the next poll.'
date: '2026-11-05'
---

Your Gmail and Google Calendar triggers no longer wait for the next poll. Google now tells Composio about a new email or a moved meeting as it happens, and the event reaches your webhook URL in seconds, in the same payload shape your handler already reads.

On Composio-managed auth, there's nothing to set up. Create a trigger the way you always have:

```bash
curl -X POST https://backend.composio.dev/api/v3.1/trigger_instances/GMAIL_NEW_GMAIL_MESSAGE/upsert \
  -H "x-api-key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"user_id": "user-id-123435"}'
```

```json
{
  "trigger_id": "ti_xxx",
  "type": "webhook",
  "fallback_reason": null,
  "polling_interval": null
}
```

What just happened? The trigger supports both webhooks and polling, so Composio picked the webhook. The response's `type` tells you which one each trigger uses.

### What's new

- **Instant Gmail triggers.** `GMAIL_NEW_GMAIL_MESSAGE` and `GMAIL_EMAIL_SENT_TRIGGER`.
- **Instant Google Calendar triggers.** `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_CREATED_TRIGGER`, `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_UPDATED_TRIGGER`, `GOOGLECALENDAR_GOOGLE_CALENDAR_EVENT_SYNC_TRIGGER`, `GOOGLECALENDAR_EVENT_CANCELED_DELETED_TRIGGER`, and `GOOGLECALENDAR_ATTENDEE_RESPONSE_CHANGED_TRIGGER`. `GOOGLECALENDAR_EVENT_STARTING_SOON_TRIGGER` keeps polling, because it fires on a schedule relative to each event's start time.
- **Choose webhook or polling.** Pass `type` as `"webhook"` or `"poll"`. Omit it and Composio uses a webhook whenever it can set one up.
- **`polling_interval`.** Set the minutes between polls with this top-level parameter (`pollingInterval` in TypeScript). It applies when you pass `type: "poll"`, and when a trigger falls back to polling. Composio checks it even when the trigger ends up on a webhook, so a value outside the toolkit's allowed range fails the request.
- **`fallback_reason`.** When a trigger polls because Composio couldn't set up its webhook, `fallback_reason` says what's missing.

Python `composio` 0.31.0 and TypeScript `@composio/core` 0.28.0 support `type` and the polling interval. See the [SDK release notes](/docs/changelog/2026/11/03).

<Callout>
**Deprecated: `interval` in `trigger_config`.** Use the top-level `polling_interval` instead. `interval` keeps working when you don't pass `polling_interval`.
</Callout>

### Existing triggers

Composio doesn't move your existing triggers. They keep polling exactly as before, so nothing changes under you. To move one to webhooks, delete it and create it again. An existing trigger keeps the type it was created with, so an upsert that asks for the other type returns `409`.

### Gmail and Calendar on your own OAuth app

Google Calendar works on your own Google OAuth app with no extra setup.

Gmail delivers mailbox changes through Google Cloud Pub/Sub, so your app needs a topic and a push subscription in the Google Cloud project that owns your OAuth client. Each Gmail trigger's description walks you through it. Read it with `composio.triggers.get_type("GMAIL_NEW_GMAIL_MESSAGE")` in Python, `composio.triggers.getType('GMAIL_NEW_GMAIL_MESSAGE')` in TypeScript, or `GET /api/v3.1/triggers_types/GMAIL_NEW_GMAIL_MESSAGE`.

Setup is complete once your Gmail [webhook endpoint](/docs/setting-up-triggers/custom-oauth-webhooks) exists and holds every field: `topic_name`, `push_service_account_email`, and `push_audience`. Until then, new Gmail triggers keep polling, and `fallback_reason` tells you which piece is missing. Nothing breaks while you set up.

<Callout type="warn">
Once the endpoint is complete, every new Gmail trigger you create without `type` uses the webhook right away. If the Pub/Sub push subscription isn't delivering to the endpoint's `webhook_url` yet, those triggers fire nothing, and no error tells you.
</Callout>

For a smooth, test-first rollout:

1. Create Gmail triggers with `type: "poll"` while you set up, so the switch can't catch you halfway.
2. Create the webhook endpoint, fill every field, and create the Pub/Sub push subscription that delivers to its `webhook_url`.
3. Create a few test triggers with `type: "webhook"`, send yourself an email, and watch the event arrive.
4. Switch new triggers to `type: "webhook"`, or drop `type`. Recreate your existing polling triggers to move them over.
