---

Two new controls tie an OAuth connection to the user who started it, so a connection cannot be
completed by anyone else. Both are off by default — if you do nothing, your connect flows are
unchanged.

### What shipped

- **Same-browser binding** — for **Composio managed** apps, a Connect Link must be finished in the
  browser that started it; a callback from a different browser is rejected. Composio-enforced, off
  by default — contact us to turn it on. [Learn more](/docs/oauth-connection-security#same-browser-binding)
- **Callback identity verification** — for **your own OAuth apps**, set a verifier URL and Composio
  hands each OAuth return to your server, which names its signed-in user; the connection activates
  only if that matches the user the flow started for. Enable it yourself in Settings → General.
  [Learn more](/docs/oauth-connection-security#callback-identity-verification)

### Breaking changes

Only if you enable callback identity verification. Both take effect project-wide the moment you
save the URL.

<Callout type="warn">
- Connections started from the Composio dashboard no longer complete — start flows from your own app.
- Every connection must pass a real `user_id`; a blank or `default` placeholder is rejected.
</Callout>

Handle these before you switch it on — see [Before you enable it](/docs/oauth-connection-security#before-you-enable-it).
