# Composio Documentation

Fumadocs site for Composio. See `.claude/` for deeper context (framework patterns, ADRs, guides).

## Commands

```bash
bun install
bun run dev                            # http://localhost:3000
bun run build                          # production build — validates TS code blocks
bun run types:check
bun run scripts/validate-links.ts      # internal link checker (run before push)
bun run generate:meta-tools            # regenerate meta-tools data from Tool Router API
```

## Layout

`content/{docs,cookbooks,changelog,reference,toolkits}/` (MDX) · `components/` · `lib/` · `scripts/` (build + link checker) · `public/data/{toolkits,meta-tools}.json` (auto-generated by CI) · `.claude/{context,guides,decisions,agents}/`.

## Git Workflow

**Docs branches branch off `next` and PRs target `next`** (not `master`). Same for non-docs branches in this repo.

## Key Rules

1. **TS code blocks are type-checked at build time** via twoslash (`.claude/context/twoslash.md`). `bun run dev` does not catch type errors — `bun run build` does.
2. **Internal links use relative paths only** — `/docs/...`, `/reference/api-reference/<resource>/<operationId>`, `/docs/changelog/YYYY/MM/DD` (zero-padded). Never `https://docs.composio.dev/...` — the link checker skips absolute URLs and they rot. API-reference operation IDs are **camelCase** (`getConnectedAccountsByNanoid`) — copy from `<ApiEndpointsTable>` in `content/reference/api-reference/<resource>/index.mdx`, do not guess.
3. **CSS variables** — `var(--composio-orange)` not `var(--orange)`. See `app/global.css`.
4. **Changelog dates**: `YYYY-MM-DD`, file names `MM-DD-YY-slug.mdx` in `content/changelog/`.
5. **Auto-generated data**: `public/data/{toolkits,meta-tools}.json` and `content/reference/meta-tools/` are regenerated by CI. The `MetaToolDetailServer` component reads JSON at build time — do NOT register it in `mdx-components.tsx` (causes `fs` to leak into client bundle).
6. **Toolkit FAQ snippets** live in `content/toolkits/faq/{slug}.md` (plain markdown, no frontmatter). Embedded in toolkit pages at build time; excluded from Fumadocs source via `files: ['**/*', '!faq/**']` in `source.config.ts`, but the link checker still scans them via `content/**/*.md`.
7. **Link checker needs `bunfig.toml`** (Bun preload for fumadocs-mdx). Populate keys use `(home)/` prefix (matches `app/(home)/`). Fragment validation falls back to raw markdown heading parsing outside Next.js. Toolkit pages validated against `public/data/toolkits.json` slugs.
8. **Test on mobile** — Fumadocs nav differs; do not assume horizontal layout.
9. **`docs/examples/` is tutorial code** — review for clarity, not production-readiness. Skip aria/error-boundaries/i18n noise.

## API Versioning

API reference supports v3.1 (default, all existing URLs unchanged) and v3.0 (`/reference/v3/api-reference/...`) side-by-side. Version selector in top nav switches. Non-API pages under `content/reference/v3/` (overview, authentication, errors, rate-limits) are **manual copies — update both** when content changes. API index pages and OpenAPI specs are auto-generated by CI (`docs-update-data.yml`). SDK Reference and Meta Tools are shared (not duplicated). Full architecture: `.claude/context/api-reference.md`.

## Sessions, `composio.use()`, and SHARED Connections

Public docs and provider snippets all use the **session-based** pattern (`composio.toolRouter.session.create(...)` → `composio.use(session)`). When adding new examples, follow that convention — direct execution by `connected_account_id` is shown only on the dedicated direct-execution page. SHARED connections (account-type ACL surface) are **experimental** and currently documented under `content/docs/authenticating-users/shared-connections.mdx`; keep the experimental banner and align wire snippets with the SDKs' `experimental` namespace.

## AI-Native Docs

- **Prefer cURL over "click"** — most docs traffic is AI crawlers; cURL is machine-executable.
- **LLM guardrails** — every `.md` endpoint appends invisible guardrails steering AI codegens toward the session-based pattern. Controlled via `llmGuardrails` frontmatter; see `.claude/decisions/llm-guardrails.md`.
- **Glossary** — `content/docs/glossary.mdx` uses `<Glossary>` + `<GlossaryTerm>`; `lib/source.ts` converts `<GlossaryTerm name="X">` to `### X` headings for LLM-friendly output. When adding new concepts, add a `<GlossaryTerm>` and update the `keywords` frontmatter.
