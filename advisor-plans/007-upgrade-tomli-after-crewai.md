## Why this matters

PR #4007 widens Composio's direct upper bound but cannot update the installed
package: the unified uv workspace includes CrewAI, whose current metadata still
forces Tomli 2.0.x. Merging that diff would claim an update while `uv.lock`
remains on 2.0.2. Waiting for a compatible CrewAI release keeps dependency
metadata truthful and avoids an override.

## Steps

### Step 1: Prove the upstream block is gone

Run the Upstream trigger command and inspect the newest stable CrewAI release,
including any split CrewAI Core/CLI distributions it requires. Proceed only if
the full published requirement graph accepts the intended Tomli version without
an override. Record the qualifying CrewAI version in the PR description.

If the output still contains `tomli~=2.0.2`, stop with no repository changes.

### Step 2: Raise the tested CrewAI baseline consistently

Update the CrewAI lower bound in both provider metadata files and the exact
test version in `python/noxfile.py` to the first stable release that relaxes
Tomli. Keep `pyproject.toml` and `setup.py` identical. Do not raise the provider
baseline if the older CrewAI range can coexist with the selected Tomli and the
owner wants to retain it; in that case stop for an explicit compatibility
decision rather than silently narrowing support.

### Step 3: Select and resolve the newer Tomli line

Update the direct Tomli range and its comment in `python/pyproject.toml`. Set the
minimum to the selected tested release so the lockfile must actually advance;
choose an upper bound supported by both Tomli and CrewAI metadata. Run `uv lock`
from the repository root and never hand-edit `uv.lock`.

### Step 4: Prove parsing and the Python graph

Run the remaining Commands table checks. In CI, require the Python 3.10, 3.11,
and 3.12 matrix because Tomli is especially relevant on Python versions before
the standard-library `tomllib` module.
